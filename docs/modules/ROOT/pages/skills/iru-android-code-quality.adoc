= Android Code Quality
:description: Runs Android Lint, Detekt, and ktlint (via Spotless or the standalone plugin) on a Gradle module and summarizes every issue found, grouped by tool.
:keywords: iru-android-code-quality, claude code skill, gradle, kotlin, android lint, detekt, ktlint, spotless, static analysis, code quality report

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run whichever static-analysis tools an Android/Kotlin module actually has wired — Android Lint (always available
via AGP), Detekt (only when its plugin is applied), and ktlint (only when wired, either through Spotless's
`spotlessCheck` or the standalone `org.jlleitschuh.gradle.ktlint` plugin) — then read each tool's generated report
to summarize every issue found, grouped by tool and classified by id/severity. This is a read-only reporting
skill: it runs static analysis and reports results, it does not fix issues or modify lint/Detekt/Spotless
configuration unless asked to as an explicit follow-up.

== Purpose

`iru-android-code-quality` gives a lint/static-analysis pass called out separately from `iru-android-test`/
`iru-android-coverage`, without trusting console output alone. Before running anything it verifies each tool is
actually wired (plugin applied, config file present) so a "zero issues" result from a tool that was never
configured is never reported as a clean pass — an absent tool is explicitly called "not wired" instead of being
silently omitted or misreported as passing. It parses each tool's own generated report (Lint's XML, Detekt's
Checkstyle-format XML or SARIF, Spotless's console output, ktlint's text/XML report) directly rather than relying
on the Gradle console, and can scope its summary to a single file/class even though none of these tools expose a
per-file CLI selector — the underlying Gradle run always analyzes the whole module.

== Outputs

* A plain-text summary in the conversation — never a written file.
* Findings grouped by tool (Android Lint, Detekt, ktlint/Spotless), then by id/rule, with a severity breakdown
  per tool (Lint: Fatal/Error/Warning/Informational; Detekt/ktlint: error/warning; Spotless: a single
  `formatting` bucket).
* An overall total and a per-tool total; a tool that isn't wired is called out as "not wired" rather than omitted
  or shown as a false "0 issues" pass.
* When a baseline was supplied, only the new-vs-baseline issues (increased counts, newly appearing ids/entries).
* No source, Lint, Detekt, Spotless, or ktlint configuration is ever modified.
