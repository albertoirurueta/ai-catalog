= Setup Ionic App
:description: Scaffolds a new Ionic (Angular or React) hybrid app via the Ionic CLI, then adds Vitest coverage, ESLint/Prettier, Playwright, Maestro, and Sonar.
:keywords: iru-setup-ionic-app, claude code skill, ionic, capacitor, vitest, eslint, playwright, maestro, sonarqube, scaffold

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold a new Ionic (Angular or React) hybrid mobile app at the repository root using the real `@ionic/cli`
`start` schematic, then layer on this catalog's house test/lint/e2e/Sonar conventions on top of the stock starter.

== Purpose

`iru-setup-ionic-app` bootstraps a new Ionic 9 + Capacitor 8 app — no Cordova, no Ionic Appflow — using the
Ionic CLI's own scaffold instead of a hand-rolled reimplementation of it, then wires in Vitest with v8 coverage
(the Angular flavor's `@angular/build:unit-test` runner, or Vite's own runner for React), the starter's existing
ESLint flat config plus Prettier, a Playwright web-build smoke test, a Maestro on-device flow skeleton, and
`sonar-project.properties` when opted in. Every command and quirk documented in its `SKILL.md` was confirmed by
actually running the exact sequence against both flavors (`@ionic/cli` 7.2.1, `@ionic/angular`/`@ionic/react`
9.0.4, Capacitor 8.5.2) rather than assumed from the tools' documentation alone.

== Outputs

* A scaffolded Ionic app at the repository root (`package.json`, `capacitor.config.ts`, `src/`, framework
  config), moved up from a temporary sibling directory when the root wasn't empty.
* `capacitor.config.ts` re-initialized with the real `app-id` in place of the starter's `io.ionic.starter`.
* Vitest coverage wired into `angular.json` (Angular) or `vite.config.ts` (React), plus non-interactive
  `test`/`coverage` `package.json` scripts.
* `eslint.config.js` extended with build/coverage `ignores` and `eslint-config-prettier`; `.prettierrc.json`
  and `format`/`format:fix` scripts added.
* `playwright.config.ts` and `e2e/smoke.spec.ts` (optionally replacing the React starter's Cypress setup), plus
  an `e2e` script.
* `.maestro/smoke.yaml`, an unverified on-device smoke-flow skeleton.
* `sonar-project.properties` at the repository root, only when `sonar` is `cloud` or `self-hosted`.
* `android/` and/or `ios/` native platform folders, for whichever of `add-android`/`add-ios` was Yes.
* A report of every resolved value, what was included versus omitted and why, and explicit warnings to review
  generated files and provision Sonar/store credentials before relying on CI.
