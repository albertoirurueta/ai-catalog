= Setup Dotnet Gitignore
:description: Creates or updates the root .gitignore for a .NET library, service or CLI, with bin, obj, artifacts, test results, signing keys and DocFX output rules.
:keywords: iru-setup-dotnet-gitignore, claude code skill, dotnet, csharp, gitignore, docfx, nuget, native aot, repository setup

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root `.gitignore` of a plain .NET repository — a class library, a service, or a command-line tool
such as the layout produced by xref:skills/iru-setup-dotnet-cli.adoc[]. The template is a trimmed, house-style version
of what such a solution produces, not GitHub's 400-line Visual Studio file. It never overwrites an existing
`.gitignore` without showing a diff and getting approval.

== Purpose

`iru-setup-dotnet-gitignore` ignores .NET build output (`[Bb]in/`, `[Oo]bj/`, the .NET 8+ `artifacts/` layout holding
Native AOT publish output, NuGet tool packages, man page and completions, and `publish/`), Visual Studio/Rider/VS Code
user state, test and coverage output (`TestResults/`, `*.trx`, `coverage*.xml`, `coveragereport/`), analyzer SARIF
logs, NuGet packages, signing material (`*.pfx`, `*.p12`, `*.key` — but not `*.snk`), the Antora build output, OS files
and the repository-wide `.integration-test.lock/`. A DocFX section covering the `docfx.json` metadata `dest` and site
`output` folders is added only when a `docfx.json` exists.

It never ignores the generated-but-committed `docs/modules/ROOT/pages/cli-reference.adoc`, and checks the draft with
`git check-ignore` against build props, solution, `.editorconfig`, DocFX sources and project files. It stops and points
to xref:skills/iru-setup-windows-gitignore.adoc[] for Windows desktop apps (WPF, WinUI 3, Windows Forms, MSIX). When
`.gitignore` exists it announces an update, shows a diff and asks Update / Keep as is / Replace.

== Outputs

* A root `.gitignore` — created, updated (merged, keeping hand-added lines), replaced with the template, or left untouched when kept as is.
* A report stating whether the run was from scratch or an update, the action taken (created / updated / replaced / kept as is, and its source), which conditional sections were included or skipped, the result of the `git check-ignore` safety check, and any tracked file under a newly ignored path with the `git rm -r --cached` it needs.
* Explicit warnings: review the file before committing; writing `.gitignore` never untracks committed files (rotate any committed certificate or key); never commit `*.pfx` or NuGet API keys.
