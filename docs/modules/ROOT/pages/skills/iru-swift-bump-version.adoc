= Swift Bump Version
:description: Sets a SwiftPM library's version.txt, CHANGELOG.md, and README, or an Apple app's MARKETING_VERSION/CURRENT_PROJECT_VERSION, to an exact version.
:keywords: iru-swift-bump-version, claude code skill, swift, swiftpm, xcodegen, tuist, xcconfig, agvtool, bump version, sync files

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a Swift (SwiftPM library) or Apple app (XcodeGen/Tuist/xcconfig/`.xcodeproj`) project's version to an exact
literal value across every file that needs to agree with it. A SwiftPM library carries no in-tree version field at
all — a consumer resolves it against the package's git tag — so this skill only rewrites the files that mirror that
tag by this catalog's own convention (`version.txt`, `CHANGELOG.md`, README dependency snippets). An Apple app, by
contrast, does carry an in-tree version (`MARKETING_VERSION`/`CURRENT_PROJECT_VERSION`), rewritten in whichever
project format is present. This skill never computes a version itself; it only applies exactly the string it is
given, after validating its shape.

== Purpose

`iru-swift-bump-version` is the Swift/Apple-ecosystem equivalent of `iru-java-bump-version`/`iru-typescript-bump-version`/
`iru-android-bump-version`: a small, deterministic skill a caller (typically `iru-release`) can invoke with a
literal version string, without having to reason about SwiftPM's git-tag-based versioning, XcodeGen/Tuist manifest
syntax, or `agvtool`. Because neither SwiftPM nor Xcode build settings parse or validate a free-form version string,
this skill validates with a regex and rewrites each file with a targeted `python3` substitution (or, for a
hand-maintained `.xcodeproj` with no generator, via `agvtool`).

== Outputs

* **Library**: `version.txt` updated (or created, only if the repository's `sync.yml`/README actually reference
  it); `CHANGELOG.md`'s `## [Unreleased]` heading renamed to `## [<new-version>] - <date>` with a fresh
  `## [Unreleased]` reopened above it (skipped if the file doesn't exist); README `.package(url:, from:/exact:)`
  snippets rewritten to the new version.
* **App**: `MARKETING_VERSION` set to the new version and `CURRENT_PROJECT_VERSION` incremented by exactly 1, in
  whichever of `project.yml` (XcodeGen), `Project.swift` (Tuist), a `*.xcconfig` file, or `.xcodeproj`
  (`agvtool`/`project.pbxproj` sed) actually carries the value.
* Optionally, `docs/antora.yml`'s `version:` field, Antora pages with a literal dependency snippet, and/or a README
  version badge mention, if `sync-files` was accepted.
* A sanity check: `swift package dump-package` for a library, or an Xcode project regenerate +
  `xcodebuild -showBuildSettings` round-trip (or `agvtool what-version`/`what-marketing-version` read-back for a
  hand-maintained `.xcodeproj`) for an app.
* A report of the detected kind, the old and new version, every file actually changed (or skipped and why), and an
  explicit warning that — for a library — the git tag itself is the real release artifact, this skill never creates
  it.
* No commit or git tag is created — this skill only edits files (or, on `dry-run: yes`, only prints diffs).

  whichever `MARKETING_VERSION` value the caller decides (a plain release string or a beta suffix).
