= Python Code Quality
:description: Runs a Python project's wired Ruff, mypy, pyright, Bandit and djLint checks and reports issue counts by tool and rule id, with optional baseline diff.
:keywords: iru-python-code-quality, claude code skill, python, ruff, mypy, pyright, bandit, djlint, lint, static analysis

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run every static-analysis and style tool a Python project actually has wired, Ruff (lint and format), mypy or pyright, and, when configured, Bandit, djLint and django-upgrade, and report every issue grouped by tool and by rule id. It is a read-only reporting skill: it never fixes issues, applies formatting, regenerates a baseline, or modifies tool configuration unless asked to as a follow-up.

== Purpose

Different Ruff or mypy versions report different rules, so `iru-python-code-quality` detects the project's environment runner and mirrors the project's real invocation from CI, pre-commit, and Makefile or tox targets. It verifies which tools are installed and configured, runs each one in read-only mode with machine-readable output scoped to the requested paths, parses the reports into tool, rule id and issue, and reports counts. A tool that is not wired is named as skipped, and a tool that broke (Ruff exit 2, a mypy plugin that cannot import Django settings) is reported as a tooling failure, never as "0 issues". When a calling skill supplies a baseline, only new issues are reported.

== Outputs

* A plain-text summary in the conversation: an overall total first, then per tool whether it ran or was skipped (and why), the config and version in force, its total, and one line per rule-id bucket with its count.
* A `file:line — message` list when the scope is smaller than the whole project or on request; per-rule lists are capped at 20 entries with "(+N more)".
* Special Ruff families are called out: `S*` security first, `D*` docstrings (handed to `iru-python-docstrings`), `DJ*` and `FAST*` framework rules, and `invalid-syntax`.
* With a baseline, only issues new since it are reported, matched on tool, rule id and file rather than line numbers.
* Tool failures get their own line with the first error line. Temporary reports under `build/iru-python-cq-*` are deleted. No source or configuration is ever modified, and no `--fix`, write-mode formatter or `# noqa` is applied.
