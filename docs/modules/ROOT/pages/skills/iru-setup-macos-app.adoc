= Setup macOS App
:description: Scaffolds a native macOS desktop app (Swift 6, XcodeGen, SwiftUI or AppKit) with a UI-free Core package, Swift Testing, XCUITest, SwiftLint, DMG packaging.
:keywords: iru-setup-macos-app, claude code skill, macos, swift 6, xcodegen, swiftui, appkit, swift testing, notarization, dmg, scaffold app

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate a complete, buildable native macOS desktop app: an XcodeGen manifest, a UI-free `Packages/Core` local package
holding the testable logic, the `App/` UI layer in SwiftUI or AppKit, unit and UI tests, quality configs and
packaging helpers, written from templates in the skill's `reference/` files.

== Purpose

`iru-setup-macos-app` is the scaffold step of the macOS chain run by `iru-setup-macos-repository`, and it also works
standalone. It writes `project.yml` (one macOS app target and scheme, a hosted Swift Testing unit-test target, an
XCUITest target and the package's `CoreTests`; `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` in `settings.base`,
strict concurrency, hardened runtime), an entitlements file with the App Sandbox, `Packages/Core` (models and services,
plus `ViewModels/` for MVVM or `Controllers/` for MVC) tested to 100% lines, the `App/` layer per `ui` (SwiftUI scenes
with Settings and Commands, or programmatic AppKit with `NSWindowController`/`NSViewController`), a `--uitesting` launch
argument with accessibility identifiers, a root `.ui-quality.yml`, the shared `App/Tests/Support/UIScreenshots.swift`
capture helper and UI tests that capture the main window across left-to-right/right-to-left × light/dark into
`.ui-screenshots/` plus a `performAccessibilityAudit()` test at the configured level (the catalog's UI contract; see
xref:guides/building-user-interfaces.adoc[Building user interfaces]), `ExportOptions-*.plist` per `distribution`, `scripts/make-dmg.sh`,
`.swiftlint.yml`, `.swift-format` and `sonar-project.properties`. The generated `.xcodeproj` is never committed and
Fastlane is not used.

The layout is the scaffold contract the Swift gate skills (`iru-swift-test`, `iru-swift-coverage`,
`iru-swift-code-quality`, `iru-swift-docc`, `iru-swift-bump-version`, `iru-swift-code-one-task`) and
`iru-setup-macos-github-workflows` rely on. It follows `iru-setup-apple-app`'s conventions (use that skill for a
multi-platform app) and `iru-setup-kmp-app`'s structure. It announces whether it is scaffolding from scratch or
updating, asks Update / Keep as is / Replace / Stop per existing file group (unless `on-existing` decides), and looks
up toolchain versions at run time with a dated fallback table.

== Outputs

* `project.yml`, the entitlements file, the asset catalog, the matching `ExportOptions-*.plist`, `scripts/make-dmg.sh`,
  `.swiftlint.yml`, `.swift-format`, `.ui-quality.yml` and `sonar-project.properties` (omitted when `sonar: none`).
* `Packages/Core` (Package.swift, DocC catalog, models, services and view models or controllers) with its Swift Testing
  suite.
* `App/Sources`, `App/Tests` (including `Support/UIScreenshots.swift`, compiled into both test targets) and
  `App/UITests` (behaviour, window captures and the accessibility audit) for the chosen `ui` and `architecture`.
  The captures land under `.ui-screenshots/screen/<ScreenType>/`, recovered from the `.xcresult` by
  `iru-swift-test`'s `ui` run because the sandboxed host cannot write the repository.
* A verification pass (Core tests and coverage, `xcodegen generate`, `xcodebuild build-for-testing` and tests, SwiftLint
  and swift-format, DocC, archive/export/DMG), all through `iru-gate-runner`; everything needing macOS or Xcode is
  reported "unverified" elsewhere. The UI contract additions (captures, audit) are only partly verified; without the
  Automation permission or a logged-in desktop the UI tests are unverified, not passed.
* A report with the action per file group (including `.ui-quality.yml` and its `accessibility` level), the resolved options, toolchain versions (live versus fallback) and the
  scaffold contract table.

== Dependencies

=== Invokes

None -- `iru-setup-macos-app` invokes no other catalog skill; it writes files from its own `reference/` templates and
runs `xcodegen`, `xcodebuild`, `swift`, `swiftlint` and `python3` directly. The layout it writes is the contract for
xref:skills/iru-swift-code-one-task.adoc[], xref:skills/iru-swift-test.adoc[], xref:skills/iru-swift-coverage.adoc[],
xref:skills/iru-swift-code-quality.adoc[], xref:skills/iru-swift-docc.adoc[], xref:skills/iru-swift-bump-version.adoc[]
and xref:skills/iru-setup-macos-github-workflows.adoc[], but it does not call them.

=== Invoked by

* xref:skills/iru-setup-macos-repository.adoc[] -- Step 4 runs `iru-setup-macos-app` (through an isolated skill
  executor) first in the chain, passing the resolved shared inputs as `args`.
* xref:skills/iru-setup-repository.adoc[] -- reaches it indirectly by delegating to `iru-setup-macos-repository`. It can
  also be run directly by a person.

=== Related agents

  caller's context.
