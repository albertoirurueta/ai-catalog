= Setup PHP Repository
:description: Bootstraps a Laravel, WordPress plugin, WordPress block theme or PrestaShop module repository end to end: scaffold, docs, gitignore, CI, changelog and README.
:keywords: iru-setup-php-repository, claude code skill, php, laravel, wordpress, prestashop, composer, github actions, bootstrap, orchestrator

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for a PHP repository of one of four flavors — Laravel application, WordPress plugin, WordPress
block theme, or PrestaShop module — by orchestrating the flavor's scaffold skill and the shared repository-level
skills in one pass, collecting every shared parameter once.

== Purpose

`iru-setup-php-repository` is the PHP stack orchestrator, run stand-alone or from the `iru-setup-repository` front
door. It resolves the `flavor` (from `args`, an `iru-explore` `Project type:` line, or on-disk markers, otherwise
asked), the project identity (name, slug, Composer vendor, namespace, description, per-flavor license, developer
details), the PHP version floor (from php.net active support, the Laravel skeleton's floor, or PrestaShop's system
requirements), and the shared pipeline parameters (`open-source`, `visibility`, `ci`, `ci-tests`, `pages`,
`distribution` with its flavor-specific meaning, `sonar` and its detail keys, `accessibility` — the level of the browser UI tests' automated accessibility checks that every flavor's scaffold writes to `.ui-quality.yml` — and branches). It then runs, each through
the `iru-isolated-skill-executor` agent so only a short summary returns: the scaffold skill, `iru-setup-antora`,
`iru-setup-php-gitignore`, `iru-setup-php-github-workflows` (skipped entirely when `ci` is `no`),
`iru-setup-changelog`, and `iru-setup-readme`.

It announces the setup mode first (from scratch vs updating an existing repository, with a per-component inventory
marked absent/present/partial); each sub-skill then asks Update / Keep as is / Replace for what it finds. Plain
Composer libraries (`php-library`) are out of scope and stop the run.

== Outputs

* A scaffolded PHP project for the chosen flavor, with tests, quality configuration and browser UI tests (`.ui-quality.yml`, Playwright + axe-core, `.ui-screenshots/` captures), via the scaffold skill.
* An Antora docs site, a root `.gitignore`, `CHANGELOG.md` and `README.md`, via the delegated skills.
* Unless `ci: no`, GitHub Actions workflows (`build`, `release`, `sync`, `security`) and Dependabot.
* A final report: the setup mode, resolved flavor and mode, identity and license, PHP floor and its source, a
per-component action table (now including `.ui-quality.yml`; created / updated / replaced / kept as is / skipped (ci: no) / not written), the
verification results (including browser UI tests), what was wired or omitted and why, the required-secrets table, and explicit warnings.
