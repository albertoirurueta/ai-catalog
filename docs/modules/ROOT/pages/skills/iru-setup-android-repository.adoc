= Setup Android Repository
:description: Bootstraps or catches up an Android/Gradle repository (library or app): Gradle scaffold, Antora docs, gitignore, CI workflows, changelog, README.
:keywords: iru-setup-android-repository, claude code skill, android, gradle, kotlin, antora, github actions, sonar, changelog, readme

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for an Android/Gradle repository of either flavor — library or app. It resolves the
flavor, branching model and mode once, collects the project's identity and shared pipeline parameters once, then
orchestrates six other skills in a fixed order so nothing is asked twice.

== Purpose

`iru-setup-android-repository` is the Android-specific stack orchestrator invoked by `iru-setup-repository` (or
run standalone) once the project type is known to be `android-library` or `android-app`. Rather than duplicating
Gradle scaffolding, documentation setup, `.gitignore` generation, CI/CD workflow authoring, changelog
bootstrapping, or README generation, it resolves the flavor's scaffold skill (`iru-setup-android-library` or
`iru-setup-android-app`) and passes every downstream skill only the `args` keys that skill's own Step 0 actually
accepts. In `mode: existing` it skips the scaffold outright when `settings.gradle.kts` already exists and tells
every downstream step to take its own update/gap-fill path instead of assuming a brand-new repository.

== Outputs

* The flavor's Gradle scaffold — a `lib/` library module plus a Compose `app/` sample, or a single `app/`
  application module — the Gradle wrapper and root build files (via `iru-setup-android-library` or
  `iru-setup-android-app`), skipped in `mode: existing` when `settings.gradle.kts` already exists.
* A scaffolded Antora documentation site under `docs/` (via `iru-setup-antora`).
* Root and per-module `.gitignore` files (via `iru-setup-android-gitignore`).
* CI/CD workflows — `develop.yml`/`main.yml`/`sync.yml` (gitflow) or `main.yml`/`publish.yml` (main-only), plus
  `security.yml` and `.github/dependabot.yml` (via `iru-setup-android-github-workflows`).
* A root `CHANGELOG.md` backfilled from git/GitHub release history (via `iru-setup-changelog`).
* A root `README.md` with badges, a project-status table, documentation links, and installation instructions
  (via `iru-setup-readme`).
* A final report summarizing the resolved flavor/branching/mode, identity/license/pipeline parameters, which
  files were created versus left untouched, the consolidated required-secrets table, and explicit review
  warnings.

== Dependencies

=== Invokes

Each of the following is invoked via the xref:agents/iru-isolated-skill-executor.adoc[`iru-isolated-skill-executor`]
agent rather than a direct `Skill` call — every sub-skill re-derives what it needs straight from the filesystem
this orchestrator has just written to, so only a short completion summary flows back, keeping each sub-skill's own
exploration/file reads (and the Android scaffold's very long template listings) out of this orchestrator's own
context. Every sub-agent is launched with `run_in_background: false` since each step depends on the previous
one's files being on disk:

* xref:skills/iru-setup-android-library.adoc[] — Step 4, `flavor: library`: writes `lib/` and the sample Compose
  `app/` module, passing Step 2's identity fields and Step 3's pipeline parameters as `args`; skipped in
  `mode: existing` when `settings.gradle.kts` already exists.
* xref:skills/iru-setup-android-app.adoc[] — Step 4, `flavor: app`: writes the single `app/` application module,
  passing the same kind of `args`; skipped under the same `mode: existing` condition.
* xref:skills/iru-setup-antora.adoc[] — Step 5: scaffolds the Antora documentation site, invoked with no `args`
  since it derives the component name/title/version from the Gradle project itself.
* xref:skills/iru-setup-android-gitignore.adoc[] — Step 6: writes or updates root and per-module `.gitignore`
  files, invoked with no `args` since it derives the module list from `settings.gradle.kts` and detects `mode`
  from whether a root `.gitignore` already exists.
* xref:skills/iru-setup-android-github-workflows.adoc[] — Step 7: writes the CI/CD + security workflows, passing
  Step 1's `flavor`/`branching` and Step 3's pipeline parameters as `args`.
* xref:skills/iru-setup-changelog.adoc[] — Step 8: bootstraps the root `CHANGELOG.md`, invoked with no `args`
  since it works from the repository's own git tag/GitHub Release history.
* xref:skills/iru-setup-readme.adoc[] — Step 9, last: bootstraps the root `README.md`, invoked with no `args`
  since it explores the finished state left by every earlier step.

=== Invoked by

xref:skills/iru-setup-repository.adoc[] — Step 4, via `iru-isolated-skill-executor`, when the detected or chosen
project type is `android-library` or `android-app`. Also runnable standalone.

=== Related agents

* xref:agents/iru-isolated-skill-executor.adoc[`iru-isolated-skill-executor`] — spawned once per sub-skill
  (Steps 4–9), so all six sub-skills' own exploration/file-read transcripts don't accumulate in this
  orchestrator's context over the course of a single bootstrap run.
