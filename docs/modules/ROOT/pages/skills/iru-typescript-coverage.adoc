= TypeScript Coverage
:description: Runs Vitest, Jest, or Angular's ng test with coverage enabled and reads coverage-summary.json/lcov.info for exact percentages.
:keywords: iru-typescript-coverage, claude code skill, vitest, jest, angular, lcov, coverage-summary.json, code coverage report, unit testing

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run the project's TypeScript/JavaScript test runner — Vitest, Jest, or Angular's `ng test` — with coverage
enabled, then read the exact percentages from the generated `coverage/coverage-summary.json` (falling back to
`coverage/lcov.info` when the summary is missing or a specific file isn't in it). This is a read-only reporting
skill: it measures and reports coverage, it does not add tests or modify source/test code unless asked to as an
explicit follow-up.

== Purpose

`iru-typescript-coverage` answers "does file X meet the coverage bar?" with an exact, report-derived percentage
instead of an eyeballed guess from a runner's console output. It reuses `iru-typescript-test`'s selector syntax to
scope which tests run, infers or accepts explicit target files, and — for files under the bar — points to the
exact uncovered line ranges (collapsed from consecutive `DA:<line>,0` records in `lcov.info`) so a follow-up can
target them precisely.

== Inputs

|===
|Argument |Required |Description |Default

|`scope`
|No
|A file path, a directory, or a name pattern — the same selector syntax as the `iru-typescript-test` skill's.
Must cover every test that exercises the target file(s) — a selector scoped too narrowly undercounts real
coverage, so a broader selector (a directory, or the full suite) is preferred when in doubt.
|None — omitting it runs the whole suite and reports whole-project coverage.
|===

== Outputs

* A plain-text summary in the conversation — never a written file.
* Per target file: exact line and branch coverage percentages (and functions, when relevant), computed directly
  from `coverage/coverage-summary.json` (or `coverage/<project-name>/coverage-summary.json` for Angular CLI) —
  never estimated.
* If the user gave a coverage bar (e.g. "at least 80%"): a clear statement of whether each file/the total meets
  it.
* For files under the bar: uncovered line ranges collapsed from `lcov.info`'s `DA:` records (e.g.
  `src/math.ts: lines 66.66% — uncovered: 11, 17`).
* "Coverage not wired" (naming the missing package/config, e.g. `@vitest/coverage-v8`) instead of a false
  0%/100% when the coverage provider isn't installed.
* A file that has zero tests is forced into the report at 0% (via the runner's include flag), not silently
  omitted.
* No source or test code is ever modified, and coverage is never re-run to try to raise a number.
