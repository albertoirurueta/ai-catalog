Generate a complete, buildable, agent-friendly .NET 10 / C# 14 command-line tool: a solution with a framework-free `Core` library that implements the catalog's CLI contract, a thin System.CommandLine 2.0 executable, MSTest 4 tests and DocFX API docs.

== Purpose

`iru-setup-dotnet-cli` bootstraps a new .NET command-line tool from an embedded, verified house template. At the repository root it writes `global.json`, `Directory.Build.props`, central package management in `Directory.Packages.props`, `.editorconfig`, `stylecop.json`, a `<ToolName>.slnx` solution, `tests/coverlet.runsettings` and a DocFX `docfx.json`.

The `src/<ToolName>.Core` project (`net10.0`, `IsAotCompatible`) holds the whole CLI contract: the exit-code enum (0-7, 130, 143), the JSON error envelope on stderr, deterministic source-generated System.Text.Json output, the colour and prompt policies, signal handling with `PosixSignalRegistration`, the `schema` model, static bash/zsh/fish/PowerShell completion scripts and a generated AsciiDoc CLI reference plus man page.

The thin `src/<ToolName>` executable is published as a Native AOT binary and packed as a .NET tool (RID-specific packages plus an `any` fallback, so `dotnet tool install` and `dnx` both work). It offers the commands `greet`, `completion`, `schema`, `--version`, a hidden `gen-docs` and, with `ui: tui`, a TTY-gated Terminal.Gui v2 `browse` command whose view (`Tui/BrowseView`) gets UI tests per the catalog's UI contract (see xref:guides/building-user-interfaces.adoc[Building user interfaces]): rendered on Terminal.Gui's ANSI driver, every state and `.ui-quality.yml` direction is captured as a text file under `.ui-screenshots/`, and asserted terminal accessibility checks run at the level of a root `.ui-quality.yml`.

The skill announces whether it is scaffolding from scratch or updating an existing .NET CLI. For every file group it owns that already exists it warns and asks Update / Keep as is / Replace / Stop (unless `on-existing` decides), and it never overwrites hand-written source. A foreign layout (a single-project `dotnet new console` app, System.CommandLine betas, a Spectre.Console.Cli app, a `.sln` with other projects) is never converted: the skill either adds its pieces alongside or stops. Every version is looked up at run time, with a verified fallback table.

The layout is the scaffold contract that the .NET coding and gate skills and xref:skills/iru-setup-cli-github-workflows.adoc[] detect and call. The skill writes no CI workflow, `.gitignore` (see xref:skills/iru-setup-dotnet-gitignore.adoc[]), README, changelog, `LICENSE` or Antora site, and no Sonar file.

== Outputs

* Repository-level build and quality files: `global.json` (SDK pinned, `rollForward: latestFeature`), `Directory.Build.props`, `Directory.Packages.props` (StyleCop.Analyzers as a `GlobalPackageReference`), `.editorconfig`, `stylecop.json`, `<ToolName>.slnx`, `tests/coverlet.runsettings`, `docfx.json` and `docfx/`.
* `src/<ToolName>.Core/` with the exit codes, the `Output/`, `Terminal/`, `Greeting/`, `Schema/`, `Completion/` and `Docs/` namespaces, and `Browse/BrowseState.cs` for `ui: tui`.
* `src/<ToolName>/` with the `Exe` project (assembly `<bin>`, `PublishAot`, `PackAsTool`), `Program.cs`, `CliApp`, `GlobalOptions`, `ToolCommand` and the `Greet`, `Completion`, `Schema` and `GenDocs` commands, plus `BrowseCommand.cs` for `ui: tui`.
* `tests/<ToolName>.Core.Tests` (about 99% Core line and branch coverage) and `tests/<ToolName>.Cli.Tests` (in-process command tree runs with captured stdout/stderr, plus opt-in published-binary smoke tests).
* With `ui: tui`: a root `.ui-quality.yml`, `src/<ToolName>/Tui/BrowseView.cs`, and in `tests/<ToolName>.Cli.Tests` `UiScreenshots.cs`, `AccessibilityCheck.cs` and `Tui/BrowseViewTests.cs` (`[TestCategory("UI")]`), which write `.ui-screenshots/screen/BrowseView/<state>--<direction>--no-color.txt` captures (to be gitignored by xref:skills/iru-setup-dotnet-gitignore.adoc[]).
* `docs/modules/ROOT/pages/cli-reference.adoc`, generated by `gen-docs` during verification (the only Antora page the skill creates); the man page and completion scripts under `artifacts/` are gitignored build output.
* A report with the resolved names, `ui` (with the `.ui-quality.yml` action and `accessibility` level), version and license; whether the run scaffolded, updated or stopped; the per-group action (created / updated / replaced / kept as is) with mismatches and possibly lost customizations; which toolchain versions were live versus fallback; the scaffold contract table; and a block of explicit warnings (review generated files, run `iru-setup-dotnet-gitignore`, the NuGet package id must be free and RID packages pushed before the pointer package, Sonar token needed).
