= KMP Bump Version
:description: Sets a Kotlin Multiplatform app's version to an exact value across gradle.properties and the iOS Config.xcconfig, never writing SNAPSHOT values to iOS.
:keywords: iru-kmp-bump-version, claude code skill, kotlin multiplatform, kmp, version_name, version_code, marketing_version, xcconfig, bump version

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a Kotlin Multiplatform (Android + iOS) app's version to an exact literal value in every file that must agree with
it: the shared Gradle side (`gradle.properties`' `VERSION_NAME`/`VERSION_CODE`, read by the Android app) and the iOS
host app's Xcode build settings (`MARKETING_VERSION`/`CURRENT_PROJECT_VERSION`). This skill never computes a version
itself; it applies exactly the string it is given, after validating its shape.

== Purpose

`iru-kmp-bump-version` is the two-platform counterpart of `iru-android-bump-version` and `iru-swift-bump-version`.
`VERSION_NAME` always becomes the new version; for a release value only (plain `X.Y.Z` — no `-SNAPSHOT` or other pre-release suffix), `VERSION_CODE` is
incremented by one and the iOS `MARKETING_VERSION` is set to the release with `CURRENT_PROJECT_VERSION` set to the
new `VERSION_CODE`, so the Android and iOS build numbers stay identical. A `-SNAPSHOT` (or any pre-release) value is
never written to an iOS file, because App Store Connect rejects it. The skill detects the layout at runtime and falls
back to `libs.versions.toml` entries, literals in the Android app module's build script, XcodeGen `project.yml`, a
literal `Info.plist`, or a committed `project.pbxproj` when the `iru-setup-kmp-app` layout isn't present. Step 5 of
the skill is the authoritative statement of the KMP pre-release convention for callers such as `iru-release`.

== Outputs

* `gradle.properties`: `VERSION_NAME` set to the new version; `VERSION_CODE` incremented by exactly 1 only for a
  release (unchanged for a snapshot). Fallbacks: `gradle/libs.versions.toml` version entries, or `versionName`/
  `versionCode` literals in the Android app module's build script.
* iOS, release values only: `iosApp/Configuration/Config.xcconfig` `MARKETING_VERSION` set to the release and
  `CURRENT_PROJECT_VERSION` set to the new `VERSION_CODE`. Fallbacks: XcodeGen `project.yml`, a literal
  `Info.plist`, or a committed `project.pbxproj`. For a snapshot the iOS side is left untouched and the report says so.
* Optionally, README/Antora version mentions mapped by release vs. development marker, if `sync-files` was accepted.
* A sanity check (`./gradlew -q help`, a `properties` read-back, and an `xcodegen`/`xcodebuild` round-trip when
  available), skipped on a dry run.
* A report of old and new values for every field and file, the fallback used (if any), and a warning to review the
  diff before committing.
* No commit or tag is created.
