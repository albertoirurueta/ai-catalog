= Setup Python Gitignore

Create or refresh the root `.gitignore` for a Python project — a universal base plus sections for whatever is actually
detected (Django static/media/SQLite paths, a file-based FastAPI database, Sphinx or MkDocs output, notebooks, PDM
files, Node tooling, an Antora docs build). It mirrors `iru-setup-php-gitignore` and `iru-setup-typescript-gitignore`
for the Python ecosystem and never overwrites an existing `.gitignore` without showing a diff and getting approval.

== Purpose

`iru-setup-python-gitignore` bootstraps a `.gitignore` that matches what a uv-managed Python project really
produces: bytecode, `build/` and `dist/` output (coverage XML, JUnit results, API docs, `uv build` artifacts),
`*.egg-info/`, virtual environments (`.venv/`), pytest/coverage/Hypothesis/tox/nox caches, mypy/Ruff/Pyre/Pytype
caches, env files (keeping `.env.example`), `.pypirc`, logs, OS/editor noise and the repository-wide
`.integration-test.lock/` directory. It adds a section only when the thing it targets is present: Django's
`STATIC_ROOT`/`MEDIA_ROOT`/`db.sqlite3` (read from the settings), a file-based SQLite database for FastAPI, Celery beat
files, Sphinx or MkDocs build directories, Jupyter checkpoints, PDM local files, root Node tooling, and Antora build
output.

It never ignores `uv.lock` (or `poetry.lock`/`pdm.lock`/`Pipfile.lock`), `.python-version` or `.secrets.baseline` —
CI installs with `uv sync --locked`, so those files must be committed — and proposes removing such a line from an
existing file. When `.gitignore` already exists it announces an update, shows the merged draft as a diff, and asks
Update (merge, keep hand-added entries) / Keep as is / Replace (template only).

== Outputs

* A root `.gitignore` — created from scratch, updated (merged, keeping hand-added lines), or replaced with the
  template — or left untouched when kept as is.
* A report stating whether the run was from scratch or an update, the action taken (created / updated / replaced /
  kept as is, and whether it came from the user's answer or `on-existing`), the detected flavor, which conditional
  sections were included or skipped and why, whether a `uv.lock` or `.python-version` ignore line was removed, the
  `git check-ignore` result, and which hand-added lines were preserved or dropped.
* Explicit warnings: review the file before committing (detection is heuristic); run `git rm -r --cached` manually
  for anything already tracked under a newly ignored path (rotate credentials if `.env` or `.pypirc` was
  committed); commit `uv.lock` and `.python-version`; and which entries were verified versus inferred.
