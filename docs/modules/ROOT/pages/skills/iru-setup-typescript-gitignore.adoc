= Setup TypeScript Gitignore
:description: Creates or updates a TypeScript/npm project's root .gitignore, including NestJS, Next.js and Prisma paths, asking Update, Keep as is or Replace.
:keywords: iru-setup-typescript-gitignore, claude code skill, npm, nestjs, nextjs, prisma, angular, vite, react native, gitignore

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root `.gitignore` for a TypeScript/npm project, mirroring `iru-setup-java-gitignore`'s
contract for the npm ecosystem — never overwriting an existing file without showing the user exactly what would
change and getting explicit approval first.

== Purpose

`iru-setup-typescript-gitignore` composes a TypeScript-appropriate `.gitignore`: a universal base
(`node_modules/`, build/output directories, test/coverage output, TypeScript incremental-build info, lint caches,
env files, OS/editor noise) plus conditionally-detected sections for whichever package manager, frontend
framework, and documentation tooling are actually present in the target repository — pnpm/Yarn debug logs,
Angular, React/Vite (and Storybook), NestJS (logs, runtime and diagnostic files, test reports), Next.js (`.next/`,
`next-env.d.ts`, `.vercel`, matching `create-next-app`), a Prisma client generated inside the source tree (the path is
read from `schema.prisma`; migrations are never ignored), the repository-wide `.integration-test.lock/` used by the
NestJS/Next.js coding skills, React Native (Expo, or a bare Metro/React Native CLI app — Gradle, Xcode, CocoaPods and Bundler outputs, signing
material, and keeping the template's committed `debug.keystore`; paths are prefixed with the app subdirectory when the
app does not live at the root), Ionic/Capacitor, Playwright, Turborepo, Istanbul/nyc,
Antora docs build output, TypeDoc/Compodoc API docs, and a Spring Boot + Vaadin Hilla frontend embedded in a
Maven project. It never invents entries for things that aren't actually present. If `.gitignore` already exists,
it is treated as sensitive: the skill announces it is updating rather than creating from scratch, reads it, composes
a merged draft (hand-added lines kept) and a template-only draft, and shows the user a diff, then asks Update / Keep
as is / Replace before writing anything.

== Outputs

* A `.gitignore` file at the repository root — newly created, updated (merged), replaced, or left untouched.
* If `.gitignore` didn't previously exist: the run is announced as "from scratch" and the file is written directly,
  no approval step needed.
* If `.gitignore` already existed: the run is announced as "updating existing", and a diff of the merged draft is
  shown first (via `git diff --no-index`). The user is asked **Update** (merged draft; hand-added lines kept),
  **Keep as is** (nothing written) or **Replace** (template-only draft; the hand-added lines that would be lost are
  listed) — or `on-existing` answers it. If the merged draft is identical to the current file, the question is
  skipped and the outcome is "kept as is".
* A closing report naming which conditional sections (package manager, Angular, React/Vite, NestJS, Next.js, Prisma client,
  integration-test lock, React Native (Expo or Metro),
  Ionic/Capacitor, Playwright, Turborepo, nyc, Antora, TypeDoc/Compodoc, Hilla) were included versus skipped and
  why, the action taken (created / updated / replaced / kept as is, and whether it came from the user or `on-existing`), which hand-added lines were preserved or dropped, plus warnings that detection is heuristic and that already-tracked files under a newly-ignored directory
  need a manual `git rm -r --cached`.
