= Swift Coverage
:description: Runs swift test or xcodebuild test with coverage enabled and parses llvm-cov/xccov output to report exact line and function coverage for Swift code.
:keywords: iru-swift-coverage, claude code skill, swift, swiftpm, xcodebuild, llvm-cov, xccov, code coverage report, unit testing

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run whichever coverage path a Swift package or Xcode app project actually has wired — `swift test
--enable-code-coverage` followed by `xcrun llvm-cov` for a SwiftPM package, or `xcodebuild test
-enableCodeCoverage YES` followed by `xcrun xccov` for an Xcode app target — and report the exact, measured
line/function coverage percentage for the scope the caller cares about. This is a read-only reporting skill: it
measures and reports coverage, it does not add tests or modify source/test code unless asked to as an explicit
follow-up.

== Purpose

`iru-swift-coverage` answers "does this file/type meet the coverage bar?" with an exact, tool-derived percentage
instead of an eyeballed guess from `swift test`/`xcodebuild test` console output. It auto-detects whether the
repository is a bare SwiftPM package or an Xcode app project, runs the matching coverage path, and — for scope
under the bar — points to the exact uncovered line ranges so a follow-up can target them precisely. It is the
Swift/Apple-platform equivalent of `iru-java-coverage`, `iru-typescript-coverage`, and `iru-android-coverage`.

== Outputs

* A plain-text summary in the conversation — never a written file.
* Per target file/type: exact line-coverage and function-coverage percentages, computed directly from
  `llvm-cov`/`xccov` output — never estimated.
* Branch coverage is always reported as **not available** for Swift (never as 0%) — verified locally against
  Swift 6.4/Xcode 27: `llvm-cov report`'s Branches column stays `0 0 -`, and `xccov`'s JSON schema has no branch
  field at all.
* If the caller gave a coverage bar: a clear statement of whether each file/type/the whole scope meets it.
* For scope under the bar: the exact uncovered line ranges (collapsed from `llvm-cov export -format=lcov`'s
  `DA:` lines or `xccov`'s per-line JSON), not just the aggregate percentage.
* A scope file/type absent from the report is reported as 0% coverage, not as an error.
* If coverage isn't wired (no test target in `Package.swift`, no test scheme in the Xcode project), that is
  reported explicitly, naming exactly what's missing, instead of a false 0%/100%.
* No source or test code is ever modified, and coverage is never re-run to try to raise a number.
