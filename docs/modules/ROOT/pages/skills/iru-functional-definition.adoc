= Functional Definition
:description: Writes or updates a testable functional definition for a GitHub issue or Jira ticket: requirements, acceptance criteria and a mandatory AC-DOC block.
:keywords: iru-functional-definition, claude code skill, functional definition, acceptance criteria, requirements, github issue, jira ticket, AC-DOC, ticket intake

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Produce a complete, testable functional definition for a ticket, grounded in the real codebase and reviewed by a read-only agent.

== Purpose

`iru-functional-definition` writes a Markdown draft in the format of its functional-definition template (Context, numbered
requirements, acceptance criteria with verification methods and at least one negative case per behavioural requirement,
and, when known, Out of scope, Dependencies, Task details and References; in embedded mode the last three are left to the
calling skill). A Jira key decides the tracker even in a GitHub-hosted repository. It explores the repository, asks only what is missing in small
batches, adds exactly one `AC-DOC` item (functional documentation block, or a declined block with a specific reason), and
runs up to three review rounds with the `iru-functional-reviewer` agent. Standalone it files a new ticket or updates an
existing one after confirmation; when called by another skill (`mode: embedded` or a `tracker:` argument) it only returns
the draft path. It writes no code and never invents requirements. It stops, writing nothing, when neither GitHub nor a Jira
MCP integration is available.

== Outputs

* A Markdown draft in a temporary directory (`functional-definition-draft.md`).
* Standalone and after explicit confirmation: a new issue or ticket, or an updated body (with a before/after of every changed section).
* Embedded: nothing is filed; it returns a block with `Draft:` (absolute path), `Tracker:`, `Verdict:` (the last review
  round's, read by the caller's completeness gate), `Summary:` (requirement and criteria counts, AC-DOC target or reason)
  and `Unresolved findings:`, without asking whether to proceed with gaps.
