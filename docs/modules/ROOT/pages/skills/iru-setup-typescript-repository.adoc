= Setup TypeScript Repository
:description: End-to-end bootstrap or update of an npm/TypeScript repository of seven flavors (library, react, nextjs, angular, nestjs, react-native, ionic).
:keywords: iru-setup-typescript-repository, claude code skill, npm, typescript, nextjs, nestjs, angular, react native, ionic, repository bootstrap

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for an npm/TypeScript repository of any of seven flavors. It collects the flavor, the
project's identity, and the shared pipeline parameters once, announces whether it is setting up from scratch or
updating an existing repository, then orchestrates six other skills in a fixed order so nothing is asked twice.

== Purpose

`iru-setup-typescript-repository` is the front door for starting (or catching up) a brand-new npm/TypeScript
repository, whatever its shape — a published library, a React, Next.js or Angular web app, a NestJS backend
service, or a React Native or Ionic mobile app. Rather than duplicating each flavor's scaffold logic, documentation setup, `.gitignore` rules, CI
workflows, changelog bootstrapping, or README generation, it resolves the `flavor` and `mode`, gathers the
project's identity and the shared pipeline parameters (open-source, publish/distribution, Sonar, integration
branch, Node version, package manager, repository visibility, CI, CI test scope, GitHub Pages) plus the
flavor-specific choices that shape later steps (NestJS `orm`/`database`, Next.js `output`/`e2e`) once, and passes each
downstream skill only the `args` keys it actually accepts. It opens with a "Setup mode" statement and an inventory
of every component it owns (absent / present / partial); the keep/update/replace question for pre-existing files is
asked by each sub-skill, never by this orchestrator, and the final report lists the action taken per component.
For private or internal repositories it states the cost context (included Actions minutes per plan, macOS minutes
roughly 10x Linux for the iOS release job, SonarCloud being free only for public open-source projects, GitHub Pages
requiring a paid plan) and recommends accordingly.

== Outputs

* A "Setup mode" announcement (from scratch vs updating an existing repository) with a per-component inventory.
* The flavor's own scaffold output — `package.json` and toolchain files (via `iru-setup-typescript-library`,
  `iru-setup-react-web`, `iru-setup-nextjs-web`, `iru-setup-angular-web`, `iru-setup-nestjs-app`,
  `iru-setup-react-native-app`, or `iru-setup-ionic-app`). When files
  already exist, the scaffold skill itself asks Update / Keep as is / Replace per file (or applies `on-existing`).
* A scaffolded Antora documentation site under `docs/` (via `iru-setup-antora`).
* A root `.gitignore` covering `node_modules/`, build output, coverage, and the Antora build output (via
  `iru-setup-typescript-gitignore`).
* `build.yml`/`release.yml`/`sync.yml`/`security.yml` GitHub Actions workflows and `.github/dependabot.yml` (via
  `iru-setup-typescript-github-workflows`) — skipped entirely when `ci: no`, with the security block (Dependabot,
  dependency-review, CodeQL, OSV-Scanner, gitleaks) skipped alongside.
* A root `CHANGELOG.md` backfilled from git/GitHub release history (via `iru-setup-changelog`).
* A root `README.md` with badges, a project-status table, documentation links, and installation instructions
  (via `iru-setup-readme`).
* A final report summarizing the resolved flavor/mode/identity/license/pipeline parameters (including visibility, ci, ci-tests, pages), which files were
  created / updated / replaced / kept as is / skipped (ci: no) with mismatches listed for kept files, the cost
context for private repositories, the consolidated required-secrets table, decisions made on the user's
  behalf, and an explicit warning to review every generated file before building, committing, or relying on CI.

== Dependencies

=== Invokes

Each of the following is invoked via the xref:agents/iru-isolated-skill-executor.adoc[`iru-isolated-skill-executor`]
agent rather than a direct `Skill` call — every sub-skill re-derives what it needs straight from the filesystem
this orchestrator has just written to, so only a short completion summary needs to come back, keeping each
sub-skill's own exploration/file reads out of this orchestrator's own context:

* xref:skills/iru-setup-typescript-library.adoc[] — Step 5, when `flavor: library`: writes `package.json` and the
  library toolchain, passing identity and pipeline `args`.
* xref:skills/iru-setup-react-web.adoc[] — Step 5, when `flavor: react`: scaffolds a Vite React app, passing
  identity, pipeline, and `storybook` `args` (no `publish`/`distribution` key).
* xref:skills/iru-setup-nextjs-web.adoc[] — Step 5, when `flavor: nextjs`: scaffolds a Next.js app, passing
  identity, `output`, `e2e`, `distribution`, `package-manager`, `node-version` and pipeline `args`; `router`,
  `cache-components` and `styling` only if they arrived via `args`. `pages` is deliberately not sent.
* xref:skills/iru-setup-nestjs-app.adoc[] — Step 5, when `flavor: nestjs`: scaffolds a NestJS service, passing
  identity, `orm`, `database` (only when `orm` is not `none`), `distribution`, `package-manager`, `node-version` and
  pipeline `args`; `module-system` and `http` only if they arrived via `args`.
* xref:skills/iru-setup-angular-web.adoc[] — Step 5, when `flavor: angular`: scaffolds an Angular CLI app, passing
  identity (no `description`), `directory`, and pipeline `args`.
* xref:skills/iru-setup-react-native-app.adoc[] — Step 5, when `flavor: react-native`: scaffolds an Expo-managed
  app, passing identity (no `description`), `app-slug`, `app-directory`, `native-builds`, and `distribution`
  `args`.
* xref:skills/iru-setup-ionic-app.adoc[] — Step 5, when `flavor: ionic`: scaffolds a Capacitor hybrid app, passing
  `framework`, `app-id`, identity, and `distribution` `args`.
* xref:skills/iru-setup-antora.adoc[] — Step 6: scaffolds the Antora documentation site, invoked with no `args`
  (or only `on-existing` when supplied) since it derives the component name/title/version directly from `package.json`. Run before Step 8 so that
  skill's own docs-config survey finds it already in place.
* xref:skills/iru-setup-typescript-gitignore.adoc[] — Step 7: writes or updates the root `.gitignore`, invoked
  with no `args` (or only `on-existing` when supplied) since it explores the repository directly (package manager, framework, Playwright, docs
  tooling).
* xref:skills/iru-setup-typescript-github-workflows.adoc[] — Step 8: writes the CI/CD workflows, passing `flavor`,
  the pipeline parameters (including `visibility`, `pages`, and `ci-tests` where resolved),
  `publish`/`distribution`/`native-builds`/`framework`/`orm`/`output`/`e2e` (only when the flavor uses them), and the
  derived `docs-tool` as `args`. Skipped entirely when `ci: no`.
* xref:skills/iru-setup-changelog.adoc[] — Step 9: bootstraps the root `CHANGELOG.md`, invoked with no `args` (or
  only `on-existing` when supplied) since it works from the repository's own git tag/GitHub Release history.
* xref:skills/iru-setup-readme.adoc[] — Step 10, last: bootstraps the root `README.md`, passing `sonar`, `ci`, and `pages`
  (plus `on-existing` when supplied); it explores the finished state left by every earlier step.
