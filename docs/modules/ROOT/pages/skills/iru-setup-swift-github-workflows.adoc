= Setup Swift GitHub Workflows
:description: Scaffolds or updates build.yml, release.yml, sync.yml, security.yml, and dependabot.yml GitHub Actions workflows for a Swift/Apple CI/CD pipeline.
:keywords: iru-setup-swift-github-workflows, claude code skill, swift, swiftpm, xcodebuild, docc, swiftlint, github actions, ci/cd, sonarqube

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold (or update) the `build.yml`, `release.yml`, `sync.yml` (gitflow only), `security.yml`, and
`.github/dependabot.yml` GitHub Actions workflows for a Swift repository produced by `iru-setup-swift-library`
(a SwiftPM package) or `iru-setup-apple-app` (an XcodeGen/Tuist-generated Xcode app).

== Purpose

`iru-setup-swift-github-workflows` wires up the house CI/CD pipeline for the Swift/Apple stack: SwiftLint +
`swift format lint --strict`, a build/test step whose shape depends on `flavor` (library:
`swift test --enable-code-coverage --parallel` with a `.build` cache keyed on `Package.resolved`, plus an
`xcrun llvm-cov`-to-SonarQube-generic-XML coverage conversion and an optional `ubuntu-latest` Linux matrix leg; app: `xcodegen generate`/`tuist generate` plus one
`xcodebuild test -enableCodeCoverage YES` run per selected platform destination, piped through `xcbeautify`,
converted to Sonar's generic XML via SonarSource's `xccov-to-sonarqube-generic.sh`), an optional
SonarQube/SonarCloud scan, a DocC + Antora documentation build published to GitHub Pages from the stable
branch, a release workflow (library: verifies the release tag is valid semver and the manifest still parses,
plus an optional `release-please` job; app: archives, signs via `fastlane match` or an App Store Connect API
key, exports, uploads to TestFlight, and — for macOS — exports with Developer ID, notarizes and staples), a gitflow-only `sync.yml` that merges a
released branch back into the integration branch and bumps the development version (reusing
`iru-swift-bump-version`'s exact rewrite targets via a vendored `sync_versions.py`), and a
`security.yml`/`dependabot.yml` block (dependency-review, CodeQL, OSV-Scanner, gitleaks). Unlike its
Java/TypeScript/Android siblings, no single real Swift repository exists to genericize these templates from —
they are assembled instead from this catalog's own already-verified `iru-setup-swift-library`/
`iru-setup-apple-app`/`iru-swift-coverage`/`iru-swift-bump-version` commands, plus this skill's own verification
pass. If any relevant workflow file already exists, it asks the user whether to stop or attempt an update using
the templates as reference, preserving any step this skill doesn't own.

== Outputs

* `.github/workflows/build.yml`, `release.yml`, and (gitflow only) `sync.yml` — created fresh, or updated in
  place if any already existed and the user chose to continue.
* `.github/workflows/security.yml` and `.github/dependabot.yml` — always written (or updated), independent of
  `flavor`/`branching`.
* `.github/scripts/sync_versions.py`, always written together with `sync.yml` — never one without the other,
  and never for `main-only`.
* `.github/scripts/lcov_to_sonar_generic.py` — only when `flavor: library` and `sonar` isn't `none` (the app
  flavor instead fetches SonarSource's own `xccov-to-sonarqube-generic.sh` at CI time).
* A report of which files were created/updated/left untouched, open gaps (missing `docs/antora.yml`, a
  `Packages/Core` with no `swift-docc-plugin` dependency, a `<team-id>` the user still needs to supply, version
  wording that didn't match `sync_versions.py`'s regexes), the required-secrets table below, and warnings about
  what this skill's own verification pass could not exercise locally (no `brew` — SwiftLint, `xcbeautify`,
  `xcodegen`/`tuist`, and therefore the whole app-flavor pipeline beyond its rendered YAML).

=== Required secrets

[cols="1,2,2", options="header"]
|===
|Secret |Purpose |Only needed when

|`SONAR_TOKEN`
|Auth token for the SonarQube/SonarCloud scan
|`sonar` is `cloud` or `self-hosted`

|`MATCH_GIT_URL` / `MATCH_PASSWORD`
|`fastlane match`'s certs-repo URL and its encryption passphrase
|`flavor: app`, `signing: fastlane-match`

|`MATCH_GIT_BASIC_AUTHORIZATION`
|base64 of `<git-user>:<personal-access-token>` — how `match` clones a private certs repository over HTTPS on
the runner
|`flavor: app`, `signing: fastlane-match`

|`APP_STORE_CONNECT_API_KEY_ID` / `_ISSUER_ID` / `_KEY_BASE64`
|App Store Connect API key — auth for `fastlane pilot upload`, `apple-actions/upload-testflight-build`,
`notarytool`, and (api-key only) `-allowProvisioningUpdates`
|`flavor: app`, `distribution` isn't `none` — both signing modes, since `match` certificates never
authenticate an upload or a notarization

|`DEVELOPER_ID_CERTIFICATE_P12_BASE64` / `DEVELOPER_ID_CERTIFICATE_PASSWORD`
|Exported Developer ID Application certificate for the macOS `developer-id` export
|`flavor: app`, `macos` selected, `distribution` isn't `none`, `signing: api-key`

|`GITHUB_TOKEN`
|`sync.yml`'s `gh` calls, `security.yml`'s CodeQL/gitleaks jobs
|Automatic — no setup needed
|===

`sync.yml` also needs the repository setting under Settings -> Actions -> General -> "Workflow permissions" set
to allow GitHub Actions to create pull requests. The Pages deploy job needs Settings -> Pages -> "Build and
deployment" -> Source set to GitHub Actions.
