= Kotlin Code Quality
:description: Runs a JVM Kotlin project's detekt and ktlint (Gradle, Maven or Spotless) and reports every issue by tool and rule id, with optional baseline diff.
:keywords: iru-kotlin-code-quality, claude code skill, kotlin, detekt, ktlint, spotless, gradle, maven, static analysis, code quality report

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run whichever Kotlin static-analysis tools a JVM project actually has wired — detekt and ktlint — and report every
issue they find (file, line, rule id, severity, message), grouped by tool. This is a report-only skill: it never
fixes issues and never adds or changes detekt, ktlint or Spotless configuration.

== Purpose

`iru-kotlin-code-quality` gives plain Kotlin libraries, Kotlin Spring Boot services and Kotlin Quarkus services a
single lint pass on Maven or Gradle (Kotlin DSL or Groovy, wrapper preferred, multi-module aware). It verifies each
tool is genuinely wired before trusting a "zero issues" result, runs the wired tasks, then parses the generated
reports (detekt Checkstyle-format XML or SARIF, ktlint checkstyle or plain reporter output, Spotless console
output) instead of eyeballing console text. A tool that is not wired is reported as "not wired", never as a clean
pass. Android modules belong to `iru-android-code-quality`, Kotlin Multiplatform modules to xref:skills/iru-kmp-code-quality.adoc[], and Java sources in a mixed Java+Kotlin module belong
to `iru-java-code-quality`.

== Outputs

* A plain-text summary in the conversation — never a written file.
* An overall total, then per tool (and per module when several ran): whether it ran or was skipped as "not wired",
  which config, baseline or `.editorconfig` governed it, the total, the severity breakdown, and one line per rule
  bucket (detekt rule name, ktlint `ruleset:rule-id`, Spotless `formatting`).
* The file:line list with rule id, severity and message when the scope is smaller than the whole project.
* Notes for skipped Android modules and for Java sources left to `iru-java-code-quality`.
* With a baseline: only issues new since the baseline; a tool unwired in the baseline counts entirely as new.
* "No Kotlin static analysis configured (detekt/ktlint not wired)" when neither tool is wired anywhere.
* No source or configuration is modified: no `ktlintFormat`, `spotlessApply`, detekt `autoCorrect` or baseline
  creation.
