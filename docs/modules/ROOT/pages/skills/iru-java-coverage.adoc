= Java Coverage
:description: Measures exact line coverage for JVM (Java or Kotlin) classes with JaCoCo or Kover on Maven or Gradle, including Quarkus, against an optional coverage bar.
:keywords: iru-java-coverage, claude code skill, java, kotlin, maven, gradle, jacoco, kover, quarkus, code coverage

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run JaCoCo (or Kover) against a scoped or full unit-test run of a JVM project — Java or Kotlin sources, Maven or
Gradle — then read the generated CSV/XML report to give the exact, measured line-coverage percentage for the
specific class(es) the caller cares about. This is a read-only reporting skill: it measures and reports coverage, it
does not add tests or modify source/test/build code unless asked to as an explicit follow-up.

== Purpose

`iru-java-coverage` answers "does class X meet the coverage bar?" with an exact, report-derived percentage instead of
an eyeballed guess from test output. It detects the build tool and coverage engine (Maven with `jacoco-maven-plugin`;
Gradle with JaCoCo, using a throwaway init script that forces CSV/XML reports on without touching the build; Gradle
with Kover; Quarkus with `quarkus-jacoco`), reuses `iru-java-test`'s selector syntax to scope which tests run, infers
or accepts an explicit list of target classes (including Kotlin's compiler-generated `FooKt`, `Foo.Companion` and
lambda classes), and, for classes under the bar, points to the exact uncovered lines/branches in the per-class HTML
or XML report. It measures unit tests only and never runs Failsafe, `verify`, `integrationTest` or `quarkusIntTest`.
Android Gradle builds are redirected to `iru-android-coverage`.

When the Kotlin Multiplatform plugin is applied anywhere in the build, the skill stops and points to xref:skills/iru-kmp-coverage.adoc[] instead.

== Inputs

[cols="1,1,3,2", options="header"]
|===
|Argument |Required |Description |Default

|`selector`
|No
|Which tests to run, using the exact same syntax as the `iru-java-test` skill's selector table (class, class+method,
comma list, wildcard, package pattern, tag expression). Must cover every test class that exercises the target
class(es) — a selector scoped too narrowly undercounts real coverage, so a broader selector (a whole package, or
the full suite) is preferred when in doubt.
|None — omitting it runs the full unit suite.

|`TargetClass1,TargetClass2,...`
|No
|Comma-separated class name(s) to report coverage for.
|None — if omitted, target classes are inferred from the test selector by convention (`FooTest` → `Foo`), or, for
a wildcard/package/tag selector where no name can be inferred, every class touched by the run is reported (or the
user is asked which class(es) matter).
|===

== Outputs

* A plain-text summary in the conversation — never a written file.
* Per target class: exact line-coverage percentage (and branch/instruction coverage where relevant), computed from
  the CSV or JaCoCo-format XML counters — never estimated — labelled with the engine it came from (JaCoCo Maven,
  JaCoCo Gradle, Kover, `quarkus-jacoco`).
* If the user gave a coverage bar (e.g. "at least 80%"): a clear statement of whether each class meets it.
* For classes under the bar: a pointer to the per-class HTML report and the exact uncovered line numbers (via the
  `nc`/`pc`/`fc` span classes, or the XML `<line>` entries) rather than just the aggregate percentage.
* A class absent from the report is reported as 0% coverage, not as an error. Kotlin generated-code noise
  (`inline` bodies, companion rows, coroutine state machines) is called out as such.
* Quarkus: `@QuarkusTest` coverage from `quarkus-jacoco` and plain-unit-test coverage are reported separately, never
  summed; classes exercised only by `@QuarkusComponentTest` without `quarkus-jacoco` are reported as unmeasured, not 0%.
* A build, compilation or test failure (including a Docker-less Testcontainers/Dev Services start-up failure) is
  reported as such instead of reading a stale report.
* No source, test or build code is ever modified, and coverage is never re-run to try to raise a number.

== Dependencies

=== Invokes

None — `iru-java-coverage` is a leaf skill; it only runs Maven/Gradle commands and reads the generated reports. It
reuses the build-tool detection and selector syntax documented in xref:skills/iru-java-test.adoc[], and redirects
Android Gradle builds to xref:skills/iru-android-coverage.adoc[], but it does not call either skill.

It also points Kotlin Multiplatform projects at xref:skills/iru-kmp-coverage.adoc[] but does not invoke it.

  80% coverage bar (falling back to `mvn jacoco:prepare-agent test jacoco:report` directly if this skill is
  unavailable).
* xref:skills/iru-kotlin-springboot-code-one-task-group.adoc[] — Step 3.5, unit-only 80% coverage gate, via the xref:agents/iru-gate-runner.adoc[`iru-gate-runner`] agent.
