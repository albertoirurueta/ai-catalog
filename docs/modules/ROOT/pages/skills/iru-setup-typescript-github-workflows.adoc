= Setup TypeScript GitHub Workflows

Scaffold or update the `build.yml`, `release.yml`, `sync.yml` (every flavor but react-native/ionic), and
`security.yml` GitHub Actions workflows plus `.github/dependabot.yml` that make up an npm/TypeScript
repository's CI/CD release pipeline, for whichever of seven flavors the repository actually is.

== Purpose

`iru-setup-typescript-github-workflows` wires up the house pipeline for an npm/TypeScript repository of one of
seven flavors: `library` (a published npm package), `react` (a Vite/React web app), `angular` (an Angular CLI
web app), `react-native` (an Expo app, or a bare React Native Community CLI app on the Metro toolchain), `ionic` (an Ionic + Capacitor hybrid app), `nestjs` (a NestJS service),
or `nextjs` (a Next.js web app with `output` `server` or `static`). `build.yml` runs install, lint, format check,
typecheck, unit tests with coverage, an optional SonarQube/SonarCloud scan (skipped on fork pull requests), e2e
per `ci-tests` (Playwright for the web flavors and Next.js — each UI/e2e job also uploads the UI tests' `.ui-screenshots/` directory as a 7-day `ui-screenshots` artifact; for NestJS the `test:e2e` suite with Testcontainers
on the runner's Docker, after `prisma generate` when `orm: prisma`), the production build (plus an unpushed
container-image build check when a NestJS/Next.js server image is distributed), a docs build
(TypeDoc/Compodoc/Storybook) merged with an Antora build, and a GitHub Pages deploy from the stable branch only
(when `pages: yes`; with `pages: no` the merged site is uploaded as a workflow artifact instead).

`release.yml` is flavor-specific: npm publish via OIDC trusted publishing plus an optional Changesets version-PR
job for `library`; a web-bundle deploy to Pages for `react`/`angular` (`dist/` for Vite, `dist/<project>/browser/`
for Angular) and for `nextjs` with `output: static` (the `out/` export, with `basePath` taken from
`actions/configure-pages`); a multi-stage `Dockerfile` build pushed to GHCR for `nestjs` and `nextjs` `server`
with `distribution: internal` (no `release.yml` at all with `distribution: none`); with `pages: no` the web
flavors only build and upload the bundle as an artifact. For `react-native` with `toolchain: expo`, EAS or local
Gradle/Xcode builds per `native-builds`; with `toolchain: metro`, `build.yml` gains native jobs on top of the shared
`build` job — an `android` job on Linux (JDK 17, Gradle cache, `./gradlew assembleDebug testDebugUnitTest lint`), a
cost-gated macOS `ios` job (`bundle install`, cached `pod install`, unsigned simulator `xcodebuild`) and, only with
`ci-tests: full`, an `e2e-android` job running Maestro flows on a `reactivecircus/android-emulator-runner` emulator —
and `release.yml` signs an AAB with the upload keystore and uploads it to Google Play (internal track for
`distribution: internal`, production for `store`) and archives/exports/uploads the iOS app to TestFlight with an App
Store Connect API key (with `distribution: none`, only unsigned/debug-signed proof builds). Android/iOS store or
internal artifacts for `ionic`. `sync.yml` plus its companion
`.github/scripts/sync_versions.py` (library/react/angular/nestjs/nextjs) merge the stable branch back into the
integration branch and bump `package.json` to the next `x.y.(z+1)-dev.0` prerelease. `security.yml` runs the
shared Dependabot (`npm`, plus `docker` when a `Dockerfile` exists, and `gradle` for `/android` plus `bundler` for the
Gemfile on react-native/metro) / dependency-review / CodeQL (`javascript-typescript`, plus `actions` for
nestjs/nextjs/react-native-metro, `java-kotlin` with a manual Gradle compile and, on public repositories only,
`swift` with a manual simulator build for react-native/metro) / OSV-Scanner / gitleaks block. The skill ships generic
example templates embedded in the skill file, resolves versions at run time against the npm registry and GitHub
Releases API, and resolves every other placeholder from a survey of the target repository rather than guessing.

It announces whether it is creating the CI/CD workflows from scratch or updating an existing setup. For each
workflow file that already exists it warns and asks **Update** (merge, preserving any step it doesn't own, with a
diff shown), **Keep as is** (mismatches with this run's choices are listed in the report), or **Replace**
(regenerate from the template, losing customizations), plus **Stop**; `on-existing` applies one answer to every
file, and `mode: existing` alone does not skip the question. For private or internal repositories it states the
cost context (included Actions minutes per plan, macOS runner minutes about 10x Linux for the iOS release job and, for
Metro, the `build.yml` iOS simulator job (limited to stable-branch pushes and manual runs on private repositories
unless `ci-tests` is `full`),
SonarCloud pricing, Pages availability) before asking about `sonar`, `ci-tests`, and `pages`.

== Outputs

* UI-contract capture upload (see xref:guides/building-user-interfaces.adoc[Building user interfaces]): every Playwright
  e2e job (and the metro Maestro `e2e-android` job) sets `UI_SCREENSHOTS_DIR` and uploads `.ui-screenshots/` as a 7-day
  `ui-screenshots` artifact (`if: always()`, `if-no-files-found: ignore`). When `.ui-quality.yml` sets
  `accessibility: none`, no accessibility report (`a11y-report.txt`), upload or accessibility-only step is emitted. `ci-tests: unit` drops that upload with the
  Playwright steps. The Maestro job excludes the dev-only `ui-gallery` flows (a release APK has no gallery), so React
  Native component/screen gallery captures stay local (`iru-typescript-test`'s `e2e` selector).
* `.github/workflows/build.yml` and `.github/workflows/release.yml` — created fresh, or, if either already
  existed, updated (merged), replaced, or kept as is per the user's per-file choice (or `on-existing`).
  `release.yml` is not written for `library` with `publish: no`, nor for `nestjs`/`nextjs` `server` with
  `distribution: none`.
* `.github/workflows/sync.yml` and `.github/scripts/sync_versions.py` — written together, only for the
  `library`/`react`/`angular`/`nestjs`/`nextjs` flavors; never generated for `react-native`/`ionic`.
* `.github/workflows/security.yml` and `.github/dependabot.yml` — always created or updated, independent of
  `flavor`/`sonar`/`publish`/`distribution`. For react-native with `toolchain: metro`, CodeQL becomes a
  `javascript-typescript` / `actions` / `java-kotlin` (plus `swift` on public repositories only) matrix and Dependabot
  adds `gradle` (`/android`) and `bundler` entries.
* Supporting files created if missing: `sonar-project.properties` (when `sonar` isn't `none`, laid out per flavor),
  and `.gitignore` entries for `dist/`, `coverage/`, `docs/api/`, `docs/build/`, `storybook-static/`.
* A report stating from-scratch vs update, the per-file action (created / updated / replaced / kept as is) with every
  mismatch listed for kept files, the `visibility` used and its cost context, and what `ci-tests`, `pages`,
  `distribution`/`output`, `orm`, `sonar`, `docs-tool`, and the security block did.
* A report of required repository secrets and repository settings that must be enabled, plus any open gaps (missing
  Playwright config, missing `ExportOptions.plist`, missing `Dockerfile`, missing `Gemfile.lock`/`ios/Podfile.lock` on metro, `next.config` not reading
  `PAGES_BASE_PATH`, README/Antora wording that didn't match `sync_versions.py`'s default regexes), ending with a
  warning to review the workflows before relying on them.

`GITHUB_TOKEN` needs no setup — GitHub Actions provides it automatically for `sync.yml`'s `gh` calls and
`security.yml`'s `gitleaks`/CodeQL jobs.

The first GHCR push for `nestjs`/`nextjs` creates a private package even from a public repository; make it public
or grant the deploying host a pull token. The Testcontainers e2e step needs Docker on the runner (present on
GitHub-hosted `ubuntu-latest`).
