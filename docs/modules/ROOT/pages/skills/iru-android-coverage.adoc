= Android Coverage
:description: Detects the Android coverage path a module has wired (Kover, AGP, or vendored JaCoCo CLI), runs it, and reports exact line/branch coverage.
:keywords: iru-android-coverage, claude code skill, kotlin, gradle, kover, jacoco, agp, code coverage report, unit testing

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run whichever unit-test coverage path an Android/Kotlin module actually has wired — preferring the Kover Gradle
plugin, falling back to the Android Gradle Plugin's own `enableUnitTestCoverage` task, and falling back further to
a vendored JaCoCo CLI conversion — then parse the resulting JaCoCo-format XML to report exact line/branch
coverage percentages and uncovered line numbers for the requested scope. This is a read-only reporting skill: it
never adds tests or modifies source/test code.

== Purpose

`iru-android-coverage` answers "does this class/module meet the coverage bar?" with an exact, XML-derived
percentage instead of eyeballing Gradle console output. Because Android/Kotlin modules can have coverage wired in
three different ways (or none at all), it detects which one is actually configured before running anything, and
reports "coverage not wired" — naming exactly what's missing — rather than a false 0%/100% when none is.

== Outputs

* A plain-text summary in the conversation — never a written file.
* Per target class (or the whole module if unscoped): exact line-coverage and branch-coverage percentages,
  computed directly from the parsed JaCoCo-format XML counters — never estimated.
* If the user gave a coverage bar (e.g. "at least 80%"): a clear statement of whether each class/the whole module
  meets it, plus uncovered line numbers for anything under the bar.
* A named scope class absent from the report is reported as 0% coverage, not as an error (same convention as
  `iru-java-coverage`).
* If no coverage path is wired: "coverage not wired", naming exactly what's missing (no Kover plugin;
  `enableUnitTestCoverage` not set; no vendored `jacococli.jar`) — never a fabricated percentage.
* If the AGP task's XML wasn't found and Step 2 fell back to the vendored CLI conversion, that fallback is
  called out explicitly in the report.
* An existing `androidTest/debug/connected/report.xml` is reported for information only, clearly labeled as
  instrumented coverage, without re-running `connectedAndroidTest`.
* No source, test, or build code is ever modified, and coverage is never re-run to try to raise a number.
