= Setup Android GitHub Workflows
:description: Scaffolds gitflow or main-only GitHub Actions CI/CD and security workflows for an Android/Gradle library or app repository, plus Dependabot config.
:keywords: iru-setup-android-github-workflows, claude code skill, android, gradle, github actions, jacoco, dokka, sonarqube, ci/cd, dependabot

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold or update the GitHub Actions CI/CD and security workflows, plus a Dependabot config, for an
Android/Gradle repository produced by `iru-setup-android-library` or `iru-setup-android-app`.

== Purpose

`iru-setup-android-github-workflows` wires up the house CI/CD pipeline for an Android/Gradle repository: build
and unit test, an optional instrumented test on a `reactivecircus/android-emulator-runner` emulator, lint with
SARIF upload, unit-test coverage via AGP's own `createDebugUnitTestCoverageReport` task (with a vendored-
`jacococli.jar` fallback), an optional SonarQube/SonarCloud scan, a Dokka + Antora documentation build
published to GitHub Pages (library flavor; with `pages: no` the docs are still built but only uploaded as a workflow
artifact), and — depending on `flavor` — either an optional Maven Central
publish or a signed release build uploaded to Google Play or Firebase App Distribution. It also generates a
`security.yml` (dependency-review, CodeQL, OSV-Scanner, gitleaks, plus two opt-in jobs) and
`.github/dependabot.yml`, regardless of branching model. The skill supports two branching shapes —
`gitflow` (`develop.yml`/`main.yml`/`sync.yml`) and `main-only` (`main.yml`/`publish.yml`, no `sync.yml`) — and
two flavors (`library`/`app`), ships genericized example templates derived from a real Android library
repository's actual workflows, and resolves every placeholder from a survey of the target repository rather
than guessing. It announces whether it is creating the pipeline from scratch or updating an existing one; for each
pre-existing workflow file it compares the file with this run's choices, names every concrete mismatch (for example
an emulator step with `ci-tests: unit`, or a Pages deploy with `pages: no`), and asks Update / Keep as is / Replace
(Stop on the first question), preserving any step/job this skill doesn't own on Update. Standalone, it also
resolves `visibility`, `sonar`, `ci-tests` and `pages` with cost-aware recommendations for private repositories
(GitHub Actions minutes, SonarCloud pricing, GitHub Pages availability). There is no `ci` key: invoking the skill
means CI is wanted. Every `build` job also ends with an `Upload UI screenshots` step (`actions/upload-artifact`,
`if: always()`, 7-day retention) that attaches the `.ui-screenshots/` captures of the catalog's UI contract as a
`ui-screenshots` workflow artifact — evidence only, nothing is published (see
xref:guides/building-user-interfaces.adoc[Building user interfaces]). When the repository's `.ui-quality.yml` sets
`accessibility: none`, no accessibility report artifact, upload or accessibility-only job/step is generated (the UI test
run and screenshot upload are unaffected).

== Outputs

Which files are written depends on `branching` × `flavor`:

[cols="1,3", options="header"]
|===
|`branching` × `flavor` |Files written

|`gitflow` / `library`
|`.github/workflows/develop.yml`, `main.yml`, `sync.yml`, `.github/scripts/sync_versions.py`, `security.yml`,
`.github/dependabot.yml`

|`gitflow` / `app`
|Same six files (the release job inside `main.yml` differs internally — signing/store upload instead of
Maven Central publish)

|`main-only` / `library`
|`.github/workflows/main.yml`, `publish.yml`, `security.yml`, `.github/dependabot.yml`

|`main-only` / `app`
|Same four files (the release job inside `publish.yml` differs internally, same as above)
|===

* Every file above is created fresh when absent. When it already existed, it is updated in place (merged,
  preserving any step/job this skill doesn't own), replaced with the template, or left as is, per the user's answer
  or `on-existing` (Step 1); choosing Stop writes nothing. Per file, the report states the action taken
  (created / updated / replaced / kept as is) and, for a kept file, each mismatch with this run's choices.
* In every workflow's `build` job, an `Upload UI screenshots` step (`ui-screenshots` artifact, 7-day retention,
  `if-no-files-found: ignore`) covering the repository-root `.ui-screenshots/` and, with instrumented tests, each
  module's `connected_android_test_additional_output` captures; no extra job or runner is added.
* With `pages: no` the library `build` job uploads the built Dokka + Antora site as a `docs-site` workflow artifact
  (`actions/upload-artifact`) instead of the Pages artifact, and no `deploy-docs` job or Pages permissions are
  generated. With `ci-tests: unit` the emulator and KVM steps are omitted.
* A report of required repository secrets and settings — see the table below — plus any open gaps found along
  the way (missing `docs/antora.yml`, a Gradle Play Publisher plugin found and preferred over the workflow-level
  upload action, README/Antora wording that didn't match `sync_versions.py`'s regexes, a vendored
  `jacococli.jar` found and used instead of the AGP-path default).

Required secrets (only the rows that apply to what was actually generated need to be created):

|===
|Secret |Purpose |Only needed when

|`SONAR_TOKEN`

|`MAVEN_CENTRAL_USERNAME` / `MAVEN_CENTRAL_PASSWORD`

|`flavor: library`, `publish: yes`

|`ANDROID_KEYSTORE_BASE64`
|Base64-encoded release keystore, decoded to `<app-module>/release.jks` at build time
|`flavor: app`, `distribution` isn't `none`

|`ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`
|Exported as `SIGNING_STORE_PASSWORD`/`SIGNING_KEY_ALIAS`/`SIGNING_KEY_PASSWORD`, the exact env vars

|`flavor: app`, `distribution` isn't `none`

|`PLAY_SERVICE_ACCOUNT_JSON`
|Google Play service-account JSON for the workflow-level upload action
|`flavor: app`, `distribution: store`, no Gradle Play Publisher plugin found

|`FIREBASE_APP_ID` / `FIREBASE_SERVICE_CREDENTIALS`
|Firebase App Distribution upload
|`flavor: app`, `distribution: internal`

|`NVD_API_KEY`
|Raises the NVD lookup rate limit for OWASP Dependency-Check (the scan runs without it, just slower)
|`security-owasp-dependency-check: yes`

|`GITHUB_TOKEN`
|`sync.yml`'s `gh` calls, `security.yml`'s CodeQL/gitleaks jobs
|Automatic — no setup needed
|===

`sync.yml` also needs the repository's Settings → Actions → General → "Workflow permissions" set to allow
GitHub Actions to create pull requests. With `pages: yes`, the Pages deploy jobs also need Settings → Pages →
"Build and deployment" → Source set to **GitHub Actions** (and, for a private/internal repository, a GitHub Pro,
Team or Enterprise Cloud plan; the site is public unless Enterprise Cloud private access control is used); with
`pages: no` there is no Pages setting to change. These are called out explicitly in the final report since each
fails silently on the first real run without it.

The generated files' bytes come from template files under `templates/` (and, where a template needs variant-specific notes, `reference/`) in `.claude/skills/iru-setup-android-github-workflows/`; the skill reads only the files for the variant it resolved, not the whole set, which keeps its `SKILL.md` small.
