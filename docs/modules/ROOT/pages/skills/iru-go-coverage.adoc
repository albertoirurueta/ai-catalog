= Go Coverage
:description: Measures statement coverage of a Go module's container-free tests with -coverpkg and a stdlib Python profile parser, reporting per-file gaps against a bar.
:keywords: iru-go-coverage, claude code skill, go, coverage, coverprofile, coverpkg, testscript, covdata, statement coverage, measure coverage

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run a Go module's (or Go workspace's) fast, container-free tests with Go's statement coverage and report the exact, measured coverage for the files the caller cares about, read from the coverprofile. It is a report-only skill: it never adds tests or modifies source or test code.

== Purpose

`go tool cover -func` only reports per-function figures, so `iru-go-coverage` runs `go test -covermode=atomic -coverpkg=<pattern> -coverprofile=build/coverage/cover.out` and reads the profile with a small stdlib Python parser. The parser merges the duplicate blocks `-coverpkg` writes once per test binary, maps import paths back to repository-relative files, excludes generated files (`// Code generated ... DO NOT EDIT.`), and reports the statement % for the total and per file, with uncovered line ranges for files under the bar.

`-coverpkg=./...` makes code exercised from another package's tests count, including in-process testscript end-to-end tests that run the Cobra command tree, so a thin `cmd/<bin>/main.go` and `internal/cli` are measured fairly. Optionally a second profile from instrumented binaries (`go build -cover`, `GOCOVERDIR`, `go tool covdata textfmt`) is merged in. Branch coverage is reported as "not available in Go". Only container-free tests count toward the gate: the `integration` build tag is not set unless asked, and then the result is labeled as not the gate value. A target with no statements or outside `-coverpkg` is reported as "not in profile" rather than a false 0%.

== Outputs

* A plain-text summary in the conversation: the toolchain, how coverage was collected (`-coverpkg` pattern, `-covermode=atomic`, whether a binary profile was merged), the test selection (and that `integration`-tagged tests were not compiled), and whether the tests passed.
* Total statement %, with a verdict against the bar, and "branch coverage: not available in Go".
* Per target (or per file): statement %, and for every target under the bar the uncovered line ranges.
* Excluded generated files, thin entry points with no logic, and every `NOT IN PROFILE` target with its reason.
* Coverage from a failing run is reported with the failures listed, and a build failure is reported instead of a percentage.
* `build/coverage/cover.out` is left in place when `build/` is gitignored, otherwise deleted. No source, test or configuration is ever modified.
