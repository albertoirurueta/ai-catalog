= Draft GitHub Issue
:description: Interviews the user and writes a complete spec-style GitHub issue, functional or documentation, reviews it in a loop, offers a split, and files it after confirmation.
:keywords: iru-draft-github-issue, claude code skill, github issue, spec-style issue, acceptance criteria, issue review loop, documentation issue, ticket intake

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Write a fully specified GitHub issue the way a specification is written: grounded in the codebase, complete,
reviewed for gaps before it exists, and split into dependency-ordered sub-issues when it is too large.

== Purpose

`iru-draft-github-issue` is the detailed counterpart to the quick xref:skills/iru-create-github-issue.adoc[] path. It
explores the codebase, decides whether the issue is _functional_ (context, functional requirements, acceptance
criteria, optional technical details, out of scope, dependencies, task details) or _documentation_ (audience,
technical vs. non-technical page structure, diagrams, bibliography, acceptance criteria), interviews the user, writes the
draft to a file and then loops (at most five rounds) with xref:skills/iru-review-github-issue.adoc[], resolving
findings from the codebase first and asking the user for the rest. When the issue looks too large it offers
xref:skills/iru-split-github-issue.adoc[]. Nothing is created on GitHub until the user confirms the final draft.
It stops on non-GitHub hosts and is not meant for issues that already exist.

== Outputs

* A draft file for the issue, revised through the review loop.
* If the user confirms: a new GitHub issue (or, if a split was accepted, the root issue, sub-issues and milestone
  created by `iru-split-github-issue`, which receives the chosen label as `label:`).
* A final report with the issue number and URL.
* If the user declines, no issue is created and the draft remains the deliverable.
