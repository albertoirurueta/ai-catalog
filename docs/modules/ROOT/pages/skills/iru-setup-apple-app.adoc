= Setup Apple App
:description: Scaffolds a native Apple app's XcodeGen or Tuist manifest, shared SwiftPM Core package, test targets, lint/format config, and Fastlane/Sonar setup.
:keywords: iru-setup-apple-app, claude code skill, swift, xcodegen, tuist, swiftui, fastlane, sonarcloud, xcuitest, scaffold

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate a complete, buildable native Apple application scaffold — a project-generator manifest (XcodeGen's
`project.yml`, or Tuist's `Project.swift` + `Tuist.swift`) declaring one application target per selected platform
(iOS/iPadOS, macOS, watchOS), a shared `Packages/Core` local SwiftPM package for testable business logic,
per-platform Swift Testing unit-test and XCUITest UI-test targets, lint/format config, a gated `fastlane/Fastfile`,
and `sonar-project.properties` — from explicit example templates embedded in the skill itself.

== Purpose

`iru-setup-apple-app` bootstraps a new native Apple application from a house template: one XcodeGen or Tuist
manifest per repository, one application target per selected platform with `SWIFT_STRICT_CONCURRENCY = complete`
and the app's `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION`, a shared `Packages/Core` package that holds all
testable logic outside any UI framework, and per-platform Swift Testing/XCUITest targets. It never commits the
generated `.xcodeproj`/`.xcworkspace` — those are always generator output, regenerated on demand by
`xcodegen generate`/`tuist generate` and gitignored by the companion xref:skills/iru-setup-swift-gitignore.adoc[].
It is the Swift/Apple equivalent of xref:skills/iru-setup-android-app.adoc[] and
xref:skills/iru-setup-react-native-app.adoc[] for the other app-shaped stacks in this catalog; use
xref:skills/iru-setup-swift-library.adoc[] instead for a pure SwiftPM library with no app target.

== Outputs

* `project.yml` (XcodeGen) or `Project.swift` + `Tuist.swift` (Tuist), per `generator`, with one target/scheme
  triple per selected platform.
* `Packages/Core/Package.swift`, `Sources/Core/Greeter.swift`, and `Tests/CoreTests/GreeterTests.swift` — a
  minimal, genuinely testable placeholder business-logic package.
* Per selected platform, `Targets/<Platform>/Sources/<AppName>App.swift` (SwiftUI `App` entry point),
  `ContentView.swift`, `Tests/<AppName>Tests.swift` (Swift Testing), and `UITests/<AppName>UITests.swift`
  (XCUITest).
* `.swiftlint.yml` and `.swift-format` at the repository root.
* `fastlane/Fastfile`, with only the lanes `distribution`/`signing` back — never a lane this skill can't support.
* `sonar-project.properties`, only when `sonar` != `none`.
* No `.xcodeproj`/`.xcworkspace` — those are `xcodegen generate`/`tuist generate` output, never written here.
* A report of every resolved input, which files were created fresh versus left untouched (gap-fill) versus
  replaced (update), the Step 7 verification results, and explicit warnings (generator never run locally, review
  before build/commit, signing/Sonar credentials still needed).

== Dependencies

=== Invokes

None — `iru-setup-apple-app` is a leaf skill; it does not call any other skill in this catalog. Verification in
Step 7 runs through the xref:agents/iru-gate-runner.adoc[`iru-gate-runner`] agent, not another skill.

=== Invoked by

* xref:skills/iru-setup-swift-repository.adoc[] — Step 5 runs `iru-setup-apple-app` for the app flavor, passing
  the shared bootstrap inputs through `args` so this skill's own Step 2 questions are skipped.

=== Related agents

* xref:agents/iru-gate-runner.adoc[`iru-gate-runner`] — Step 7 runs the YAML/`swiftc -parse` checks and
  `swift build`/`swift test` against the scaffolded `Packages/Core`, plus `xcodebuild` against that package where
  possible, through this agent so the caller gets a compact pass/fail summary instead of raw command output.
  XcodeGen/Tuist generation itself (`xcodegen generate`/`tuist generate`) and everything downstream of a real
  `.xcodeproj` remain unverified locally, per Step 7.
