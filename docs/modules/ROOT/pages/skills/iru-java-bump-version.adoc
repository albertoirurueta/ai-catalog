= Java Bump Version
:description: Sets a Maven project's version to an exact value in pom.xml, single-module or reactor-wide, with optional README/Antora sync and dry-run.
:keywords: iru-java-bump-version, claude code skill, maven, pom.xml, versions-maven-plugin, semver, snapshot, sync version, dry run

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a Maven/Java project's version to an exact value across every file that needs to agree with it. For a
single-module `pom.xml` it rewrites the root artifact's own `<version>` element in place; for a reactor (a root
`pom.xml` declaring `<modules>`) it runs `mvn versions:set` so every module and parent reference updates
consistently in one step. This skill never computes a version itself — it only applies the exact value it is
given, validated for shape, and optionally syncs README/Antora mentions to match.

== Purpose

`iru-java-bump-version` is the Maven-ecosystem leaf that a caller — typically `iru-release` — delegates the
actual version-file edit to, instead of hand-editing `pom.xml` or duplicating reactor-vs-single-module logic in
every skill that needs to change a project's version. It mirrors the same contract `iru-typescript-bump-version`,
`iru-android-bump-version`, and `iru-swift-bump-version` each define for their own ecosystems, documenting this
catalog's `X.Y.Z` / `X.Y.Z-SNAPSHOT` pre-release convention so a caller has one place to read the release/next-dev
computation from.

== Outputs

* `pom.xml` rewritten in place — either the root artifact's own `<version>` element (single module) or every
module's version via `mvn versions:set -DgenerateBackupPoms=false` (reactor).
* Optionally, when `sync-files` is accepted: a `<version>` dependency snippet in `README.md`, the `version:`
field in `docs/antora.yml` (only for a released, non-`-SNAPSHOT` value), and any Antora page under
`docs/modules/ROOT/pages/` showing a literal `<version>` dependency snippet.
* A report of the old and new version, whether the project was treated as a reactor or a single module, every
file actually touched, and the Step 6 sanity-check result.
* With `dry-run: yes`, no file is written and no mutating command is run — only the diff/command is shown.

== Dependencies

=== Invokes

None — `iru-java-bump-version` is a leaf skill; it only runs Maven (`mvn versions:set`, `mvn help:evaluate`) and
Python/regex file rewrites, and reports on the outcome. It does not call any other skill in this catalog.

=== Invoked by

* xref:skills/iru-release.adoc[] — Step 6, called twice per release (once to strip `-SNAPSHOT` for the release
version, once to bump and reappend `-SNAPSHOT` for the next development cycle) when `iru-release` detects the
repository's ecosystem is Java/Maven, discovered by its `find .claude/skills -maxdepth 1 -type d -name
"iru-*-bump-version"` lookup.

=== Related agents

None — this skill runs inline; it is not dispatched through `iru-gate-runner`, `iru-isolated-skill-executor`, or
`iru-change-summarizer`, and does not spawn the built-in Explore/general-purpose agents.
