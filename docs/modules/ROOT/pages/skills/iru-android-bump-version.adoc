= Android Bump Version
:description: Sets an Android/Gradle project's version to an exact value across lib/build.gradle.kts, app/build.gradle.kts, and optionally README/Antora mentions.
:keywords: iru-android-bump-version, claude code skill, android, gradle, kotlin dsl, versioncode, versionname, bump version, sync files

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set an Android (Gradle/Kotlin DSL) project's version to an exact literal value across every file that needs to
agree with it: `lib/build.gradle.kts`'s `libraryVersion`, `app/build.gradle.kts`'s `versionName` (and, per this
catalog's own convention, `versionCode`), and — optionally — `README.md`/Antora version mentions. This skill
never computes a version itself; it only applies exactly the string it is given, after validating its shape.

== Purpose

`iru-android-bump-version` is the Android/Gradle-ecosystem equivalent of a Maven `pom.xml` version bump: a small,
deterministic skill that a caller (typically `iru-release`) can invoke twice per release — once to strip the
`-SNAPSHOT` suffix for the release itself, once to open the next development cycle — without either caller having
to hand-edit Kotlin DSL build scripts or reason about `versionCode` semantics. Because Gradle doesn't parse or
validate a free-form version string the way npm's `version` command does, this skill validates with a regex
instead and rewrites each file with a targeted `python3` substitution.

== Outputs

* `lib/build.gradle.kts`'s `val libraryVersion = "…"` updated to the new version, when a `lib` module exists.
* `app/build.gradle.kts`'s `versionName` updated to the new version, when an `app` module exists; `versionCode`
  incremented by exactly 1 only when `<new-version>` does not end in `-SNAPSHOT` (left unchanged otherwise).
* Optionally, `README.md`'s dependency snippet, `docs/antora.yml`'s `version:` field, and/or Antora pages with a
  literal dependency snippet, if `sync-files` was accepted.
* A `./gradlew -q help` sanity check confirming the rewritten Kotlin DSL is still syntactically valid (skipped on
  a `dry-run`).
* A report of the old and new version, every file actually changed (or skipped and why), whether `versionCode`
  was bumped, and a warning to review the diff before committing.
* No commit is created — this skill only edits files (or, on `dry-run: yes`, only prints diffs).
