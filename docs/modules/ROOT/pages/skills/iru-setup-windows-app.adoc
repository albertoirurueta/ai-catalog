= Setup Windows App
:description: Scaffolds a WPF, WinUI 3 or Windows Forms app on .NET 10 with a UI-free Core project, MSTest and coverlet tests, FlaUI UI tests, DocFX and MSIX packaging.
:keywords: iru-setup-windows-app, claude code skill, windows desktop, wpf, winui, winforms, dotnet 10, msix, mstest, flaui, docfx, scaffold app

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate a complete, buildable Windows desktop app on .NET 10 and C# 14: a solution with a UI-free `Core` library
holding all testable logic, a WPF, WinUI 3 or Windows Forms app project composed with the Generic Host, an MSTest 4
Core test project at 100% line coverage, optional FlaUI UI tests, DocFX API docs and optional MSIX packaging, written
from templates in the skill's `reference/` files.

== Purpose

`iru-setup-windows-app` is the scaffold step of the Windows chain run by `iru-setup-windows-repository`, and it also
works standalone. It writes `global.json`, `Directory.Build.props` (the app `<Version>` `x.y.z[-dev]`, nullable,
warnings as errors, `EnableWindowsTargeting` so WPF and WinForms build on Linux and macOS, one SARIF analyzer log per
project), central package management, `.editorconfig`, `stylecop.json`, an `<AppName>.slnx` solution, `src/<AppName>.Core`
(models and services, plus `ViewModels/` for MVVM or `Controllers/` and a passive-view interface for MVC), the
`src/<AppName>` UI project per `ui`, MSTest tests with `tests/coverlet.runsettings`, an optional FlaUI
`tests/<AppName>.UITests` project, a root `.ui-quality.yml`, a DocFX `docfx.json`, generated placeholder icons and, for WPF/WinForms with
`msix: yes`, a `packaging/` folder with `AppxManifest.xml` and `build-msix.ps1`.

The layout is the scaffold contract that `iru-windows-code-one-task`, `iru-windows-code-one-task-group`, the
`iru-dotnet-*` gate skills, `iru-dotnet-bump-version` and `iru-setup-windows-github-workflows` rely on; Step 8 of the
skill lists the confirmed names, commands and paths. It announces whether it is scaffolding from scratch or updating,
and for each existing file group asks Update / Keep as is / Replace / Stop (unless `on-existing` decides). It never
overwrites hand-written source and treats a foreign layout (a single-project `dotnet new wpf` app, a `.sln` with other
projects, a `.wapproj` packaging project) as foreign. Toolchain versions are looked up at run time with a recorded
fallback table.

The FlaUI project follows the catalog's UI contract (see xref:guides/building-user-interfaces.adoc[Building user interfaces]): the app reads `--ui-direction`/`--ui-theme` launch arguments through a `UiTestOptions` class, and the tests render the main screen in every left-to-right/right-to-left x light/dark combination, capture it into `.ui-screenshots/` with the shared `UiScreenshots` helper, and run an Axe.Windows accessibility scan at the level recorded in `.ui-quality.yml`. The helpers (`UiQuality`, `UiScreenshots`, `AccessibilityCheck`) come from `reference/uitest-templates.md`.

== Outputs

* Build foundation: `global.json`, `Directory.Build.props`, `Directory.Packages.props`, `.editorconfig`, `stylecop.json`,
  `<AppName>.slnx`, and `.ui-quality.yml` (`accessibility`, `directions: [ltr, rtl]`, `themes: [light, dark]`; written for every `ui`).
* `src/<AppName>.Core` (UI-free, `net10.0`), `src/<AppName>` (WPF, WinUI 3 or WinForms app), `app.manifest`, `UiTestOptions.cs` (the UI-test launch-argument hook) and, for
  WinUI, `Package.appxmanifest` and publish profiles.
* `tests/<AppName>.Core.Tests` (MSTest 4 plus coverlet), `tests/coverlet.runsettings`, and optionally
  `tests/<AppName>.UITests` (FlaUI, `[TestCategory("UI")]`, Windows only) with the `UiQuality`, `UiScreenshots` and `AccessibilityCheck` helpers and a matrix capture test that writes `.ui-screenshots/screen/<MainWindow|MainForm>/<state>--<direction>--<theme>.png` (8 captures) and scans with Axe.Windows.
* `docfx.json` for the Core API, generated icon and tile PNGs, and, with `msix: yes` for WPF/WinForms, `packaging/`.
* A verification pass (restore, build with analyzers, `dotnet format`, Core tests and coverage, DocFX; Windows-only
  stages reported as unverified off Windows) and a report with the action per file group, versions used (live versus
  fallback) and the scaffold contract table.

== Dependencies

=== Invokes

None -- `iru-setup-windows-app` invokes no other catalog skill; it writes files from its own `reference/` templates and
runs `dotnet`, `docfx`, `pwsh` and `python3` directly. Its Step 7 verification and the documented gate commands mirror
those of xref:skills/iru-dotnet-test.adoc[], xref:skills/iru-dotnet-coverage.adoc[],
xref:skills/iru-dotnet-code-quality.adoc[] and xref:skills/iru-dotnet-docfx.adoc[], and the Core/UI layout it writes
is the contract for xref:skills/iru-windows-code-one-task.adoc[], xref:skills/iru-dotnet-bump-version.adoc[] and
xref:skills/iru-setup-windows-github-workflows.adoc[], but it does not call them.

=== Invoked by

* xref:skills/iru-setup-windows-repository.adoc[] -- Step 4 runs `iru-setup-windows-app` (through an isolated skill
  executor) first in the chain, passing the resolved shared inputs as `args`.
* xref:skills/iru-setup-repository.adoc[] -- reaches it indirectly by delegating to `iru-setup-windows-repository`. It
  can also be run directly by a person.

=== Related agents
