= Python Bump Version
:description: Sets a Python project's version to an exact PEP 440 value in pyproject.toml, __version__ literals, Django settings, FastAPI and uv.lock.
:keywords: iru-python-bump-version, claude code skill, python, version bump, pep 440, pyproject, uv, fastapi, django, release

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a Python project's version to an exact, caller-supplied value across every file that must agree with it,
following the catalog's PEP 440 `X.Y.Z.dev0` development-version convention.

== Purpose

`iru-python-bump-version` never computes a version; it validates the given string as PEP 440 (warning on
non-canonical forms such as `1.4.0-dev`, which normalizes to `1.4.0.dev0`) and applies it. An embedded Python helper
with `--list`, `--dry-run` and `--force` modes surveys and rewrites exactly the known locations: `pyproject.toml`
`[project].version` and `[tool.poetry].version`, legacy `setup.cfg` and `setup.py` literals, tracked `__version__`
literals, Django `VERSION` or `APP_VERSION` settings, and a `FastAPI(version=...)` literal only when it equals the
package version. File-based dynamic versions are followed to their source file; for a VCS-derived version (hatch-vcs,
setuptools-scm and similar) it reports that the git tag is the version and changes nothing. It refreshes `uv.lock`
with `uv lock` when the lockfile records the project's own version, and refuses to write when locations disagree
until the user confirms. Step 5 documents the pre-release convention that `iru-release` calls it against, and it can
optionally sync `docs/antora.yml` and README or Antora version mentions.

== Outputs

* Updated version locations for the detected project, and a refreshed `uv.lock` when it records the project's own
  version.
* Optionally updated `docs/antora.yml`, README and Antora mentions.
* A report: each location with its old value, the new version and whether it was normalized to canonical PEP 440,
  every file touched (or that a VCS-derived version changed nothing), any disagreement aligned with `--force`, any
  FastAPI API version left alone, and the sanity-check result (`--list` agreement, `uv lock --check`, `ast.parse`).
* A warning to review the diff before committing, and that a `.devN` version uploaded to PyPI is permanent.
