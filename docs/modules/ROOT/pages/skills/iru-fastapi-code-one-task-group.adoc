Implement one bucket of FastAPI tasks from a plan's task group end to end: one quality baseline up front, each task implemented with its fast tests, then the whole bucket validated once — with the container-backed stage serialized behind a repository-wide lock.

== Purpose

`iru-fastapi-code-one-task-group` is the FastAPI counterpart to `iru-nestjs-code-one-task-group` and `iru-php-code-one-task-group`, built on the shared Python gate skills (`iru-python-test`, `-coverage`, `-code-quality`, `-docstrings`), each run through an `iru-gate-runner` agent. Step 1 detects the runner prefix, layout, persistence stack, sync versus async, Alembic, the fast versus `integration` test split, wired quality tools and Docker availability, and captures one pre-change quality baseline. It then implements each task through `iru-fastapi-code-one-task` (in parallel agents when allowed, except tasks sharing `main.py`, `dependencies.py`, a model module or `conftest.py`, or each adding an Alembic revision).

Step 3 validates cheapest first: license headers, docstrings, scoped fast tests, optional import boundaries, an 80% coverage gate measured from container-free tests alone, the full fast suite, Ruff plus mypy/pyright (plus Bandit) diffed against the baseline, an app-import and OpenAPI-build smoke check with a single-head Alembic check, and last the container-backed stage behind the atomic `mkdir`-based `.integration-test.lock` (stale after 60 minutes, bounded ~45-minute wait, released on every exit path). That stage runs `iru-python-test integration` and, when models or migrations changed, an `alembic upgrade`, `check` and `downgrade` round trip against a throwaway PostgreSQL. Integration results never count toward coverage, and a stage needing Docker when it is unavailable is reported unverified.

== Outputs

* Source files, fast tests, integration tests and Alembic revisions created or modified per task, via `iru-fastapi-code-one-task`.
* License headers and docstrings kept current across the files the bucket touched.
* Container-free test coverage of at least 80% lines for changed or new production files, never satisfied by integration tests.
* No new Ruff, mypy/pyright or Bandit issues versus the baseline, an app that imports with an OpenAPI schema that builds, and a single Alembic head.
* `implementation_plan.md` with each task's checkbox checked and its note replaced by the final outcome, quoting the container-free coverage, the integration result and the Alembic result separately.
* A bucket report to the caller: detected shape, per-task results, accepted coverage exceptions, type-check and security findings, the smoke check, the container-backed outcome (passed, fixed, unverified with reason, or no integration selection), lock behavior, and any blocked task.
