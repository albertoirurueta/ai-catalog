= Java Test
:description: Runs a JVM project's JUnit tests via Maven Surefire or the Gradle test task (Java, Kotlin, Spring Boot, Quarkus), scoped by selector, and reports results.
:keywords: iru-java-test, claude code skill, java, kotlin, maven, gradle, junit, quarkus, run unit tests, test selector

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run a JVM (Java or Kotlin) project's JUnit test suite through the Maven Surefire plugin (`mvn test`) or the Gradle
`test` task (`./gradlew test --tests '<pattern>'`), scoped to whatever the caller asked for — everything, a single
class, a single method, a wildcard/package pattern, or a tag expression. This is a read-only reporting skill: it runs
tests and summarizes the outcome, it does not fix failures unless asked to as an explicit follow-up.

== Purpose

`iru-java-test` turns a loosely-specified request ("run the FooTest", "just the fast tests", "everything") into the
correct invocation for the detected build tool and a concise pass/fail summary. It covers plain Java/Kotlin
libraries, Spring Boot (Java or Kotlin), and Quarkus (Java or Kotlin). It exists so that running and narrowing down
tests doesn't require hand-composing `-Dtest`/`-Dgroups`/`--tests` syntax each time, and so that a calling skill (or a
human) gets back a short report instead of a full raw build log.

When the Kotlin Multiplatform plugin is applied anywhere in the build, the skill stops and points to xref:skills/iru-kmp-test.adoc[] instead.

== Inputs

[cols="1,1,3,2", options="header"]
|===
|Argument |Required |Description |Default

|`selector`
|No
|Names what to run: a test class (`FooTest`), a class+method (`FooTest#testSomething`, including a Kotlin backtick
name), several classes, a wildcard/package pattern, an exclusion, or a tag expression, optionally prefixed with a
module (`:service:FooTest` / `-pl service`). Mapped to the correct parameter for the detected build tool.
|None — omitting it runs the full unit suite (`mvn test` / `./gradlew test`).
|===

The build tool is detected first: `pom.xml` means Maven (`./mvnw` allowed when `mvn` is absent); `settings.gradle(.kts)`
or `build.gradle(.kts)` without a `pom.xml` means Gradle (wrapper preferred, system `gradle` only as a stated
fallback); when both exist the CI workflow decides, and if that doesn't settle it the user is asked once. An Android
Gradle plugin means the project is Android and `iru-android-test` is the right skill instead. Multi-module builds are
scoped to the named module(s) (`-pl <module> -am` for Maven, `:<module>:test` for Gradle).

Maven selectors map to Surefire parameters as follows:

[cols="3,3,3", options="header"]
|===
|What the user wants |Parameter |Example

|Everything
|_(none)_
|`mvn test`

|One test class
|`-Dtest`
|`mvn test -Dtest=FooTest`

|One method in a class
|`-Dtest` with `#`
|`mvn test -Dtest=FooTest#testSomething`

|Several methods in one class
|`-Dtest` with `+` between method names after `#`
|`mvn test -Dtest=FooTest#method1+method2`

|Several classes
|`-Dtest` comma-separated
|`mvn test -Dtest=FooTest,BarTest`

|Classes matching a name pattern
|`-Dtest` with `*` wildcard
|`mvn test -Dtest=*ServiceTest`

|All classes in a package
|`-Dtest` with the package path and wildcard
|`mvn test -Dtest=com.example.pkg.**`

|Excluding some classes/methods
|`-Dtest` with `!` prefix (combine with other `-Dtest` entries via comma)
|`mvn test -Dtest=!SlowTest`

|Tests tagged with a JUnit 5 `@Tag`
|`-Dgroups`
|`mvn test -Dgroups="fast"`

|Excluding a JUnit 5 tag
|`-DexcludedGroups`
|`mvn test -DexcludedGroups="slow"`

|Tag boolean expression
|`-Dgroups` with `&`, `\|`, `!`
|`mvn test -Dgroups="fast & !flaky"`
|===

Gradle selectors map to `--tests` filters, always placed immediately after the `test` task they filter:

[cols="3,3,3", options="header"]
|===
|What the user wants |Parameter |Example

|Everything
|_(none)_
|`./gradlew test`

|One test class
|`--tests` (simple or fully qualified name)
|`./gradlew test --tests 'FooTest'`

|One method in a class
|`--tests` with `.` (not `#`)
|`./gradlew test --tests 'FooTest.testSomething'`

|Several classes/methods
|repeat `--tests`
|`./gradlew test --tests 'FooTest' --tests 'BarTest'`

|Name or package pattern
|`--tests` with `*`
|`./gradlew test --tests '*ServiceTest'`

|One module only
|prefix the task path
|`./gradlew :service:test --tests 'FooTest'`

|Several modules
|list each task plus `--continue`
|`./gradlew :a:test :b:test --continue`
|===

A Maven-style selector passed by a caller is translated (`FooTest#method` becomes `--tests 'FooTest.method'`).
Exclusions and JUnit 5 tag expressions have no Gradle command-line flag: the skill looks for a project property wired
to them and, if none exists, tells the user the filter cannot be applied without editing the build script (which it
never edits itself) and offers the closest class/package selector. A selector matching nothing fails the build in
both tools ("No tests matching pattern..." / "No tests found for given includes"); the no-match-is-fine flags are only
added when the user explicitly asks. `--rerun` (Gradle 7.6+) or `cleanTest` is used only when a re-run of an
up-to-date scope is actually wanted.

Kotlin notes: test sources in `src/test/kotlin` use the same selectors. Backtick method names compile to names with
spaces, so the whole selector is single-quoted (`--tests 'FooTest.should parse input'`,
`-Dtest='FooTest#should parse input'`); if such a name does not resolve, the skill widens to a wildcard on a
distinctive prefix and says so in the report.

Quarkus notes: `@QuarkusTest` classes are ordinary Surefire/`test`-task tests, but boot the application (slower).
They may start Dev Services containers, which need a Docker/Podman daemon; a "Docker is not running"-style failure is
reported as an environment failure, not a test failure, and Dev Services are disabled only if asked
(`-Dquarkus.devservices.enabled=false` for Maven, the `QUARKUS_DEVSERVICES_ENABLED=false` environment variable for
Gradle). `@QuarkusIntegrationTest`/`*IT` classes (and Testcontainers-backed Spring Boot `*IT` classes) are not part of
the default run — they only run, under `mvn verify` or the Gradle `quarkusIntTest`/`integrationTest` task, on
explicit request. `./gradlew build`/`check` and `mvn verify` are never used for a plain unit-test request.

== Outputs

* A plain-text summary in the conversation — never a written file.
* Total tests run, failures, errors, and skipped counts — from Surefire's totals line for Maven, or from the JUnit
  XML under `build/test-results/test/` (parsed with a short `python3` snippet) for Gradle, whose console only lists
  failures.
* If everything passed: a brief confirmation, without pasting the full log.
* If there are failures/errors: the failing test names and the relevant assertion/exception output (from
  `target/surefire-reports/*.txt` or the `<failure>`/`<error>` element of the matching Gradle XML if the console
  output was truncated) — without unrelated passing-test noise.
* Environment failures (Docker/Dev Services/Testcontainers unavailable) reported separately from genuine test
  failures, naming the test classes that could not run.
* No source or test code (and no build script) is ever modified.
