= Rust Rustdoc
:description: Audits Rust crates for complete rustdoc on public items, fills the gaps, and verifies with doc lints, cargo doc under -D warnings and cargo test --doc.
:keywords: iru-rust-rustdoc, claude code skill, rust, rustdoc, doctests, clippy, cargo doc, intra-doc links, audit rustdoc, fill missing docs

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Make sure a set of Rust items carry complete, well-formed rustdoc, filling in whatever is missing, then prove the
result through the doc lints, a warnings-as-errors `cargo doc` build and the doctests. It only adds or completes doc
comments (`///` and `//!`) — it never changes behavior, signatures, attributes, `use` lines or any non-doc code.

== Purpose

`iru-rust-rustdoc` surveys the Cargo workspace (library roots, binaries, which targets run doctests), then audits
every public item reachable from the crate API: the crate root `//!` docs, public modules, structs, enums with each
variant, `pub` fields, traits, functions, methods, consts, type aliases and exported macros. It discovers the
project's documentation bar first (`[lints]` tables, CI `RUSTDOCFLAGS`, docs.rs metadata, house style) and then writes
what is missing following the rustdoc and API Guidelines convention: a one-sentence summary, `# Errors`, `# Panics`,
`# Safety` and runnable `# Examples` sections, and intra-doc links instead of bare names.

It knows that doctests only run for library targets, so a bin-only crate's `main.rs` examples are never compiled; it
documents binary items for readers but puts examples on the library items the binary calls, which is why this
catalog's CLI scaffold keeps the logic in `lib.rs`. Test code, benches, examples and generated code are out of scope.

[source]
----

Comma-separated item paths such as `crate::output::Envelope` or `commands::greet::run`, and files or globs such as

== Outputs

* Edited `.rs` files with added or completed doc comments: crate and module `//!` docs, summaries, field and variant
  docs, `# Errors`, `# Panics`, `# Safety` sections, doctest examples and intra-doc links.
* A per-file report: public items already fully documented, gaps found and filled (kind and what was added).
* The verification result: doc lints clean or what remains, `cargo doc` with `-D warnings` pass or open warnings, and
  doctests passed or failed ("none" for a bin-only crate).
* The convention used and where it came from, arguments dropped, and pre-existing out-of-scope failures as follow-ups.
  Raw tool output is never pasted.
