= Split GitHub Issue
:description: Assesses whether a GitHub issue is too large and splits it into dependency-ordered sub-issues under a root issue, tracked by a milestone, after confirmation.
:keywords: iru-split-github-issue, claude code skill, github issue, sub-issues, milestone, issue dependencies, parallel groups, ticket intake

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Turn one oversized issue into a root issue plus small, self-sufficient sub-issues ordered by dependency.

== Purpose

`iru-split-github-issue` judges size from signals (many requirements, several independently deliverable capabilities,
several areas touched, estimated difficulty hard or above), proposes slices that each own a subset of the
requirements and acceptance criteria, computes `Blocked by` relations and parallel groups (same group means independent),
reviews each sub-issue draft with xref:skills/iru-review-github-issue.adoc[], and creates the root issue, a milestone linking it
(reusing an existing milestone with the same title), the sub-issues and GitHub's sub-issue links. Steps 1 to 5 are read-only: nothing is created, edited or linked before the explicit
confirmation in Step 6. An existing issue stays the root and its original text is preserved. It stops on
non-GitHub hosts.

== Outputs

* After confirmation: the root issue (new or rewritten), a milestone linking it (found by title across open and
  closed milestones and reused, or created), the sub-issues in dependency order, and
  sub-issue links (a task list fallback when the endpoint is unavailable).
* A report with the milestone and issue URLs and a table of sub-issues.
* If the user declines, nothing is created and the proposal is the deliverable.
