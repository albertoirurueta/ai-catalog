Implement one bucket of TypeScript tasks from a plan's task group end to end: capture a single pre-change quality
baseline, run `iru-typescript-code-one-task` once per task (in parallel when the group allows it), then validate
the entire bucket once — license headers, TSDoc, scoped tests, an 80% coverage check, a full-suite run, and a
code-quality regression check.

== Purpose

`iru-typescript-code-one-task-group` is the npm/TypeScript counterpart to `iru-java-code-one-task-group`, carrying
the same cost-cutting shape into TypeScript projects: it validates a whole bucket once instead of once per task.
Step 1 detects the project's flavor (`hilla-frontend` / `react-native` / `ionic` / `angular` / `react` / `library`),
test runner (Vitest, Jest, or the Angular CLI builder), and package manager (npm/pnpm/yarn) once, then captures a
pre-change quality baseline covering every file the bucket's tasks are expected to touch. Step 2 implements each
task via `iru-typescript-code-one-task` — concurrently, in a single batch of `Agent` calls, when the plan marks the
group `Parallelizable: yes`; one at a time otherwise. `iru-typescript-code-one-task` itself checks off each task's
box in `implementation_plan.md` the moment that task finishes, with a "group validation pending" note — this skill
re-reads the file as each task's agent reports back to confirm the box landed, backfilling it only if a rare
concurrent-write race clobbered it, and notifies the user before group-wide validation runs. Once every
non-blocked task has landed, Step 3 validates the whole bucket in one pass: license headers, TSDoc, the affected
test files, coverage, the full suite, and a quality-regression check against its one baseline. A failure traced to
a specific task sends that task back for a fix and a re-run of the affected checks, rather than re-validating the
whole bucket.

== Outputs

* Source and test files created/modified per task, via `iru-typescript-code-one-task`.
* License headers and TSDoc kept current across every file the bucket touched, checked once for the whole bucket
  rather than once per task.
* Tests achieving at least 80% line and branch coverage for the bucket's changed/new files, verified against the
  real coverage report.
* `implementation_plan.md` with each task's (and sub-task's) checkbox checked and a progress note — first an
  "implemented, group validation pending" note written by `iru-typescript-code-one-task` itself as each task lands
  (backfilled here only if a rare concurrent-write race dropped it), then replaced with the final coverage/quality
  outcome once bucket-wide validation passes.
* User-facing notifications at both phases: per task as its implementation lands, and once when group validation
  completes.
* A summary handed back to the caller (`iru-code-one-task-group`): per task, files touched, tests added/updated,
  coverage achieved, code-quality outcome, and any task that stopped on a blocker.
