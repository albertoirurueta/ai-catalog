Create or update the root `.gitignore` for a Java project, using this repository's own `.gitignore` as the
concrete reference template — never overwriting an existing file without showing the user exactly what would
change and getting an explicit Update / Keep / Replace decision first.

== Purpose

`iru-setup-java-gitignore` composes a Java-appropriate `.gitignore`: a universal base (compiled classes, logs,
packaged artifacts, JVM crash logs) plus conditionally-detected sections for the actual build tool (Maven
`/target/` or Gradle `build/`/`.gradle/`), IDE files (IntelliJ, VS Code, Eclipse), a generated build-info
properties file if a Groovy/Maven plugin writes one, and Antora documentation build output. It never invents
entries for things that aren't actually present in the target repository. The skill announces whether it is
creating `.gitignore` from scratch or updating an existing one. If `.gitignore` already exists, it is treated as
sensitive: the skill reads it, warns, merges rather than duplicates, shows the user a diff, and asks whether to
Update (merge, keeping hand-added entries), Keep it as is, or Replace it with the pure template (hand-added entries
lost) — unless `on-existing` already decides.

== Outputs

* A `.gitignore` file at the repository root — newly created, updated, or replaced, or left untouched when Keep is
  chosen.
* If `.gitignore` didn't previously exist: it is written directly, no approval step needed.
* If `.gitignore` already existed: a diff of the proposed content is shown first, and the user chooses Update
  (write the merged draft), Keep as is (no change), or Replace (write the pure-template version), unless
  `on-existing` decides.
* A closing report stating whether the file was created, updated, replaced, or kept as is (and whether that came
  from the user or `on-existing`), which conditional sections (build tool, IDE, build-info file, Antora build
  output) were included versus skipped and why, the hand-added lines dropped by Replace, and the template entries
  still missing after Keep.
