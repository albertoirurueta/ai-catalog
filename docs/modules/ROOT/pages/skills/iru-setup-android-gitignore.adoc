= Setup Android Gitignore
:description: Creates or gap-fills the root and per-module .gitignore files for an Android Gradle project, never ignoring a vendored JaCoCo CLI directory.
:keywords: iru-setup-android-gitignore, claude code skill, android, gradle, kotlin, jacoco, gitignore, keystore, antora

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

`iru-setup-android-gitignore` composes the root `.gitignore` and one per-module `.gitignore` for an Android
(Gradle/Kotlin) library or app project, using
https://github.com/albertoirurueta/irurueta-android-glutils[irurueta-android-glutils]'s own `.gitignore`,
`lib/.gitignore` and `app/.gitignore` as the concrete reference templates. It never overwrites an existing
`.gitignore` silently: it announces whether it is creating files from scratch or updating existing ones, and for each
pre-existing file it warns, shows a diff and asks the user to Update, Keep as is, or Replace.

== Purpose

The skill produces a house-standard Android `.gitignore`: an unconditional root base (Gradle build output,
`local.properties`, IDE files, keystores, `google-services.json`, profiling output, the Kotlin 2.x compiler's
root-level `.kotlin/` cache, the UI tests' `.ui-screenshots/` capture directory, plus the catalog's own Antora `docs/build/`/`docs/node_modules/` additions), a
one-line anchored `/build` `.gitignore` for each Gradle module, and a conditionally-detected root section for
Fastlane output. It deliberately never ignores a vendored `jacoco-<ver>/` JaCoCo CLI directory if the repository
vendors one (as the reference repository does, for `iru-setup-android-github-workflows`' opt-in
coverage-conversion fallback), since CI would depend on that directory staying tracked to convert coverage
without a network dependency. It mirrors `iru-setup-java-gitignore`'s warn-and-ask contract (Update / Keep as is /
Replace per pre-existing file), adapted to the Android/Gradle ecosystem. `.ui-screenshots/` is the repository-wide
capture directory of the catalog's UI contract (cleared by every full UI test run, with the few images the docs use
copied into the Antora module's `images/ui/`), so it is ignored unconditionally; the committed `.ui-quality.yml` next
to it is never ignored.

== Inputs

|===
|Argument |Required |Description |Default

|`mode`
|No
|`new` or `existing`. Selects whether the skill should expect to write fresh files or work with files that already
exist. `existing` never means "update silently": every pre-existing file still goes through the Update / Keep /
Replace question unless `on-existing` decides it.
|Detected from whether a root `.gitignore` already exists (present → `existing`, absent → `new`).

|`modules`
|No
|Comma- or space-separated Gradle module directory names that should each get their own `/build`-only
`.gitignore` (e.g. `lib`, `app`).
|Derived from every `include(":<name>")` entry in `settings.gradle.kts`/`settings.gradle`; if neither file
exists yet, falls back to whichever of `lib`/`app` exist as directories, or asks the user via
`AskUserQuestion`.

|`on-existing`
|No
|`ask`, `keep`, `update` or `replace`. How each already-existing `.gitignore` is treated: `ask` asks per file;
the others apply that choice to every pre-existing file without asking (the warning and diff are still shown).
Meant for scripted runs; an orchestrator passes it only if it received it itself.
|`ask`
|===

== Outputs

* A root `.gitignore` — newly created, or, when one already existed, updated (merged), replaced with the bare
  template, or left as is, according to the user's answer or `on-existing`.
* A `<module>/.gitignore` for each resolved module (typically `lib`, `app`) — newly created, or handled the same
  way as the root file when it existed; skipped entirely when its content already matches.
* A closing report stating whether the run created from scratch or updated existing files, the action taken per
  pre-existing file (updated / replaced / kept as is, and whether the user or `on-existing` chose it, with the
  template lines still missing from each kept file), which
  conditional Step 4 section (Fastlane) was included versus skipped and why, and confirmation that no ignore
  pattern would match a vendored `jacoco-<ver>/` CLI directory if the repository has one.
