Create or refresh the root `.gitignore` of a Windows desktop application built on .NET (WPF, WinUI 3 or Windows Forms),
from a trimmed house template rather than GitHub's 400-line `VisualStudio.gitignore`.

== Purpose

`iru-setup-windows-gitignore` is the `.gitignore` step of the Windows chain run by `iru-setup-windows-repository`, and it
also works standalone against any `*.sln`/`*.slnx` desktop solution. The base template covers .NET build output
(`[Bb]in/`, `[Oo]bj/`, `artifacts/`, `publish/`), Visual Studio, Rider and VS Code user state, test and coverage output,
analyzer SARIF logs, NuGet packages, signing material (`*.pfx`, `*.p12`, `*.cer`), the Antora build output, OS files and
the repository-wide `.integration-test.lock/` that serializes desktop UI-test runs. It adds an MSIX section (`AppPackages/`,
`*.msix`, `*.appinstaller`, `packaging/layout/`) and a DocFX section (the `docfx.json` metadata and site folders) only
when those are detected.

It deliberately keeps `Properties/PublishProfiles/*.pubxml` tracked (WinUI publish profiles carry no secrets and the
build needs them) and does not ignore `*.snk`. Before proposing content it runs `git check-ignore` against the source
files the scaffold commits and refuses any line that would hide one. An existing `.gitignore` is never overwritten
silently: the skill shows a diff and asks Update (merge, keep hand-added lines) / Keep as is / Replace, unless
`on-existing` decides. It never untracks already-committed files; it reports them with the `git rm -r --cached` each
needs.

== Outputs

* The root `.gitignore`: created, updated (merged), replaced or kept as is.
* A report naming which conditional sections (MSIX, DocFX) were included or skipped and why, the result of the
  `git check-ignore` safety check, any already-tracked file under a newly ignored path, and warnings to review the file,
  untrack committed artifacts and rotate any certificate that was ever committed.
