= Go Bump Version
:description: Sets a Go module's in-tree Version literal to an exact value and checks the -ldflags -X overrides in GoReleaser, Makefile and workflow files.
:keywords: iru-go-bump-version, claude code skill, go, golang, version bump, ldflags, goreleaser, cobra, release

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a Go project's in-tree version literal to an exact, caller-supplied value, verify that the release build's
`-ldflags -X` override still reaches it, and follow the catalog's `x.y.z-dev` development-version convention.

== Purpose

`iru-go-bump-version` never computes a version; it validates the given string (`X.Y.Z` or `X.Y.Z-dev`, stripping a
leading `v`, asking about other SemVer pre-releases and refusing anything else) and applies it. An embedded Python
helper with `--list`, `--dry-run`, `--force` and `--files=` modes finds every `var Version = "..."` or
`const Version = "..."` literal in non-test, non-generated `.go` files, including the `internal/version/version.go`
file of the `iru-setup-go-cli` scaffold. It refuses to write when literals disagree until the user confirms, flags a
`const Version` (which `-ldflags -X` silently cannot override), and checks every `-X ...Version=` reference in
`.goreleaser.yaml`, `Makefile`, `Taskfile.yml`, `justfile` and GitHub workflows against the real import path, since the
linker ignores a wrong path silently. It warns when a major version 2 or above does not match a `/vN` module-path
suffix, without ever rewriting it. A library with no literal is reported as taking its version from git tags and
nothing is changed. Step 5 documents the pre-release convention that `iru-release` calls it against, and it can
optionally sync README and Antora version mentions.

== Outputs

* Updated `Version` literals in the detected `.go` files, or no change when the version comes from git tags.
* Optionally updated README and Antora version mentions.
* A report: each literal with its old and new value, `const` notes, every `-ldflags -X` reference marked `ok` or
  `MISMATCH`, every file touched, any disagreement aligned with `--force`, golden or test files that mirror the old
  value, and the sanity-check result (`--list` agreement, `--version` output or "not run").
* A warning to review the diff before committing, to tag releases as `v<new-version>`, and that a major version 2 or
  above needs the `/vN` module path.
