= Swift Generate All Tests
:description: Scans a Swift package or Xcode project for types missing tests or below 80% coverage, then writes Swift Testing/XCTest tests to clear the bar.
:keywords: iru-swift-generate-all-tests, claude code skill, swift, swiftpm, xcodebuild, swift testing, xctest, line coverage, generate unit tests

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Bring an entire Swift codebase's unit test coverage up to a minimum bar — 80% line coverage — in one pass: find
every production type (struct, class, enum, actor) with no test at all or with measured coverage below the bar,
then write or extend tests for each until it clears it. Swift Package Manager and Xcode projects only; it never
runs against, or falls back to, any other language.

== Purpose

`iru-swift-generate-all-tests` answers "bring this whole Swift codebase's test coverage up to a bar" rather than
"write tests for this one type/task," which is what `iru-swift-code-one-task` and the `iru-code` pipeline already
handle per task. It explores the whole codebase to build an inventory of testable types, delegates to
`iru-swift-coverage` for the exact, measured percentage per type (never an estimate), and only writes or extends
test code — defaulting to Swift Testing (`@Suite`, `@Test`, `#expect`, `#require`) for unit tests and falling
back to XCTest only for `XCUITest` and performance (`measure`) cases, following the project's own test framework
and style. It does not add license headers, DocC comments, or run a code-quality pass, and it only touches
production source code when a type is genuinely untestable as written, which it reports explicitly rather than
silently redesigning the type.

== Outputs

* New or extended test files for every type found with no matching test file, or with line coverage below 80% —
  defaulting to Swift Testing, following the project's own test-file naming/source-root convention, and using
  XCTest only for `XCUITest`/`measure` cases.
* Occasionally, a minimal testability change to a type under test (e.g. extracting a protocol, injecting a
  dependency) — only when a type is genuinely untestable as written, and always called out explicitly rather than
  folded silently into "tests added."
* A report: total candidate types found (and any excluded as having no testable logic), which test framework(s)
  were detected/used, how many types already met the bar, before/after coverage per type touched, any type still
  below 80% after two extension attempts (with its exact remaining uncovered lines), and the full-suite test
  result.
* No license headers, DocC comments, or code-quality fixes — those remain `iru-check-license`, `iru-swift-docc`,
  and `iru-swift-code-quality`'s jobs.

  tests have been written or extended; also delegated through `iru-gate-runner`.

=== Invoked by

None from inside this catalog — it is a top-level entry point invoked by a person who wants coverage brought up
across the whole Swift codebase in one pass, independent of the `/iru-code`/`/iru-issue` pipeline (which handles
per-task test-writing via `iru-swift-code-one-task`).
