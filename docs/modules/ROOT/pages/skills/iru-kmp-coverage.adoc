= KMP Coverage
:description: Generates Kover line/branch coverage for a Kotlin Multiplatform project's JVM and Android targets, with per-module, per-class figures and uncovered lines.
:keywords: iru-kmp-coverage, claude code skill, kotlin multiplatform, kmp, kover, coverage, line coverage, branch coverage, jacoco xml, xccov

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run the Kover coverage a Kotlin Multiplatform (Android + iOS) project has wired and report exact, measured
line/branch coverage for the requested scope -- per class, per module and for the whole project. This is a
report-only skill: it never adds tests or modifies source, test or build files.

== Purpose

`iru-kmp-coverage` checks whether the Kover Gradle plugin is wired (root aggregation via
`dependencies { kover(project(":x")) }`, per-module only, or not at all), runs the matching `koverXmlReport` task,
and parses the JaCoCo-format XML into totals, per-module and per-class line/branch percentages -- each class mapped
back to its module and source set -- plus the uncovered line numbers of classes under the bar. Coverage comes from
the JVM test runs only (Android host tests, `jvmTest`, the app's `testDebugUnitTest`, which Kover triggers itself).
Kotlin/Native has no coverage tool, so `iosMain`/`appleMain`/`nativeMain` code is listed as "not measurable" and
never fails the gate, while `commonMain` code is measured through the JVM targets' runs of `commonTest`. When Kover
is absent it reports "coverage not wired" naming what is missing, never a false 0% or 100%. It is the KMP
equivalent of xref:skills/iru-android-coverage.adoc[] and the Kover path of xref:skills/iru-java-coverage.adoc[].

== Outputs

* A plain-text report in the conversation -- never a written file.
* The engine and setup used (root aggregation or per-module), the report path(s), and the test pattern if `tests:`
  narrowed the run.
* Total, per-module and per in-scope class line/branch percentages taken from the XML counters, each judged against
  `bar`; for classes under the bar, their uncovered line numbers.
* **Not measurable**: every Kotlin/Native source set with code (e.g. `shared:iosMain`), stated as excluded from the
  gate rather than as 0%.
* **Coverage not wired** (naming what is missing) instead of any percentage when no Kover is found.
* The informational `iosApp` Swift figure when `ios-app: yes`, or why it was skipped.
* No tests, source or build files are ever added or modified.
