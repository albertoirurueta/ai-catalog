= TypeScript Generate All Tests
:description: Scans a TypeScript/npm codebase for files with no tests or below 80% line coverage, then writes or extends unit tests until each clears that bar.
:keywords: iru-typescript-generate-all-tests, claude code skill, typescript, npm, vitest, jest, line coverage, generate unit tests, code coverage report

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Bring an entire TypeScript codebase's unit test coverage up to a minimum bar — 80% line coverage — in one pass:
find every source file with no test at all or with measured coverage below the bar, then write or extend tests
for each until it clears it. TypeScript/npm only; it never runs against, or falls back to, any other language.

== Purpose

`iru-typescript-generate-all-tests` answers "bring this whole codebase's test coverage up to a bar" rather than
"write tests for this one file/task," which is what `iru-typescript-code-one-task` and the `iru-code` pipeline
already handle per task. It explores the whole codebase to build an inventory of testable files across any
detected flavor (library, React, Angular, React Native, Ionic, or Hilla frontend), delegates to
`iru-typescript-coverage` for the exact, measured percentage per file, and only writes or extends test code — it
does not add license headers, TSDoc, or run a code-quality pass, and it only touches production source code when
a file is genuinely untestable as written (e.g. no seam to substitute a hard dependency), which it reports
explicitly rather than silently redesigning the module.

== Inputs

None — no arguments are accepted. It always scopes to the whole repository (or, in a workspaces/monorepo setup
with no obvious single target, asks which workspace to scope the run to before continuing).

== Outputs

* New or extended test files for every source file found with no matching test file, or with line coverage
  below 80% — following this project's detected flavor's testing library (Vitest/Jest, `@testing-library/react`,
  `@testing-library/react-native`, Angular `TestBed`, or Hilla Vitest browser mode) and its existing test-file
  convention (sibling `.test`/`.spec`, or a mirrored `test/` tree).
* Occasionally, a minimal testability change to a module under test (e.g. accepting a dependency as a parameter,
  extracting a hook/service) — only when a file is genuinely untestable as written, and always called out
  explicitly rather than folded silently into "tests added."
* A report: total candidate files found (and any excluded as having no testable logic), the detected flavor/test
  runner/package manager/test-file convention, how many already met the bar, before/after coverage per file
  touched, any file still below 80% after two extension attempts (with its exact remaining uncovered lines), and
  the full-suite test result.
* No license headers, TSDoc, or code-quality fixes — those remain `iru-check-license`, `iru-typescript-tsdoc`,
  and `iru-typescript-code-quality`'s jobs.
