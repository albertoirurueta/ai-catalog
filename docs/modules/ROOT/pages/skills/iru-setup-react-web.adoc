= Setup React Web
:description: Scaffolds a React + Vite + TypeScript web app with Vitest, ESLint or Oxlint, Prettier, Stylelint, Playwright e2e, UI-contract screenshot and axe tests, and optional Storybook.
:keywords: iru-setup-react-web, claude code skill, react, vite, typescript, vitest, eslint, playwright, stylelint, storybook, ui-contract, accessibility

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold a React + TypeScript web application with Vite, then layer on this catalog's standard
test/coverage/lint/format/e2e toolchain — Vitest, Testing Library, ESLint or Oxlint, Prettier, Stylelint,
Playwright, an optional Storybook setup, and `sonar-project.properties` when Sonar is enabled. It also makes the
scaffold ready for the catalog's UI contract (see xref:guides/building-user-interfaces.adoc[Building user interfaces]):
a Playwright component-testing project with a component gallery, axe accessibility checks, and a `.ui-quality.yml`.

== Purpose

`iru-setup-react-web` bootstraps a new React web app from `npm create vite@latest <name> -- --template
react-ts`, then wires in the house toolchain this catalog expects every TypeScript project to carry: Vitest
(`jsdom`, v8 coverage with lcov) plus `@testing-library/react` for unit tests, ESLint 10 flat config with
`eslint-plugin-react-hooks` (or the Vite template's own Oxlint, kept by choice), Prettier, Stylelint 17 for
CSS, Playwright for an end-to-end smoke test under `e2e/`, an optional Storybook setup, and — when Sonar is
enabled — `sonar-project.properties`. There is no `publish`/`distribution` question for this skill, since a
web app isn't published to a package registry or an app store. Every step was proven against the actual
current tooling (Vite 8, ESLint 10, Vitest 5, Playwright 1.63, Stylelint 17, Storybook 10) in a throwaway
scaffold, so the gotchas called out along the way are observed behavior, not speculation.

A dedicated UI-contract step (Step 6b, with `reference/ui-screenshots.ts`) adds Playwright's built-in `mount()`
component testing driven by a Vite-served gallery (`playwright/gallery/`), `@axe-core/playwright`, a shared
`e2e/support/ui-screenshots.ts` helper, and a sample screen spec that captures `.ui-screenshots/screen/App/`
across left-to-right/right-to-left x light/dark with an accessibility check in every cell. It also switches the
template's CSS to logical properties (so right-to-left captures mirror) and fixes the template's low-contrast accent
colour, then writes `.ui-quality.yml` at the repository root with the chosen accessibility level.

== Outputs

* A Vite + React + TypeScript app scaffolded at the repository root or a subdirectory, including
  `package.json`, `vite.config.ts`, `tsconfig.json` (project references), `src/`, and `public/`.
* `vitest.config.ts`, `src/test/setup.ts`, and `src/App.test.tsx` for unit testing.
* `eslint.config.js` (or Oxlint left in place, per `keep-oxlint`), `.prettierrc`, `.prettierignore`,
  `.stylelintrc.json`.
* `playwright.config.ts` and `e2e/smoke.spec.ts` for end-to-end testing, with the Chromium browser binary
  installed locally.
* `.ui-quality.yml` at the repository root (`accessibility`, `directions: [ltr, rtl]`, `themes: [light, dark]`).
* The UI-contract test scaffold: `e2e/support/ui-screenshots.ts` (from `reference/ui-screenshots.ts`),
  `playwright/gallery/index.html` + `main.tsx`, `src/App.story.tsx`, `e2e/components/App.spec.ts`, a `components`
  Playwright project, the `@axe-core/playwright` dev dependency, and logical-property CSS fixes; running the specs
  produces the `.ui-screenshots/` captures (kept out of version control).
* `.storybook/` and its scripts, only if `storybook: yes`.
* `sonar-project.properties` at the repository root, only if `sonar` resolved to `cloud` or `self-hosted`.
* `tsconfig.e2e.json` and an updated `tsconfig.json` reference list, so `tsc -b` type-checks `e2e/` too.
* A report that opens by repeating the announced mode (scaffolded from scratch or updated an existing setup),
  lists per owned artifact the action taken (created / updated / replaced / kept as is / removed) and each
  mismatch left by a kept artifact (e.g. a `sonar-project.properties` left after `sonar: none`, a Playwright
  config still listing Firefox/WebKit), every verification command run (typecheck, lint, format, test,
  coverage, build, e2e) and its result, the `visibility` used for Sonar and where it came from, plus explicit warnings to review generated files, wire `SONAR_TOKEN`
  in CI if Sonar was enabled, and provision Playwright browsers in CI.
