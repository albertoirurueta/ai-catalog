= Rust Code Quality
:description: Runs Clippy, rustfmt and cargo-deny on a Rust crate or workspace and reports issue counts by tool and rule id, with an optional baseline diff.
:keywords: iru-rust-code-quality, claude code skill, rust, clippy, rustfmt, cargo-deny, lint, static analysis, code quality report

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run Clippy, rustfmt and, when a `deny.toml` exists, cargo-deny on a Rust crate or Cargo workspace and report every issue grouped by tool and by rule id. It is a read-only reporting skill: it never fixes issues, applies formatting, initializes a cargo-deny config, or edits lint configuration unless asked to as a follow-up.

== Purpose

`iru-rust-code-quality` reads the project's lint policy (`[lints]` or `[workspace.lints]`, `clippy.toml`, `rustfmt.toml`, `deny.toml`) and its CI invocation, then mirrors that invocation. Clippy is counted without `-D warnings`, so one failing crate does not hide the lints of the crates that depend on it, and the report says how many issues would fail a CI that denies warnings. Each tool is verified as installed before a "zero issues" result is trusted; a missing tool is reported as skipped. One embedded stdlib Python parser turns every report into per-tool totals and per-rule-id counts, deduplicating the copies Cargo prints once per target. When a calling skill supplies a baseline, only new issues are reported.

== Outputs

* A plain-text summary in the conversation: an overall total first, then per tool whether it ran or was skipped (and why), the version and config in force, its total, and one line per rule-id bucket with its count.
* A `file:line — message` list when the scope is smaller than the workspace or on request; per-rule lists are capped at 20 entries with "(+N more)".
* Rule-id buckets: `clippy::<lint>`, rustc lint names, `E…` and `compile-error` for Clippy; `rustfmt`, `rustfmt-config` and `rustfmt-error`; `cargo-deny:<check>:<code>`. Doc lints are called out for `iru-rust-rustdoc`, and `unsafe_code` findings and compile errors are listed first.
* A statement of whether a CI that runs Clippy with `-D warnings`, `cargo fmt --check` and `cargo deny check` would pass.
* With a baseline, only issues new since it, matched on tool, rule id and file rather than line numbers.
* Tool failures (Clippy exit 101 from a build error, cargo-deny `tool-error`, a stale `Cargo.lock`) get their own line, never "0 issues". Temporary reports under `target/iru-rust-cq/` are deleted. No source or configuration is modified, and no `cargo clippy --fix`, write-mode `cargo fmt`, `cargo deny init` or `cargo update` is run.
