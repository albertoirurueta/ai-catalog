= Swift Test
:description: Runs a Swift project's tests via swift test --filter for packages or xcodebuild -only-testing for Xcode apps, scoped to a selector.
:keywords: iru-swift-test, claude code skill, swift, swiftpm, xcodebuild, xctest, swift testing, xcresulttool, run unit tests, test selector

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run a Swift project's test suite through whichever runner its layout calls for — SwiftPM's `swift test` for a
package, `xcodebuild test` for an Xcode app/workspace project — scoped to whatever the caller asked for, and
report a compact pass/fail summary. This is a read-only reporting skill: it runs tests and summarizes the
outcome, it does not fix failures or modify source/test code unless asked to as an explicit follow-up.

== Purpose

`iru-swift-test` turns a loosely-specified request ("run FooTests", "just testBar", "everything") into the
correct `swift test --filter`/`--skip` or `xcodebuild -only-testing:`/`-skip-testing:` invocation, detects
package vs. app from the repository layout, parses whichever result format that runner produces (console output
for `swift test`, an `.xcresult` bundle via `xcresulttool` for `xcodebuild test`), and — critically — detects the
"selector matched zero tests" case that both runners otherwise hide behind a passing, exit-0 result. It is the
Swift/Apple-platforms equivalent of `iru-java-test`/`iru-typescript-test`/`iru-android-test`.

== Inputs

[cols="1,1,3,2", options="header"]
|===
|Argument |Required |Description |Default

|`selector`
|No
|A positional argument naming what to run: a bare test/method name, a suite/class name, a `Suite.method` or
`Suite/method` pair, or a target-qualified form. Mapped to `--filter`/`-only-testing:` syntax per the tables below.
|None — omitting it runs the full suite.

|`kind`
|No
|`key: value` override of the package-vs-app auto-detection (Step 1) — `package` or `app`. Used when a repository
has both a `Package.swift` and an `.xcodeproj`/`.xcworkspace` and the caller already knows which to exercise.
|Auto-detected from the repository's files.

|`scheme`
|No
|`key: value` — the Xcode scheme to test (app path only).
|Auto-detected via `xcodebuild -list` (the sole scheme, or the one not containing "Tests"/"UITests" when several exist).

|`destination`
|No
|`key: value` — an `xcodebuild` destination string, e.g. `platform=macOS` or
`platform=iOS Simulator,name=iPhone 17,OS=latest` (app path only).
|Inferred from the project's target platform: the first available iPhone simulator, or `platform=macOS` when the
target platform can't be determined.

|`workspace` / `project`
|No
|`key: value` — path to a `.xcworkspace`/`.xcodeproj` to disambiguate when more than one exists (app path only).
|None — `xcodebuild -list` auto-resolves the sole project/workspace when only one exists.
|===

These `key: value` overrides are only honored when the calling skill/prompt passes them explicitly; otherwise
this skill infers everything itself in Steps 1–3.

**Package selector mapping** (`swift test`):

[cols="3,3,3", options="header"]
|===
|What the user wants |Flag |Example

|Everything
|_(omit `--filter`)_
|`swift test`

|One test/method name
|`--filter '<name>'`
|`swift test --filter 'testFoo'`

|One suite/class
|`--filter '<Suite>'`
|`swift test --filter 'FooTests'`

|One method in one suite
|`--filter '<Suite>[./]<method>'`
|`swift test --filter 'FooTests/testBar'`

|One target/module
|`--filter '<Target>\.'`
|`swift test --filter 'FooPackageTests\.'`

|Several disjoint names
|repeat `--filter '<pattern>'` (OR'd, not AND'd)
|`swift test --filter testPasses --filter 'example\(\)'`

|Excluding a pattern
|`--skip '<regex>'`
|`swift test --skip 'SlowTests'`
|===

**App selector mapping** (`xcodebuild test`):

[cols="3,3,3", options="header"]
|===
|What the user wants |Flag |Example

|Everything
|_(omit `-only-testing:`)_
|`xcodebuild test -scheme Demo -destination 'platform=macOS'`

|One suite/class
|`-only-testing:<TestTarget>/<Suite>`
|`-only-testing:DemoTests/FooTests`

|One method in one suite
|`-only-testing:<TestTarget>/<Suite>/<test>`
|`-only-testing:DemoTests/FooTests/testBar`

|Whole test target/bundle
|`-only-testing:<TestTarget>`
|`-only-testing:DemoTests`

|Several disjoint scopes
|repeat `-only-testing:<...>`
|`-only-testing:DemoTests/FooTests -only-testing:DemoTests/BarTests`

|Excluding a scope
|`-skip-testing:<TestTarget>/<Suite>/<test>`
|`-skip-testing:DemoTests/SlowTests`
|===

== Outputs

* A plain-text summary in the conversation — never a written file.
* Package path: totals parsed from the console's `Executed <N> tests, with <F> failures...`/`Test run with <N>
  tests...` lines (XCTest and Swift Testing both run in one `swift test` invocation).
* App path: totals from `xcresulttool get test-results summary` (`passedTests`/`failedTests`/`totalTestCount`/`result`).
* On failures: each failing test's name plus the first line of its assertion/expectation message — for the app
  path, also the `.xcresult` bundle path for full detail instead of dumping it.
* **"Selector matched no tests"** reported explicitly and distinctly from a clean pass, for the zero-match case
  both runners otherwise hide behind exit code 0.
* No source or test code is ever modified.
