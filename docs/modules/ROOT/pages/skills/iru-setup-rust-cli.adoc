= Setup Rust CLI
:description: Scaffolds an agent-friendly Rust command-line tool: Cargo workspace, clap tree, exit codes, JSON output, optional Ratatui UI, tests, and an xtask for docs.
:keywords: iru-setup-rust-cli, claude code skill, rust, cargo, clap, ratatui, cargo-deny, cargo-llvm-cov, scaffold cli, generate man pages

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold a complete, buildable, agent-friendly Rust command-line tool at the repository root: a Cargo workspace whose
library holds all behavior behind a thin `main.rs`, sample commands that are each tested, an optional Ratatui
terminal UI, quality configuration, and an `xtask` that generates man pages, shell completions and the Antora CLI
reference.

== Purpose

`iru-setup-rust-cli` writes the catalog's Rust CLI scaffold contract, which the Rust coding and gate skills and
xref:skills/iru-setup-cli-github-workflows.adoc[] later detect and call. The root `Cargo.toml` holds the tool package
(version `0.1.0-dev` on gitflow, edition 2024, a computed `rust-version`, an explicit `[[bin]]`, workspace lints with
`missing_docs`, `unsafe_code = "forbid"` and Clippy pedantic, and a release profile with fat LTO), next to
`rust-toolchain.toml`, `rustfmt.toml`, `deny.toml` and `.cargo/config.toml` (the `cargo xtask` alias).

The library implements the shared CLI contract: a clap 4 derive tree with global flags (`--format text|json|jsonl`,
`--json`, `--no-color`, `--no-input`, `-q`, `-v`, `--log-format`, `--config`) and `<BIN>_*` environment variables,
an exit-code enum (0 to 7, 130, 143), a `thiserror` error with a JSON error envelope on stderr, per-stream colour
rules, prompts only on a terminal, flags then environment then TOML config then defaults, and signal handling. The
sample commands are `greet`, `completion`, `schema`, `version` and `--version`; with `ui: tui` a Ratatui `browse`
picker is added. Tests are in-process tests of `run`, assert_cmd and snapbox golden-file end-to-end tests, aiming at
about 98% line coverage measured with cargo-llvm-cov (80% bar).

The skill announces whether it is scaffolding from scratch or updating an existing tool. For every file group it
owns that already exists it warns and asks Update / Keep as is / Replace / Stop (or applies `on-existing`), never
overwrites hand-written source, and treats a foreign Cargo layout as foreign. Crate versions are looked up live on
crates.io with a verified fallback table. It writes no CI workflow, `.gitignore`, README, changelog, `LICENSE` or
Sonar file; those belong to the sibling skills chained by xref:skills/iru-setup-cli-repository.adoc[].

== Outputs

* `Cargo.toml` (workspace with the tool package and the `xtask` member) and a generated, committed `Cargo.lock`.
* `rust-toolchain.toml`, `rustfmt.toml`, `deny.toml` and `.cargo/config.toml`.
* `src/main.rs`, `src/lib.rs`, `src/cli.rs`, `src/exit.rs`, `src/error.rs`, `src/output.rs`, `src/term.rs`,
  `src/config.rs`, `src/signals.rs`, `src/tests.rs` and `src/commands/{mod,greet,completion,schema,version}.rs`.
* With `ui: tui`: `src/commands/browse.rs` and `src/tui/{mod,app,ui,ui_screenshots}.rs`, whose list renders only the
  rows that fit.
* With `ui: tui`, per the catalog's xref:guides/building-user-interfaces.adoc[UI contract]: `.ui-quality.yml` at the
  repository root, and UI tests that capture every picker state in each direction as
  `.ui-screenshots/screen/App/<state>--<direction>--no-color.txt` (a gitignored output; see
  xref:skills/iru-setup-rust-gitignore.adoc[]) with the asserted accessibility checks. These additions were written
  without a Rust toolchain and are flagged unverified in the skill until the first `ui: tui` run.
* `tests/cli.rs`, `tests/golden/greet-ada.json` and a generated `tests/golden/schema.json`.
* `xtask/Cargo.toml` and `xtask/src/main.rs`, plus generated man pages and completions under `target/dist/` and the CLI
  reference page `docs/modules/ROOT/pages/cli-reference.adoc` (or `target/dist/cli-reference.adoc` when the Antora
  module does not exist yet).
* A report of the mode (from scratch, updated or stopped), the resolved identity, `ui`, version, MSRV, license, the
  per-group action (including `.ui-quality.yml` for `ui: tui`) (created, updated, replaced, kept as is), crate versions used (live versus fallback), each
  verification result, anything unverified, ignored `args` keys, suggested Antora pages, and explicit warnings (review
  generated files, commit `Cargo.lock` and golden files, register new commands, run the gitignore skill, add
  `LICENSE`, Sonar and crates.io prerequisites).
