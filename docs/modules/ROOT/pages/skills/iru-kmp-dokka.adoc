= KMP Dokka
:description: Audits and fills KDoc across every Kotlin Multiplatform source set (expect/actual aware), wires module.md, and verifies the Dokka 2 multiplatform build.
:keywords: iru-kmp-dokka, claude code skill, kotlin multiplatform, kmp, kdoc, dokka, expect actual, module.md, documentation audit

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Make sure a set of Kotlin Multiplatform declarations -- and the module(s)/package(s) they live in -- carry
complete, well-formed KDoc across `commonMain`, `androidMain`, `iosMain`/`appleMain`/`nativeMain` (and `jvmMain`
when present) plus the Android app module's sources, filling in whatever is missing and proving the result builds
through the project's own Dokka multiplatform setup.

== Purpose

`iru-kmp-dokka` is the KMP equivalent of `iru-android-dokka`/`iru-kotlin-kdoc`. It adds the KMP-specific rule that
the `expect` declaration carries the KDoc and its `actual`s inherit it (an `actual` gets its own KDoc only for
genuinely platform-specific behavior), while platform-only public API (an `iosMain`-only helper, Compose
`MainViewController()`, an `androidMain`-only extension) is documented where it lives. It discovers the project's own
documentation bar (detekt `comments` rules, Dokka `documentedVisibilities`/`reportUndocumented`, contributor guides,
observed practice) instead of assuming a fixed style, ensures Dokka `module.md` (`# Module` / `# Package`) coverage
wired through `includes.from(...)`, generates missing KDoc grounded in the actual code and current changes, and runs
the Dokka 2 task (`dokkaGeneratePublicationHtml`, else `dokkaGenerate`; Dokka 1 `dokkaHtml` fallback). It only adds
or completes documentation comments (plus `module.md` and its wiring) and never changes behavior or signatures. Swift
code in `iosApp/` is out of scope (see xref:skills/iru-swift-docc.adoc[]).

== Outputs

* New or completed KDoc comments in the in-scope main source sets, with the KDoc placed on the `expect` side of each
  `expect`/`actual` pair unless an `actual` has genuinely platform-specific behavior.
* A created or extended `module.md` (`# Module` / `# Package` sections) per touched module that has Dokka applied,
  plus the `includes.from("module.md")` wiring added to its existing `dokka {}` block -- the only build-file edit
  the skill makes.
* A Dokka run per module (HTML under `<module>/build/dokka/html/index.html` unless relocated) with its warnings
  (unresolved links per source set, `Undocumented:` lines tagged `(common)`/`(android)`/`(ios)` when
  `reportUndocumented` is on).
* A report grouped by source set: declarations already documented, gaps found and filled, `@suppress` exclusions,
  Dokka result and version/mode, the `iosMain` part flagged as unverified on a non-macOS host, arguments dropped, and
  pre-existing out-of-scope warnings.
* Nothing else changes: no behavior, signatures, tests, detekt/ktlint fixes, or Dokka plugin configuration.
