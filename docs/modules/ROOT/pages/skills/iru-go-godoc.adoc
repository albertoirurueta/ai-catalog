= Go Godoc
:description: Audits Go packages for complete go.dev doc comments, fills the gaps from the real code, and verifies with revive, godot, gofmt, go vet and go doc.
:keywords: iru-go-godoc, claude code skill, go, godoc, doc comments, golangci-lint, revive, godot, cobra, audit doc comments

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Make sure a set of Go packages carry complete, well-formed doc comments as defined by go.dev/doc/comment, filling in
whatever is missing, then prove the result through revive's doc rules, `godot` and `go doc`. It only adds or completes
comments (and a `doc.go` file holding a package comment when none exists) — it never changes behavior, signatures,
imports or any non-comment code.

== Purpose

`iru-go-godoc` detects the Go module (and `go.work` workspace) and the installed golangci-lint version, then discovers
the project's real documentation bar: the `.golangci.yml` revive, godot, dupword and misspell settings, whether a
`comments` exclusion preset hides revive's doc findings, and the observed comment style. It audits every package
comment (`Package <name> …`, or `<Bin> …` for `package main`) and every exported function, method, type, constant,
variable, interface method and non-obvious struct field, generating comments grounded in the actual implementation —
returns, matchable sentinel or typed errors, side effects, concurrency safety — and keeping existing `Deprecated:`
paragraphs.

Verification uses a dedicated throwaway golangci-lint v2 config enabling only revive's `exported` and
`package-comments` rules plus `godot`, so a project config that excludes the `comments` preset cannot mask gaps. It
also runs `gofmt -l`, `go build`, `go vet`, and `go doc -all` per package to prove every comment renders and to catch
unresolved `[Name]` doc links. When golangci-lint is missing or only v1, it falls back to a `go doc` plus grep audit.
Test files, `testdata/`, `vendor/` and generated files are never edited.

== Outputs

* Edited `.go` files with added or completed doc comments, plus a new `doc.go` holding only the package comment (and
  the sibling license header) when a multi-file package had none.
* A per-package report: symbols already documented, gaps found and filled (kind and what was added).
* The verification result per check — revive `exported`/`package-comments`, `godot`, `gofmt -l`, `go build`/`go vet`,
  `go doc` rendering and unresolved doc links — and which checks could not run (fallback audit when golangci-lint is
  missing).
* Follow-ups: stutter renames, a project `comments` exclusion preset that hides these findings, and pre-existing
  out-of-scope failures. Raw tool output is never pasted.
