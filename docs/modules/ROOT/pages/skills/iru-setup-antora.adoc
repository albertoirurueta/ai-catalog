= Setup Antora
:description: Creates or updates a working Antora docs site: installs Node.js/Antora, scaffolds antora.yml and starter pages, asks how to treat an existing site.
:keywords: iru-setup-antora, claude code skill, antora, asciidoc, nodejs, documentation site, nav.adoc, static site build

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Bootstrap a minimal, working Antora documentation site for a repository: verify/install the Node.js toolchain,
install Antora plus its extensions, scaffold `antora.yml`/`antora-playbook.yml` and a `ROOT` module with three
starter pages, and confirm the site actually builds. The component name is derived from the project identifier (Maven `artifactId`, npm package `name`, or `pyproject.toml` `[project].name`), a Python `.dev0` pre-release suffix is stripped from the starting version like `-SNAPSHOT`, and for Python projects the optional API-docs entry in the starter pages points at the Sphinx build (`docs/api/`, published under the site's `api/`).

== Purpose

`iru-setup-antora` gets a repository from "no documentation site" (or a partially set-up one) to a building Antora
site with a minimal, useful `ROOT` module — without assuming any particular language or build system. It is
additive by default, and it says up front which of two things the run is doing: creating the site **from scratch**
or **updating an existing one**. When `docs/antora.yml`, the playbook, or the `ROOT` module already exists (this
repository, `ai-catalog`, already does), it warns and asks whether to **Update** (fill gaps only — no page, config
entry, or nav entry already present is overwritten or reordered), **Keep as is** (touch nothing; only the
`.gitignore` check and the build verification still run), **Replace** (rewrite `antora.yml` and the playbook from
its template; existing pages and `nav.adoc` are kept unless the user separately confirms otherwise), or **Stop**.
A scripted caller can pre-answer that question with `on-existing`. It also copies its own bundled `ui-bundle.zip` into
`docs/`, so the generated `antora-playbook.yml` points `ui.bundle.url` at that local file instead of depending
on the upstream GitLab CI artifact URL at build time.

== Outputs

* `docs/antora.yml` and `docs/antora-playbook.yml`, written fresh, corrected in place if some fields were
  already wrong (**Update**), rewritten from the template (**Replace**), or untouched (**Keep as is**).
* `docs/ui-bundle.zip` copied in from this skill's own directory (unless already present), so
  `antora-playbook.yml`'s `ui.bundle.url: ui-bundle.zip` resolves to a local file instead of the upstream
  GitLab CI artifact URL.
* `docs/modules/ROOT/nav.adoc` and a `ROOT` module skeleton at `docs/modules/ROOT/pages/` containing
  `index.adoc` (repository overview), `installation.adoc` (install guide), and `reference.adoc` (links to
  generated reports/dashboards) — skipped for any of the three roles already covered by an existing page under a
  different name.
* Antora, `@antora/lunr-extension`, `@sntke/antora-mermaid-extension`, and `@djencks/asciidoctor-mathjax`
  installed under `docs/` (as dev/regular dependencies in `docs/package.json`).
* A `docs/build/` entry added to the root `.gitignore` if missing.
* A built static site at `docs/build/site` (from `npx antora antora-playbook.yml`), or a fixed build error if one
  occurred — this skill does not report success on a broken build.
* A report that starts by restating the mode ("created from scratch" or "updated an existing site"), the option
  applied (updated / kept as is / replaced, and whether it came from the user or from `on-existing`, or that the
  user chose Stop), and, under **Keep as is**, every gap left unfilled. It then groups what already existed versus what this run created or corrected, plus a reminder to review
  the generated starter pages.
