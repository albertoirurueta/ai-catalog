= Setup Swift Gitignore
:description: Creates or refreshes a Swift/Xcode project's root .gitignore for SwiftPM build output, Xcode artifacts, Package.resolved, Fastlane, and signing files.
:keywords: iru-setup-swift-gitignore, claude code skill, swiftpm, xcode, xcodegen, tuist, fastlane, docc, gitignore, bootstrap

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root `.gitignore` for a Swift package or Apple app project, composing a universal
SwiftPM/Xcode base plus conditionally-detected sections for generator-managed Xcode projects, `Package.resolved`,
Fastlane, signing material, and Antora/DocC documentation output — never overwriting an existing file without
showing the user a diff and getting explicit approval first.

== Purpose

`iru-setup-swift-gitignore` composes a Swift/Xcode-appropriate `.gitignore`: an unconditional base
(`.build/`, `DerivedData/`, `*.xcresult`, `xcuserdata/`, `*.xcuserstate`, the narrowly-scoped `.swiftpm/xcode/`,
`.DS_Store`) plus sections detected from the actual project — an XcodeGen/Tuist-generated `.xcodeproj`/
`.xcworkspace` (only when `project.yml`/`Project.swift` is present; otherwise the project file is hand-maintained
and must stay tracked), a `Package.resolved` commit-vs-ignore decision (resolved via `args` or asked through
`AskUserQuestion`, informed by `flavor`), Fastlane output paths, signing material, and Antora/DocC build output.
It mirrors the diff-and-approve contract shared with the sibling
xref:skills/iru-setup-java-gitignore.adoc[] / xref:skills/iru-setup-typescript-gitignore.adoc[] /
xref:skills/iru-setup-android-gitignore.adoc[] skills, adapted for the Swift/Xcode ecosystem, and fits into the
catalog's Swift/Apple bootstrap pipeline as the leaf step that runs once scaffolding and docs are in place.

== Outputs

* A `.gitignore` file at the repository root — newly created, or updated after explicit user approval.
* If `.gitignore` didn't previously exist: it is written directly, no approval step needed.
* If `.gitignore` already existed: a diff of the proposed content is shown first (via `git diff --no-index`), and
  the file is only overwritten if the user explicitly accepts.
* A closing report naming which conditional sections (generator-managed Xcode project, `Package.resolved`,
  Fastlane, signing material, Antora build output, DocC output) were included versus skipped and why, the
  `Package.resolved` commit-vs-ignore decision and its reasoning, and warnings that detection is heuristic and
  that an already-tracked path this skill now proposes to ignore needs a manual `git rm -r --cached`.
