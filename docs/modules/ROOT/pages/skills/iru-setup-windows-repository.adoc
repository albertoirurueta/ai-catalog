= Setup Windows Repository
:description: Bootstraps or updates a Windows desktop app repository on .NET 10 (WPF, WinUI 3 or Windows Forms): solution, Antora docs, gitignore, CI, changelog, README.
:keywords: iru-setup-windows-repository, claude code skill, windows desktop, wpf, winui, winforms, dotnet, msix, github actions, antora, readme

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for a Windows desktop app repository on .NET 10. It resolves the UI stack, architecture,
branching model and mode once, collects the app's identity and the shared pipeline parameters once, prints a
setup-mode statement (from scratch, or an inventory of the prior setup it found), then orchestrates six other skills
in a fixed order so nothing is asked twice.

== Purpose

`iru-setup-windows-repository` is the Windows stack orchestrator invoked by `iru-setup-repository` (project type
`windows-app`) or run standalone. Rather than duplicating solution scaffolding, documentation setup, `.gitignore`
generation, CI/CD authoring, changelog bootstrapping or README generation, it passes each downstream skill only the
`args` keys that skill's own Step 0 accepts. It always invokes the scaffold skill, even in `mode: existing`: every
component sub-skill announces whether it is creating or updating, warns about the prior setup it owns, and asks Update /
Keep as is / Replace per file (or applies `on-existing` when it arrived via `args`).

Scope is desktop apps built with C# on .NET: a plain .NET class library or ASP.NET Core service, .NET MAUI, Avalonia,
Uno Platform and Electron are not scaffolded. `ui` is `wpf`, `winui` or `winforms`; `architecture` is `mvvm` for WPF
and WinUI (MVC is not offered, with an explanation) and `mvc` or `mvvm` for Windows Forms. Pipeline questions are
cost-aware: `visibility` drives recommendations about Actions minutes (the roughly 1.7x Windows multiplier),
SonarCloud pricing and GitHub Pages availability, and `ci: no` skips the workflows step entirely (security block
included). Release questions cover `distribution` (`none`, `internal` or `store`), `signing`
(`artifact-signing`, `certificate` or `none`) and `winget`.

== Outputs

* The .NET 10 solution scaffold -- Core project, WPF/WinUI/WinForms app project, tests, `.ui-quality.yml`, quality config, DocFX and
  optional MSIX packaging (via `iru-setup-windows-app`), created or updated per file group according to the user's
  answers.
* A scaffolded Antora documentation site under `docs/` (via `iru-setup-antora`).
* A root `.gitignore` (via `iru-setup-windows-gitignore`).
* CI/CD workflows -- `build.yml`, `release.yml`, `sync.yml` + `sync_versions.py` (gitflow), `security.yml` and
  `.github/dependabot.yml` (via `iru-setup-windows-github-workflows`); none when `ci: no`.
* A root `CHANGELOG.md` (via `iru-setup-changelog`) and a root `README.md` (via `iru-setup-readme`).
* A final report: setup mode, resolved `ui`/`architecture`/`branching`/`mode`, identity, license and pipeline
  parameters, a per-component table with the action taken (created / updated / replaced / kept as is / skipped
  (`ci: no`)), the consolidated required-secrets table (omitted when no workflows were generated), decisions made on
  the user's behalf (including the `accessibility` level and that UI tests capture `.ui-screenshots/`, uploaded by the CI UI job when `ci-tests: full`), and an explicit warning block (Windows-only verification, MSIX publisher matching the signing
  subject, accounts and secrets that must exist).

== Dependencies

=== Invokes

Each of the following is invoked via the xref:agents/iru-isolated-skill-executor.adoc[`iru-isolated-skill-executor`]
agent rather than a direct `Skill` call, so only a short completion summary flows back and the scaffold's long
template listings stay out of this orchestrator's context. Every sub-agent is launched with
`run_in_background: false` since each step depends on the previous one's files being on disk:

* xref:skills/iru-setup-windows-app.adoc[] -- Step 4: writes or updates the solution, Core, app and test projects,
  `.ui-quality.yml`, quality config, DocFX and packaging, passing Steps 1-3's answers as `args`. Always invoked, even in `mode: existing`.
  The first restore downloads every NuGet package (and the Windows App SDK for WinUI).
* xref:skills/iru-setup-antora.adoc[] -- Step 5: scaffolds or updates the Antora site, with no `args` (only
  `on-existing` when supplied).
* xref:skills/iru-setup-windows-gitignore.adoc[] -- Step 6: writes or updates the root `.gitignore`, with no `args`
  (only `on-existing` when supplied).
* xref:skills/iru-setup-windows-github-workflows.adoc[] -- Step 7, skipped entirely when `ci: no`: writes the CI/CD,
  release and security workflows, passing `branching`, branches, `ci-tests`, `pages`, `distribution`, `signing`, `winget`,
  Sonar keys and related args.
* xref:skills/iru-setup-changelog.adoc[] -- Step 8: bootstraps or updates `CHANGELOG.md` from the repository's tag and
  release history.
* xref:skills/iru-setup-readme.adoc[] -- Step 9, last: bootstraps or updates `README.md`, passing only `sonar`, `ci`,
  `pages` (and `on-existing` when supplied).
