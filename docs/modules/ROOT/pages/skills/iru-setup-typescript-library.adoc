= Setup TypeScript Library
:description: Creates or updates an npm/TypeScript library toolchain (package.json, vitest, eslint, typedoc, src/test skeleton), asking Update, Keep or Replace per file.
:keywords: iru-setup-typescript-library, claude code skill, npm, typescript, vitest, eslint, typedoc, changesets, sonarcloud, scaffold

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate the standard npm/TypeScript library toolchain at the repository root — `package.json`, `tsconfig.json`,
`vitest.config.ts`, `eslint.config.js`, `.prettierrc`/`.prettierignore`, `typedoc.json`, and, when opted in,
`sonar-project.properties` and `.changeset/config.json` — plus a minimal `src/index.ts` + `test/index.test.ts`
skeleton, from explicit house templates embedded in the skill itself. It announces whether it is creating the
toolchain from scratch or updating an existing one, and asks per pre-existing file.

== Purpose

`iru-setup-typescript-library` bootstraps a new npm/TypeScript library's build/test/lint/docs toolchain from a
house template: ESM-only `package.json` and `tsconfig.json` (`moduleResolution: bundler`), Vitest with v8 coverage
and an 80%-lines threshold, ESLint 10 flat config (`@eslint/js` + `typescript-eslint` recommended +
`eslint-config-prettier`, plus a license-header rule once a license is chosen), Prettier, and Typedoc with
`treatWarningsAsErrors`. Every devDependency version is looked up from the npm registry at run time (Step 4), with
a recorded fallback only for when that lookup fails, and `npm install` is run at the end so the scaffold is
immediately buildable. When any owned file already exists it announces "updating an existing setup", warns, and for
each such file asks **Update** (merge, keeping customizations), **Keep as is**, or **Replace** (regenerate from the
template, losing customizations), explaining each option's consequences; **Stop** is offered in the first batch.

== Outputs

* `package.json`, `tsconfig.json`, `vitest.config.ts`, `eslint.config.js`, `.prettierrc`, `.prettierignore`,
  `typedoc.json` at the repository root — created, merged (Update), kept, or regenerated (Replace) per file.
* `src/index.ts` and `test/index.test.ts` — a minimal placeholder module and its test, verified to build/test/
  lint/typecheck/document clean.
* `sonar-project.properties` — only when `sonar` is `cloud` or `self-hosted`; with `sonar: none`, an existing file is
  removed on Update/Replace and left in place on Keep (reported as a mismatch).
* `.changeset/config.json` — only when `publish: yes`; with `publish: no`, same removal/keep rule.
* `node_modules/` from `npm install` (or `pnpm`/`yarn` if that package manager is already in use in the
  repository), run at the end of Step 7.
* A report (Step 8) of the mode (from scratch vs update), resolved package identity, the per-file action (created / updated / replaced / kept as
  is / removed) with mismatches listed for kept files, the `visibility` used and its source, which
  devDependency versions came from a live lookup versus the recorded fallback, and explicit warnings to review
  every generated file, add a `LICENSE` file if a license was chosen, and set up `SONAR_TOKEN`/npm publishing
  credentials before relying on `sonar`/`publish`.
