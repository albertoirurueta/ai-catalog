= Setup Android Library
:description: Scaffolds a Gradle/Kotlin Android library repository (wrapper, lib module, Compose app sample) from a genericized reference-repository template.
:keywords: iru-setup-android-library, claude code skill, gradle, kotlin, android, jetpack compose, jacoco, dokka, sonarqube, scaffolding

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

`iru-setup-android-library` generates the standard Gradle/Kotlin toolchain for a new Android library at the
repository root — the Gradle wrapper, root project files, a `lib/` library module, and an `app/` Jetpack Compose
sample module that depends on `lib` — from explicit example templates embedded in the skill itself.

== Purpose

This skill bootstraps an Android/Kotlin library's entire Gradle build from a house template genericized from a
real reference repository, https://github.com/albertoirurueta/irurueta-android-glutils. It writes the Gradle
wrapper (pinned to a run-time-resolved Gradle version and checksum), the root `build.gradle.kts` /
`settings.gradle.kts` / `gradle.properties` / `gradle/libs.versions.toml`, the `lib/` module (build script,
ProGuard rules, manifests, Robolectric properties, `.gitignore`, one placeholder source + unit test +
instrumented test), and an `app/` Jetpack Compose sample module that depends on `lib` and is genuinely a working
Compose consumer, not just a declared-but-unused dependency. Every toolchain version (Gradle, AGP, Kotlin, Dokka,
Sonar/publish/Detekt/Spotless/Kover/JUnit-bridge plugins, JUnit, AndroidX Test, Compose BOM, Material3, MockK,
Robolectric) is looked up at run time, falling back to the versions this skill recorded in September 2026 only if
a live lookup fails. It gates several optional toggles (publish, Sonar, built-in Kotlin, JUnit major, coverage
tool, static-analysis stack) that each add or remove specific blocks from the generated files, and it fills gaps
or regenerates safely on a repository that already has some of these files.

== Outputs

* Gradle wrapper: `gradle/wrapper/gradle-wrapper.properties` (pinned Gradle version + `distributionSha256Sum`),
  `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`.
* Root project files: `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml`,
  and (only if missing) `local.properties`.
* `lib/` library module: `build.gradle.kts`, `proguard-rules.pro`, `.gitignore`, `src/main/AndroidManifest.xml`,
  `src/androidTest/AndroidManifest.xml`, `src/test/resources/<namespace-path>/robolectric.properties`, one
  placeholder `Example.kt` source, `ExampleUnitTest.kt`, and `ExampleInstrumentedTest.kt`; `detekt.yml` at the
  repository root when `static-analysis: lint+detekt+ktlint`.
* `app/` Jetpack Compose sample module: `build.gradle.kts`, `.gitignore`, `src/main/AndroidManifest.xml`, a real
  Compose `MainActivity.kt` (with a working `@Preview`), `values/strings.xml`, `values/colors.xml`,
  `values/themes.xml`, `values-night/themes.xml`, and the adaptive launcher-icon drawables/mipmaps.
* A report of every resolved input, which optional blocks were included/omitted and why, which toolchain versions
  came from a live lookup versus the recorded fallback, which files were created/left untouched/replaced, and an
  explicit warning block (review before building/publishing, Sonar token and Maven Central credentials still
  needed, no root `.gitignore` written, unverified toggle combinations).
