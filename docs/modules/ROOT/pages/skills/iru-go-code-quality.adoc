= Go Code Quality
:description: Runs a Go module's wired golangci-lint v2, go vet, gofmt and govulncheck checks and reports issue counts by tool and rule id, with optional baseline diff.
:keywords: iru-go-code-quality, claude code skill, go, golangci-lint, go vet, govulncheck, gofmt, lint, static analysis, baseline diff

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run every static-analysis and style check a Go project actually has wired, golangci-lint v2 (linters and formatters), `go vet` and govulncheck, and report every issue grouped by tool and by rule id. It is a read-only reporting skill: it never fixes issues, applies formatting, adds `//nolint`, tidies modules, or edits tool configuration unless asked to as a follow-up.

== Purpose

`iru-go-code-quality` works on modules and `go.work` workspaces alike, for command-line tools, libraries and services. It reads the project's real invocation from CI, Makefile or Taskfile and pre-commit configuration, verifies which tools are installed and configured, runs each one with machine-readable output, and parses every report with one embedded stdlib Python parser into per-tool totals and per-rule-id counts. Rule ids look like `revive:exported`, `gosec:G204`, `staticcheck:SA1019`, `govet:printf`, `errcheck` or `govulncheck:GO-2021-0113`.

A tool that is not wired is named as skipped, never reported as "0 issues". A v1 golangci-lint config is rejected as a tooling failure with the `golangci-lint migrate` fix, and an unreachable vulnerability database is reported as skipped. When a calling skill supplies a baseline, only new issues are reported.

== Outputs

* A plain-text summary in the conversation: an overall total first, then per tool whether it ran or was skipped (and why), the config and version in force, its total, and one line per rule-id bucket with its count.
* A `file:line — message` list when the scope is smaller than the whole module or on request; per-rule lists are capped at 20 entries with "(+N more)".
* Families called out: `typecheck` first (code does not compile), `gosec:*` and called `govulncheck:*` findings (security) early, `revive:exported`, `revive:package-comments` and `godot` (doc comments, handed to xref:skills/iru-go-godoc.adoc[]), and formatter findings (fixed by running the formatter as a follow-up).
* govulncheck findings split into called, imported-only and required-only; the last two are informational.
* With a baseline, only issues new since it are reported, matched on tool, rule id and file rather than line numbers; a new `govulncheck:*` id is flagged as a new advisory or new dependency.
* Tool failures (golangci-lint exit 3, a v1 config, `go vet` on a package that does not build, govulncheck without network) get their own line with the first error line.
* Temporary reports under `build/iru-go-cq-*` are deleted. No source or configuration is modified, and no `--fix`, write-mode formatter, `//nolint` or `go mod tidy` is applied.
