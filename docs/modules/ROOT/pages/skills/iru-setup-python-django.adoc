Scaffolds a Django 6.1 project with uv and `startproject`, or brings an existing Django project up to date, and layers this catalog's Python toolchain and a small, tested project skeleton on top.

== Purpose

`iru-setup-python-django` runs `uv init --bare`, `uv add` and `django-admin startproject config .`, then post-processes the result:

* A PEP 621 `pyproject.toml` (`version = "0.1.0.dev0"`, `uv_build` backend) with Ruff (including `DJ` rules, Google docstrings), mypy strict with django-stubs, pytest-django, and coverage with an 80% floor and Cobertura XML at `build/coverage/coverage.xml`.
* A split settings package `config/settings/{base,local,test,production}.py` driven by fail-fast environment variables, plus `config/env.py`.
* Apps under `apps/`: `apps.accounts` (custom user created before the first migration), `apps.core` (abstract `TimeStampedModel`, `/healthz` and `/readyz` probes) and a sample `catalog` app (model, `@transaction.atomic` service, admin, API).
* The API as Django REST Framework with drf-spectacular (default), Django Ninja, or none.
* Fast tests on in-memory SQLite and, for PostgreSQL, an `integration` tier on a testcontainers PostgreSQL.
* WhiteNoise, Gunicorn (`gthread` on WSGI, or `uvicorn_worker.UvicornWorker` on ASGI for Ninja), Sphinx API docs under `docs/api/`, a multi-stage non-root `Dockerfile`, `.dockerignore`, `compose.yaml` (`postgres:18`, one-shot `migrate`, `app`), `.env.example`, and `sonar-project.properties` when Sonar is enabled.
* A browser UI tier for the server-rendered pages it ships (the Django admin), per the catalog's UI contract (see xref:guides/building-user-interfaces.adoc[Building user interfaces]): `.ui-quality.yml`, pytest-playwright and axe-playwright-python, `LocaleMiddleware` (so right-to-left renders for real), the shared `tests/ui/ui_screenshots.py` helper and an `AdminLoginScreen` test that captures `.ui-screenshots/` across left-to-right/right-to-left x light/dark with an axe check. It is selected with `-m ui` and kept out of the fast tier and its 80% coverage floor; the template lives in `reference/ui-tests.md`.

The generated code is the first exemplar of the `iru-django-code-one-task` conventions, and every verification command is the one the CI workflows and the `iru-python-*` gate skills run. The skill announces whether it is scaffolding from scratch or updating an existing project and, per owned artifact that already exists, asks **Update** / **Keep as is** / **Replace** (or **Stop**) unless `on-existing` pre-answers. Replace is not offered for `manage.py`, settings, `config/urls.py` or apps.

Other keys (`ci-tests`, `pages`, `publish`, `orm`, and so on) are ignored. A Python project that is not Django (a FastAPI service, a library) stops the skill. An existing project with migrations on the default `auth.User` keeps its user model and skips `apps.accounts`.

== Outputs

* `pyproject.toml`, `uv.lock` and `.python-version` with all tool sections.
* `manage.py`, `config/` (settings package, `env.py`, `urls.py`, `asgi.py`, `wsgi.py`, and `api.py` for Ninja), `gunicorn.conf.py`.
* `apps/core/`, `apps/accounts/` and, for new projects or on request, `apps/catalog/` with its API files and generated first migrations.
* `tests/` (`conftest.py`, `factories.py`, fast tier, and `integration/` with PostgreSQL).
* `.ui-quality.yml` and the UI tier: `tests/ui/ui_screenshots.py`, `tests/ui/conftest.py`, `tests/ui/test_admin_login.py` (captures land in `.ui-screenshots/screen/AdminLoginScreen/<state>--<direction>--<theme>.png`, plus an `a11y-report.jsonl`); the `ui` pytest marker, the Playwright dev dependencies and `LocaleMiddleware` in the settings.
* `docs/api/conf.py` and the API reference pages.
* `Dockerfile`, `.dockerignore`, `compose.yaml`, `.env.example`, and `sonar-project.properties` when Sonar is enabled.
* A report: mode, per-component action (created / updated / replaced / kept as is / removed), resolved choices and server type, versions from `uv.lock`, `.ui-quality.yml` action and accessibility level, each verification command and result (including the `-m ui` tier: captures written, axe violations by rule id; unverified items such as Docker-dependent steps called out), and warnings (review identity and Sonar keys, never commit `.env` or `db.sqlite3`, production environment variables, migrations once per release, integration tests need Docker; the UI tier needs `uv run playwright install chromium` and is unverified without a browser).

No `.gitignore`, workflows, `CHANGELOG.md`, `README.md` or Antora files are written; the orchestrator runs the dedicated skills for those next.
