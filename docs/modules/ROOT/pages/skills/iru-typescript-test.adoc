= TypeScript Test
:description: Runs TypeScript unit tests via Vitest, Jest or ng test, plus opt-in NestJS, Next.js and React Native e2e suites, scoped by selector, and reports results.
:keywords: iru-typescript-test, claude code skill, typescript, vitest, jest, angular, nestjs, nextjs, react native, maestro, detox, playwright, e2e tests

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run a TypeScript/npm project's unit test suite through whichever test runner it actually has configured —
Vitest, Jest, or the Angular CLI's Vitest-backed `ng test` builder — scoping the run to whatever the caller
asked for and reporting a compact pass/fail summary parsed from the runner's own JSON reporter. This is a
read-only reporting skill: it never fixes a failing test or modifies source/test code unless asked to as an
explicit follow-up.

== Purpose

`iru-typescript-test` turns a loosely-specified request ("run everything", "just this file", "tests matching
this name") into the correct invocation for whichever runner a TypeScript project actually has wired, and
returns a concise pass/fail report instead of a raw console dump. It detects the runner and package manager
from the project's own manifests rather than assuming one, and distinguishes a genuinely clean run from a
selector that silently matched nothing — a distinction that looks identical in a broken CI job if conflated.

== Inputs

[cols="1,1,3,2", options="header"]
|===
|Argument |Required |Description |Default

|`selector`
|No
|A file path, a directory, or a `-t "<name pattern>"` filter, combinable as a file/directory plus a name
pattern. Mapped to the matching runner's scoping flags per the table below.
|None — omitting it runs the whole unit suite.

|`e2e` / `unit` keyword
|No
|Leading keyword (NestJS, Next.js and React Native only) that picks the suite. `e2e` runs the end-to-end suite instead of the
unit suite and scopes it with the rest of the selector; `unit` means the same as no keyword.
|`unit`

|`lock: held`
|No
|`key: value` line from a calling skill: the caller already holds the repository-wide `.integration-test.lock`, so a React Native `e2e` run must not acquire or release it. Ignored for every other selector.
|Not set — React Native `e2e` takes the lock itself.

|`configuration: <name>`
|No
|React Native `e2e` with Detox only: the `.detoxrc.js` configuration to run (`ios.sim.debug`, `android.emu.debug`, ...).
|Derived from `.detoxrc.js` (single configuration, else a `*.debug` one for the current platform); asked when still ambiguous.
|===

The runner and its invocation are resolved as follows:

[cols="2,1,3", options="header"]
|===
|Runner |Detected via |Full-suite command

|Vitest
|`vitest` in `dependencies`/`devDependencies` plus a `vitest.config.*` file (or a `test`/`vitest` block in
`vite.config.ts`)
|`vitest run`

|Jest
|`jest`/`jest-expo` in `dependencies`/`devDependencies` plus a `jest.config.*` file or a `"jest"` key in
`package.json`
|`jest`

|Angular CLI (`ng test`, Vitest runner)
|`@angular/build` devDependency with the project's `test` architect target using builder
`@angular/build:unit-test` (its `runner` option defaults to `"vitest"`)
|`ng test --watch=false`
|===

If none of the three is found, the skill stops and reports "no test runner wired" rather than reporting a
misleadingly clean "0 tests". If `ng test`'s target has `options.runner` explicitly set to `"karma"`, the
skill's Vitest-shaped commands don't apply and it reports that instead of guessing at Karma's CLI. The
package manager (npm/pnpm/yarn) is read from `packageManager` in `package.json` or the lockfile present, and
the runner's binary is invoked directly (`npx`/`pnpm exec`/`yarn`) rather than through the project's own
`test` npm script, since that script often omits flags the skill needs to forward predictably.

Selector scoping per runner:

[cols="2,2,2,2", options="header"]
|===
|What the user wants |Vitest |Jest |`ng test` (Vitest runner)

|One file
|`vitest run path/to/file.test.ts`
|`jest path/to/file.test.ts`
|`ng test --watch=false --include=path/to/file.spec.ts`

|A directory
|`vitest run path/to/dir`
|`jest path/to/dir`
|`ng test --watch=false --include="path/to/dir/**"`

|Name pattern
|`vitest run -t "<pattern>"`
|`jest -t "<pattern>"`
|`ng test --watch=false --filter="<pattern>"`

|File/dir + name pattern
|`vitest run path/to/file.test.ts -t "<pattern>"`
|`jest path/to/file.test.ts -t "<pattern>"`
|`ng test --watch=false --include=path/to/file.spec.ts --filter="<pattern>"`
|===

An unmatched file/directory selector is a hard failure (non-zero exit) for all three runners; an unmatched
`-t`/`--filter` name pattern against files that do match is not a failure — every runner reports the matched
tests as skipped and exits `0`.

=== NestJS, Next.js and React Native

`@nestjs/core` in `dependencies` marks a NestJS project, `next` a Next.js project, and `react-native` or `expo` a React
Native project; all still run on Vitest or Jest, detected as above, and the framework only changes which suite counts
as "unit", how failures are explained, and how `e2e` resolves:

* *NestJS* — unit tests are `*.spec.ts` next to the source and e2e tests are `test/*.e2e-spec.ts`, kept apart by
  two configs so the default run never picks up e2e files: ESM/Vitest (`vitest.config.ts` plus
  `vitest.config.e2e.ts`) or CommonJS/Jest (`jest.config.ts` plus `test/jest-e2e.json`). The e2e config path is read
  from the project's own `test:e2e` script; with no such script or config, `e2e` is reported as "NestJS e2e suite
  not wired". Relative `.js` imports in the ESM flavor are correct and never reported.
* *Next.js* — unit/component tests run on Vitest (`vitest.config.mts`) or Jest via `next/jest`; e2e is Playwright
  (`@playwright/test` plus `playwright.config.*`), which builds and starts the app, so it only runs on an explicit
  `e2e` selector and never by default. Cypress-only projects are reported as "Cypress e2e present, not run".
* *React Native* — always Jest (never Vitest), with the toolchain resolved first: `expo` in `dependencies` is `expo`
  (even with prebuild `android/`/`ios/`), otherwise `metro` (bare CLI app). The preset is read from the Jest config:
  `jest-expo` (or a platform variant; `jest-expo/universal` multiplies test counts per platform project and the report
  says so) for expo, `@react-native/jest-preset` or the legacy `react-native` preset for metro. A preset contradicting
  the toolchain still runs but is flagged. Unit tests live in `__tests__/` or beside the source; `.maestro/` and
  `e2e/` flows are never matched by the default run. Failures are reported by cause: an untranspiled ESM/Flow package
  needing `transformIgnorePatterns`, a native module without a Jest mock, or React Native Testing Library 14's
  un-awaited `render`.

React Native `e2e` picks Detox (`.detoxrc.*` plus the `detox` devDependency) or else Maestro (`.maestro/` flows), runs it
through its own JUnit/JSON reporter, and reports "React Native e2e suite not wired" when neither exists. Preconditions
are checked in order (tool installed, a booted simulator/emulator, the repository lock, Metro answering on port 8081,
started and later stopped by the skill when it wasn't running) and any miss is reported as "unverified (reason)", never
as a pass. Unlike NestJS/Next.js, whose callers take `.integration-test.lock`, React Native `e2e` acquires and
releases that lock itself unless `lock: held` is passed.

An `e2e` selector on any other project is reported as unsupported and the skill stops. A failure caused by a missing
database, Docker/Testcontainers daemon, Playwright browsers, or a failed `next build` is reported as an environment
failure ("e2e not run/aborted: cause"), never as failing tests; the skill checks `docker info` first when the project
uses Testcontainers.

== Outputs

* A plain-text pass/fail summary in the conversation — never a written file.
* Total, passed, and failed test counts parsed from each runner's JSON reporter output (`--reporter=json` for
  Vitest, `--json` for Jest, `--reporters=json` for `ng test`), written to a scratch file and deleted after
  parsing.
* On failures: each failing test's `fullName` and the first line of its assertion message — no stack traces,
  no passing-test noise.
* A selector that matched no files is reported plainly as "matched no test files", distinct from a genuinely
  clean 0-failure run; a name pattern that matched no individual tests is reported plainly as "0 of N tests
  matched the filter", distinct from "all passed".
* For NestJS, Next.js and React Native, the report states which suite ran (unit or e2e), so a green unit run is never read as e2e
  coverage. Playwright runs are parsed from its own JSON reporter shape (`stats` and nested `suites[].specs[]`).
* No source or test code is ever modified.
