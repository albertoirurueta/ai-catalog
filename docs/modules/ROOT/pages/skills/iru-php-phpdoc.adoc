= PHP PHPDoc
:description: Audits PHP files for complete PHPDoc, fills the gaps per Laravel, WordPress or PrestaShop conventions, and verifies with PHPStan, phpcs and phpDocumentor.
:keywords: iru-php-phpdoc, claude code skill, php, phpdoc, phpstan, wordpress, laravel, prestashop, docblocks, phpdocumentor

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Make sure a set of PHP files carry complete, well-formed PHPDoc, filling in whatever is missing, then prove the
result is valid through the project's own tooling. It only adds or completes documentation comments — it never
changes behavior, signatures, native types, attributes or non-comment code.

== Purpose

`iru-php-phpdoc` detects the project flavor (Laravel, WordPress plugin or theme, PrestaShop module, or plain
library) and applies that flavor's documentation convention. Libraries and Laravel follow the PHPStan-typed
convention of not repeating native types, using `@template`, array shapes, `list<T>` and `class-string<T>` only
where they add information. WordPress code follows the WordPress inline documentation standards: file headers,
`@since`, full `@param` and `@return` tags, and a hook docblock before every `do_action()` and `apply_filters()`.
PrestaShop modules get docblocks on classes, properties and methods regardless of visibility (the license header
itself is `iru-check-license`'s job). It discovers the project's real bar first (phpcs and Pint/PHP-CS-Fixer rules,
PHPStan level, contributor guides), generates docblocks grounded in the actual code, then verifies with PHPStan (or
Psalm), PHP_CodeSniffer commenting sniffs, Pint/PHP-CS-Fixer `phpdoc_*` rules and phpDocumentor, comparing against
a baseline taken before the edits. Test code is out of scope for requirements and its existing comments are never
stripped.

== Outputs

* Edited `.php` files with added or completed docblocks (and WordPress file headers where required).
* A per-file report: symbols already documented, gaps found and filled (kind and what was added), and whether a
  file header was added.
* The verification result per tool that ran — PHPStan or Psalm (no new errors versus the baseline), phpcs
  commenting sniffs, Pint/PHP-CS-Fixer docblock rules, phpDocumentor — and which tools were unavailable.
* Excluded test arguments, any `@since` version that had to be asked about, and out-of-scope pre-existing failures
  as follow-ups. Raw tool output is never pasted.
