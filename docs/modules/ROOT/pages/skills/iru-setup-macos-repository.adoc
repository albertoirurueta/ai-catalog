= Setup macOS Repository
:description: Bootstraps or updates a native macOS app repository (Swift 6, XcodeGen, SwiftUI or AppKit): Xcode scaffold, Antora docs, gitignore, CI, changelog, README.
:keywords: iru-setup-macos-repository, claude code skill, macos, swiftui, appkit, xcodegen, notarization, dmg, github actions, antora, readme

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for a native macOS desktop app repository. It resolves the UI framework, architecture, branching
model and mode once, collects the app's identity, the macOS-specific inputs and the shared pipeline parameters once,
prints a setup-mode statement (from scratch, or an inventory of the prior setup it found), then orchestrates six other
skills in a fixed order so nothing is asked twice.

== Purpose

`iru-setup-macos-repository` is the macOS stack orchestrator invoked by `iru-setup-repository` (project type
`macos-app`) or run standalone. Rather than duplicating Xcode scaffolding, documentation setup, `.gitignore`
generation, CI/CD authoring, changelog bootstrapping or README generation, it passes each downstream skill only the
`args` keys that skill's own Step 0 accepts. It always invokes the scaffold skill, even in `mode: existing`: every
component sub-skill announces whether it is creating or updating, warns about the prior setup it owns, and asks Update /
Keep as is / Replace per file (or applies `on-existing` when it arrived via `args`).

It only scaffolds macOS-only apps: if the manifest declares targets for more than one Apple platform it stops and points
at `iru-setup-swift-repository`. `ui` is `swiftui` or `appkit`; `architecture` is `mvvm` for SwiftUI and `mvc` or `mvvm`
for AppKit. Pipeline questions are cost-aware: `visibility` drives recommendations about Actions minutes, the roughly
10x macOS multiplier (`macos-ci`), SonarCloud pricing and GitHub Pages availability, and `ci: no` skips the workflows
step entirely (security block included). `distribution` is `none`, `internal` (Developer ID signed, notarized and
stapled DMG on GitHub Releases) or `store` (Mac App Store). The `.gitignore` step reuses
`iru-setup-swift-gitignore` rather than a macOS-specific skill.

== Outputs

* The Xcode project scaffold -- XcodeGen `project.yml`, UI-free `Packages/Core`, the SwiftUI or AppKit `App/` layer,
  unit and UI tests, quality configs (including `.ui-quality.yml`) and packaging helpers (via `iru-setup-macos-app`).
* A scaffolded Antora documentation site under `docs/` (via `iru-setup-antora`).
* A root `.gitignore` (via `iru-setup-swift-gitignore`).
* CI/CD workflows -- `build.yml`, `release.yml`, `sync.yml` + `sync_versions.py` (gitflow), `security.yml` and
  `.github/dependabot.yml` (via `iru-setup-macos-github-workflows`); none when `ci: no`.
* A root `CHANGELOG.md` (via `iru-setup-changelog`) and a root `README.md` (via `iru-setup-readme`).
* A final report: setup mode, resolved `ui`/`architecture`/`branching`/`mode`, identity, license and pipeline
  parameters, a per-component table with the action taken (created / updated / replaced / kept as is / skipped
  (`ci: no`)), the `accessibility` level written to `.ui-quality.yml`, the consolidated required-secrets table, decisions made on the user's behalf and an explicit warning
  block.

== Dependencies

=== Invokes

Each of the following is invoked via the xref:agents/iru-isolated-skill-executor.adoc[`iru-isolated-skill-executor`]
agent rather than a direct `Skill` call, so only a short completion summary flows back. Every sub-agent is launched
with `run_in_background: false` since each step depends on the previous one's files being on disk:

* xref:skills/iru-setup-macos-app.adoc[] -- Step 4: writes or updates the Xcode project, Core package, UI layer, tests
  and packaging helpers, passing Steps 1-3's answers as `args`. Always invoked, even in `mode: existing`.
* xref:skills/iru-setup-antora.adoc[] -- Step 5: scaffolds or updates the Antora site (only `on-existing` when supplied).
* xref:skills/iru-setup-swift-gitignore.adoc[] -- Step 6: writes or updates the root `.gitignore` (only `on-existing`
  when supplied).
* xref:skills/iru-setup-macos-github-workflows.adoc[] -- Step 7, skipped entirely when `ci: no`: writes the CI/CD,
  release and security workflows, passing `branching`, branches, `runner`, `macos-ci`, `ci-tests`, `pages`,
  `distribution`, Sonar keys and related args.
* xref:skills/iru-setup-changelog.adoc[] -- Step 8: bootstraps or updates `CHANGELOG.md`.
* xref:skills/iru-setup-readme.adoc[] -- Step 9, last: bootstraps or updates `README.md`, passing only `sonar`, `ci`,
  `pages` (and `on-existing` when supplied).
