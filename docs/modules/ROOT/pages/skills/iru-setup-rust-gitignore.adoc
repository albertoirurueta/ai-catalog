= Setup Rust Gitignore
:description: Creates or updates the root .gitignore for a Rust repository, ignoring /target/ and coverage files while keeping Cargo.lock committed for binary targets.
:keywords: iru-setup-rust-gitignore, claude code skill, rust, cargo, gitignore, cargo-fuzz, cargo-llvm-cov, repository setup

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root `.gitignore` of a Rust repository — the command-line tool layout produced by
xref:skills/iru-setup-rust-cli.adoc[] or any other Cargo crate or workspace. Cargo writes almost everything under one
directory, so the work lies in not ignoring what must stay tracked. An existing `.gitignore` is never overwritten
without showing a diff and getting approval.

== Purpose

`iru-setup-rust-gitignore` writes a short template: the anchored `/target/` directory (which also holds xtask output
under `target/dist`, rustdoc, cargo-llvm-cov and nextest reports), coverage files written elsewhere (`lcov.info`,
`*.profraw`, `*.profdata`), rustfmt backups, pending snapshot files, env files (keeping `.env.example`), the Antora
build output, editor/OS noise and the repository-wide `.integration-test.lock/`. A cargo-fuzz section is added only when
`fuzz/Cargo.toml` exists.

`Cargo.lock` is committed (no ignore line) for any package with a binary target. For a library-only workspace the skill
asks (or reads `cargo-lock`) whether to commit it (recommended) or ignore it. It never ignores `rust-toolchain.toml`,
`.cargo/config.toml`, `deny.toml`, golden test files or the generated-but-committed `cli-reference.adoc`, and it checks
the draft with `git check-ignore` against those files before proposing it. When `.gitignore` exists it announces an
update, shows the merged draft as a diff, and asks Update / Keep as is / Replace.

|`ask`, `keep`, `update` or `replace` — how to treat an existing `.gitignore` in scripted runs; the warning and diff are still printed.

== Outputs

* A root `.gitignore` — created, updated (merged, keeping hand-added lines), replaced with the template, or left untouched when kept as is.
* A report stating whether the run was from scratch or an update, the action taken (created / updated / replaced / kept as is, and whether it came from the user or `on-existing`), the `Cargo.lock` decision with its reasoning, which conditional sections were included or skipped, the result of the safety check, and any already-tracked file under a newly ignored path with the `git rm -r --cached` it needs.
* Explicit warnings: review the file before committing; writing `.gitignore` never untracks committed files (rotate any committed secret); keep `Cargo.lock` committed for binaries and regenerate the CLI reference with `cargo xtask docs` instead of ignoring it.
