= KMP Generate All Tests
:description: Brings a Kotlin Multiplatform module's JVM-measured test coverage to 80% per class, writing kotlin.test tests in the matching source set until it clears.
:keywords: iru-kmp-generate-all-tests, claude code skill, kotlin multiplatform, kmp, kotlin.test, turbine, kover, commontest, generate unit tests, coverage

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Bring one Kotlin Multiplatform module's unit test coverage up to a minimum bar — 80% line coverage, measured on the
JVM/Android host runs — in one pass: find every class with no test at all or with measured coverage below the bar,
then write or extend tests for each until it clears it. Kotlin Multiplatform/Gradle only; it never runs against, or
falls back to, another stack.

== Purpose

`iru-kmp-generate-all-tests` answers "bring this whole module's test coverage up to a bar" rather than "write tests
for this one class/task", which `iru-kmp-code-one-task` and the `iru-code` pipeline already handle per task. It
picks the module (default `shared`, or `composeApp` in the wizard layout, or `androidApp` when scoped to it), uses
the `Explore` agent to inventory every production class with its source set and the module's existing test
conventions, and delegates to `iru-kmp-coverage` (through `iru-gate-runner`) for the exact, measured percentage per
class.

Each test goes in the source set matching the code under test — `commonTest` for `commonMain` (running on every
target), the Android host-test set for `androidMain`, `iosTest` for `iosMain`, `androidApp/src/test` for the app —
defaulting to `kotlin.test` + `runTest` + Turbine (when present) + hand-written fakes (MockK never in `commonTest`;
Mokkery only if already applied). Kotlin/Native has no coverage tool, so `iosMain`/`appleMain`/`nativeMain` classes
are "not measurable", get behavior tests only when invoked with `ios: yes`, and never count against the bar. It adds
only test code; production code is touched only when a class is genuinely untestable as written, and that is
reported explicitly. It stops immediately if the repository is not a Kotlin Multiplatform Gradle project, or has no
JVM test target to measure.

== Outputs

* New or extended test files in the source set matching each class: `commonTest`, the Android host-test set
  (`androidHostTest` or `androidUnitTest`), `iosTest` (only with `ios: yes`), or `androidApp/src/test`.
* Occasionally, a minimal testability change to a class under test (e.g. extracting a common interface and injecting
  it) — only when a class is genuinely untestable as written, and always called out explicitly.
* A report: module scoped, candidate count and classes excluded as having no testable logic, conventions followed,
  how many were already at or above 80% and how many iOS-only classes were not measurable, before/after line
  coverage per class touched, any class still below 80% after two extension attempts (with uncovered lines and
  likely reason), and the full-suite result per target including any unverified iOS stage.
* No license headers, KDoc, code-quality fixes, on-device Android tests, or `iosApp` XCTest tests unless explicitly
  requested.

== Dependencies

=== Invokes

* xref:skills/iru-kmp-coverage.adoc[] — Step 3, and again in Step 6 to re-measure after generation: delegated
  through the `iru-gate-runner` agent so the Kover report never lands directly in this conversation and the JVM
  suite runs once per batch rather than once per class.
* xref:skills/iru-kmp-test.adoc[] — Step 7, once, to confirm the full suite still passes (Android, and iOS when
  `ios: yes` or a `commonTest` file changed on a macOS host with Xcode); delegated through `iru-gate-runner`, which
  lets the skill take `.integration-test.lock` itself for any iOS stage.

=== Invoked by

None from inside this catalog — it is a top-level entry point invoked directly by a person who wants coverage
brought up across one KMP module in one pass, independent of the `/iru-code`/`/iru-issue` pipeline (which handles
per-task test-writing via `iru-kmp-code-one-task`). `iru-android-generate-all-tests` only points to it in prose when
it detects a Kotlin Multiplatform project, and `iru-kmp-coverage` mentions it as a possible consumer of its report.

=== Related agents
