= Setup Android App
:description: Scaffolds a Gradle Kotlin DSL Android application module (app/) with signing, Compose or Views UI, Sonar, and Firebase or Play distribution wiring.
:keywords: iru-setup-android-app, claude code skill, gradle, kotlin, android, compose, jacoco, sonarqube, scaffold, distribution

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate a complete, buildable Gradle Kotlin-DSL Android application project — wrapper, root build files, and a
single `app/` `com.android.application` module — from explicit example templates genericized line for line from a
real reference repository's Gradle toolchain.

== Purpose

`iru-setup-android-app` bootstraps a standalone Android application's Gradle project: the wrapper, root
`build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, and `gradle/libs.versions.toml`, plus a single
`app/` module wired with `applicationId`/`namespace`, `versionCode`/`versionName`, build-info `buildConfigField`s,
an env-var-driven `signingConfigs { release {…} }` block that never fails configuration when signing secrets are
absent, a Compose-by-default UI (or a classic AppCompat + ViewBinding `views` variant), Robolectric + MockK +
JUnit 4 unit-test tooling, an instrumented-test skeleton, and an optional inline `sonar { properties {…} } }`
block. It never writes a Maven Central publishing block — `iru-setup-android-library` is the companion skill for
a library module. Every Gradle/Kotlin/plugin version is looked up at run time against the real package registries,
falling back to a recorded, CI-verified combination when a lookup fails.

== Outputs

* Gradle wrapper files, root `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, and
  `gradle/libs.versions.toml` at the repository root.
* An `app/` module: `build.gradle.kts`, `proguard-rules.pro`, `AndroidManifest.xml`, theme/color/string/launcher-icon
  resources, `MainActivity.kt` (+ Compose theme wrapper, or a ViewBinding layout for `ui: views`),
  `robolectric.properties`, a placeholder unit test, an instrumented-test skeleton, and `app/.gitignore`.
* Any opt-in Gradle plugin blocks selected (Detekt/Spotless, Kover, JUnit 5, Firebase App Distribution, Gradle
  Play Publisher) applied on top of the base templates.
* A report of resolved inputs, which toolchain versions came from a live lookup versus a recorded fallback, which
  files were created/left alone/replaced, and explicit warnings (license/keystore/`google-services.json`/Sonar
  token/distribution credentials review).

== Dependencies

=== Invokes

None — `iru-setup-android-app` is a leaf skill; it does not call any other skill in this catalog. It is
self-contained and does not read `iru-setup-android-library`'s files at run time even when a repository ends up
with both a `lib/` and an `app/` module.

=== Invoked by

* xref:skills/iru-setup-android-repository.adoc[] — Step 4, via the `iru-isolated-skill-executor` agent, when the
  repository's project type is an Android application.

=== Related agents

* xref:agents/iru-gate-runner.adoc[`iru-gate-runner`] — Step 7 runs `./gradlew --offline help` and
  `./gradlew :app:assembleDebug` through this agent so its (potentially long) build output doesn't fill this
  skill's own context.
