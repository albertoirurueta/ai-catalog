= Setup React Native App
:description: Scaffolds a new Expo-managed React Native app with Jest testing, ESLint/Prettier, EAS build profiles, Maestro smoke tests, and optional SonarCloud setup.
:keywords: iru-setup-react-native-app, claude code skill, expo, react native, typescript, jest, eslint, maestro, eas, sonarcloud

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold a new Expo-managed (React Native New Architecture only, Cordova-free) app using `create-expo-app`'s
`blank-typescript` template, then layer on this catalog's standard test, lint, build-profile, and Sonar tooling
using explicit example templates embedded in the skill and verified together end-to-end.

== Purpose

`iru-setup-react-native-app` bootstraps a managed Expo/React Native app's scaffold plus a `jest-expo` +
`@testing-library/react-native` test setup, an `eslint-config-expo` flat config, Prettier, an `eas.json` with
`development`/`preview`/`production` build profiles, a Maestro smoke-test skeleton, and — when opted in —
`sonar-project.properties`. It produces no committed `ios/`/`android/` folders and no Cordova/Capacitor
artifacts; for a Capacitor-based hybrid app, xref:skills/iru-setup-ionic-app.adoc[] is used instead.

== Outputs

* A scaffolded Expo app at `app-directory` (via `create-expo-app@latest --template blank-typescript`), or only
  the missing tooling files when gap-filling an existing scaffold.
* `package.json` merged with `test`/`coverage`/`lint`/`format`/`typecheck` scripts and this skill's devDependencies.
* `jest.config.js`, a `tsconfig.json` merge (`types: ["jest"]`), `__tests__/App.test.tsx`, `eslint.config.js`
  (generated by `npx expo lint`), `.prettierrc`/`.prettierignore`.
* `eas.json` with `development`/`preview`/`production` build profiles (plus a `submit.production` block when
  `distribution: store`).
* `.maestro/smoke.yaml` smoke-test skeleton.
* `sonar-project.properties` (only when `sonar` is not `none`).
* A report of what was created/left untouched/replaced, unresolved `<placeholder>` values still needing manual
  fill-in (e.g. `app.json`'s bundle identifiers, the Maestro `<app-id>`), and required warnings before building,
  committing, or submitting to a store.
