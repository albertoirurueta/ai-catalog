Swift Coverage

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Run whichever coverage path a Swift package or Xcode app project actually has wired — swift test --enable-code-coverage followed by xcrun llvm-cov for a SwiftPM package, or xcodebuild test -enableCodeCoverage YES followed by xcrun xccov for an Xcode app target — and report the exact, measured line/function coverage percentage for the scope the caller cares about. This is a read-only reporting skill: it measures and reports coverage, it does not add tests or modify source/test code unless asked to as an explicit follow-up.

Purpose

iru-swift-coverage answers "does this file/type meet the coverage bar?" with an exact, tool-derived percentage instead of an eyeballed guess from swift test/xcodebuild test console output. It auto-detects whether the repository is a bare SwiftPM package or an Xcode app project, runs the matching coverage path, and — for scope under the bar — points to the exact uncovered line ranges so a follow-up can target them precisely. It is the Swift/Apple-platform equivalent of iru-java-coverage, iru-typescript-coverage, and iru-android-coverage.

Purpose group

Swift Development Tooling

Invocation

/iru-swift-coverage
/iru-swift-coverage [scope]

Inputs

Argument Required Description Default

scope

No

Comma-separated list of file paths (e.g. Sources/Demo/Calculator.swift) or type simple names (e.g. Calculator, Calculator,Formatter) to report coverage for.

None — omitting it reports the whole package/target.

kind: package|app

No

Override the package-vs-app detection (SwiftPM Package.swift vs. Xcode .xcodeproj/.xcworkspace) that Step 1 would otherwise infer.

Auto-detected.

xcresult: <path>

No

An already-produced .xcresult bundle to parse directly, skipping the xcodebuild test run entirely.

None — runs xcodebuild test itself for the app path.

scheme: / destination: / target:/module:

No

Override what would otherwise be inferred the same way iru-swift-test infers them.

Inferred from xcodebuild -list / available simulators / Package.swift test targets.

bar: <N>

No

A coverage threshold (e.g. bar: 80) used only for Step 5’s pass/fail wording.

None — no pass/fail statement is made without one.

Outputs

  • A plain-text summary in the conversation — never a written file.

  • Per target file/type: exact line-coverage and function-coverage percentages, computed directly from llvm-cov/xccov output — never estimated.

  • Branch coverage is always reported as not available for Swift (never as 0%) — verified locally against Swift 6.4/Xcode 27: llvm-cov report’s Branches column stays `0 0 -, and `xccov’s JSON schema has no branch field at all.

  • If the caller gave a coverage bar: a clear statement of whether each file/type/the whole scope meets it.

  • For scope under the bar: the exact uncovered line ranges (collapsed from llvm-cov export -format=lcov’s `DA: lines or `xccov’s per-line JSON), not just the aggregate percentage.

  • A scope file/type absent from the report is reported as 0% coverage, not as an error.

  • If coverage isn’t wired (no test target in Package.swift, no test scheme in the Xcode project), that is reported explicitly, naming exactly what’s missing, instead of a false 0%/100%.

  • No source or test code is ever modified, and coverage is never re-run to try to raise a number.

Execution flow

Dependencies

Invokes

None — iru-swift-coverage is a leaf skill; it only runs swift test/xcodebuild test and parses the resulting llvm-cov/xccov output, it does not call any other skill in this catalog.

Invoked by

  • Swift Code One Task Group — Step 3.5, once per task group, via the iru-gate-runner agent, to check every changed/new file in the group meets the coverage bar.

  • Swift Generate All Tests — Steps 3 and 6, via the iru-gate-runner agent, to measure baseline coverage before generating tests and again afterward to confirm the bar is met.

Related agents

  • iru-gate-runner — both iru-swift-code-one-task-group and iru-swift-generate-all-tests always invoke this skill from inside a iru-gate-runner sub-agent they spawn, not inline.
