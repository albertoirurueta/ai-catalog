Setup Windows GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold or update the CI/CD pipeline for a Windows desktop app built by iru-setup-windows-app, around one cost rule: everything that can run on Linux runs on ubuntu-latest, and only what needs Windows uses windows-latest, because Windows minutes cost about 1.7x Linux minutes on a private repository.

Purpose

iru-setup-windows-github-workflows is the CI/CD step of the Windows chain run by iru-setup-windows-repository, and it also works standalone. It writes build.yml (a Linux core job with restore, warnings-as-errors build, format check, Core tests and an 80% line-coverage bar; a windows-latest job with the solution build, non-UI tests and, with ci-tests: full, the FlaUI desktop UI tests, whose .ui-screenshots/ captures (and the a11y-report.txt of accessibility: report) are uploaded as a 7-day ui-screenshots workflow artifact (with accessibility: none no accessibility report is collected or uploaded); an optional SonarScanner for .NET job; and an Antora + DocFX docs job deployed to GitHub Pages or uploaded as an artifact), release.yml per distribution (internal: per-architecture self-contained zips, an MSIX signed with Azure Artifact Signing or a .pfx, App Installer files and an optional WinGet pull request; store: an .msixbundle submitted with the Microsoft Store Developer CLI), sync.yml plus .github/scripts/sync_versions.py for gitflow (merge the release back and move <Version> to the next -dev), and the shared security block (security.yml with dependency-review, CodeQL csharp, OSV-Scanner and gitleaks; Dependabot for nuget and github-actions).

The templates assume iru-setup-windows-app’s scaffold contract; on a different layout the skill warns and adapts. It announces whether it is creating or updating, asks Update / Keep as is / Replace / Stop per existing file naming each mismatch (unless `on-existing decides), resolves action versions at run time with a fallback table, and ends with the required-secrets table. Standalone it resolves visibility and asks sonar, ci-tests, pages, distribution, signing and winget with the cost facts for that visibility; there is no ci key since invoking it means CI is wanted.

Purpose group

Windows Desktop Bootstrap

Plugin

Shipped by the iru-dotnet plugin of the ai-catalog marketplace (install with /plugin install iru-dotnet@ai-catalog; see Plugins).

Outputs

  • .github/workflows/build.yml, release.yml (when distribution is not none), sync.yml and .github/scripts/sync_versions.py (gitflow), security.yml and .github/dependabot.yml, plus .github/scripts/make_appinstaller.py for a signed internal MSIX release.

  • In build.yml’s UI step: `UI_SCREENSHOTS_DIR pointing at the workspace’s .ui-screenshots/ and an actions/upload-artifact step (if: always(), retention-days: 7, if-no-files-found: ignore) that publishes the captures as the ui-screenshots artifact, with no extra job or runner (see Building user interfaces).

  • A verification pass: actionlint (or a YAML parse), py_compile of the scripts and, where the scaffold and dotnet exist, a local run of the core job commands and DocFX through iru-gate-runner. Anything needing Windows runners, GitHub, certificates or Partner Center is reported unverified.

  • A report with the action per file, the job and runner layout, the options applied and the required-secrets and repository-settings table (Sonar token, Azure OIDC and Artifact Signing variables, .pfx secrets, WINGET_TOKEN, Partner Center credentials, release environment, Pages and workflow-permission settings).

Execution flow

Dependencies

Invokes

None — iru-setup-windows-github-workflows invokes no other catalog skill; it writes workflow files from its own reference/workflow-templates.md and runs gh, git, actionlint, dotnet and python3 directly. The generated sync.yml follows the x.y.z-dev convention of .NET Bump Version and the layout contract of Setup Windows App, and the generated docs job builds the site created by Setup Antora, but none of these is called.

Invoked by

  • Setup Windows Repository — Step 7 (skipped when ci: no), via the iru-isolated-skill-executor agent, passing branching, branches, ci-tests, open-source, visibility, pages, distribution, signing, winget, the Sonar keys, mode and on-existing so nothing is asked twice.

It can also be run directly by a person to add or refresh the pipeline later.

Related agents

  • iru-gate-runner — runs the local verification of the commands the workflows reference (Step 5).
