Setup Swift Repository

This documentation was generated with the assistance of AI. Please report any inaccuracies.

End-to-end bootstrap for a Swift repository of either flavor — a SwiftPM library or a native Apple app. It collects the project’s identity and pipeline parameters once, resolves which flavor and branching model apply, and orchestrates six other skills in a fixed order so nothing is asked twice.

Purpose

iru-setup-swift-repository is the top-level entry point (standalone, or as the Swift/Apple branch of iru-setup-repository) for starting or catching up a Swift repository, whichever of its two flavors it is: a redistributable SwiftPM library, or a native iOS/iPadOS/macOS/watchOS app generated from an XcodeGen or Tuist manifest. Rather than duplicating the flavor’s own scaffold logic, documentation scaffolding, .gitignore setup, CI/CD workflows, changelog bootstrapping, and README generation, it gathers the shared inputs — project identity (package name or app name/bundle-id prefix, license, developer name/email/organization URL), flavor-specific inputs (platforms, minimum deployment targets, generator, signing), and pipeline parameters (branching model, integration/stable branch, macOS runner, open-source/publish/distribution/sonar) — once, and passes each downstream skill only the args keys its own Step 0 accepts. In mode: existing it skips the scaffold entirely when a scaffold manifest already exists, so every downstream step takes its own update/gap-fill path instead of assuming a brand-new repository.

Dependencies

Invokes

Each of the following is invoked via the iru-isolated-skill-executor agent rather than a direct Skill call — every sub-skill re-derives what it needs straight from the filesystem this orchestrator has just written to, so only a short completion summary needs to come back, keeping each sub-skill’s own exploration/file reads (and the two scaffold skills' very long template listings) out of this orchestrator’s own context. Every sub-agent runs with run_in_background: false since each step depends on the previous one’s files being on disk:

  • Setup Swift Library — Step 5, flavor: library: writes Package.swift and the source folders, passing Steps 2–4’s answers (package-name, platforms, min-deployment-targets, license, developer fields, open-source, publish, sonar + detail keys, formatter if supplied, mode) as args.

  • Setup Apple App — Step 5, flavor: app: writes the generator manifest, Packages/Core, per-platform Targets/, and fastlane/Fastfile, passing the app-specific identity (app-name, bundle-id-prefix), platforms, generator, distribution, signing, license, developer fields, open-source, sonar + detail keys, and mode as args.

  • Setup Antora — Step 6: scaffolds the Antora documentation site, invoked with no args since it derives the component name/title/version directly from the manifest Step 5 just wrote (or an initial 1.0.0 if no tags/releases exist yet). Run before Step 8 so that skill’s own docs-site check finds everything in place.

  • Setup Swift Gitignore — Step 7: writes or updates the root .gitignore, passing flavor (so its Package.resolved recommendation matches the project shape) and package-resolved only if supplied; mode is deliberately not passed since the skill’s own .gitignore-presence check is the more precise signal.

  • Setup Swift GitHub Workflows — Step 8: writes the CI/CD + security workflows, passing flavor, platforms, branching, integration-branch (gitflow only), stable-branch, runner, xcode-version if supplied, generator/signing (app only), release-please if supplied (library only), open-source, publish/distribution, sonar + detail keys, and mode as args.

  • Setup Changelog — Step 9: bootstraps the root CHANGELOG.md, invoked with no args since it works from the repository’s own git tag/GitHub Release history; position relative to Steps 5–8 doesn’t matter functionally.

  • Setup Readme — Step 10, last: bootstraps the root README.md, invoked with no args since it explores the finished state left by every earlier step.

Invoked by

  • Setup Repository — Step 4, via iru-isolated-skill-executor, when the detected or chosen project type is swift-library/apple-app.

Related agents

  • iru-isolated-skill-executor — spawned once per sub-skill (Steps 5–10), so all six sub-skills' own exploration/file-read transcripts don’t accumulate in this orchestrator’s context over the course of a single bootstrap run.
