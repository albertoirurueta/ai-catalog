Setup NestJS App

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffolds a NestJS 12 service with the Nest CLI, or brings an existing NestJS app up to date, and layers this catalog’s toolchain and a small, tested application skeleton on top.

Purpose

iru-setup-nestjs-app generates the app in a temporary directory (the Nest schematics refuse to write next to existing files) and copies it into the repository without overwriting anything. It uses nest new for ESM with Vitest (the default) or the application schematic with --type=cjs for CommonJS with Jest. It then post-processes it:

  • package.json with version 0.1.0-dev.0, private: true, and the shared script names iru-setup-typescript-github-workflows and the iru-typescript-* gate skills detect: lint (Oxlint type-aware), format/format:check (Prettier), typecheck, test, coverage (80% threshold, lcov at coverage/lcov.info), test:e2e, build, start, docs (Compodoc or TypeDoc).

  • A skeleton that is the first exemplar of the iru-nestjs-code-one-task conventions: ConfigModule validated by a Zod schema, a global ValidationPipe as APP_PIPE, a shared configureApp() used by both main.ts and the e2e tests, @nestjs/terminus liveness and readiness endpoints, and a tested sample books feature module (only added to an existing app on request).

  • Optional persistence (orm: TypeORM, Prisma 7, Mongoose 9 or Drizzle) with migrations and Testcontainers-backed e2e tests.

  • A multi-stage non-root Dockerfile with a health check and .env.example (always written), and sonar-project.properties when Sonar is enabled.

Versions are resolved live from npm with verified fallbacks. The skill announces whether it is scaffolding from scratch or updating an existing app and, per owned artifact that already exists, asks Update / Keep as is / Replace (or Stop) unless on-existing pre-answers; application source such as main.ts is recommended as Keep.

Purpose group

TypeScript/Node Bootstrap

Outputs

  • The NestJS project: package.json, nest-cli.json, tsconfig*.json, .oxlintrc.json, .prettierrc/.prettierignore, unit and e2e test configs (Vitest or Jest), and optionally typedoc.json.

  • src/config/, src/app.module.ts, src/app.setup.ts, src/main.ts, src/health/, the sample src/books/ feature, and test/ e2e specs and app factory, each with specs. The scaffold’s Hello World files, the deploy script and @nestjs/mau are removed.

  • With an ORM: src/database/ wiring, an initial migration, ORM scripts and a Testcontainers global setup.

  • Dockerfile, .dockerignore, .env.example, and sonar-project.properties when Sonar is enabled.

  • A report: mode, location, resolved choices, the npm scripts written, versions and their source, each verification command and result (unverified items such as Docker-dependent e2e or MySQL called out), and warnings (review generated files, run migrations as a deployment step, SONAR_TOKEN needed).

No .gitignore, workflows, CHANGELOG.md or README.md are written; the orchestrator runs the dedicated skills for those next.

None. It runs the Nest CLI, the package manager and optionally docker directly, and reads its own reference/ files (app templates, ORM variants, Docker and Sonar).
