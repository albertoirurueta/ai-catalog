Setup Swift Gitignore

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root .gitignore for a Swift package or Apple app project, composing a universal SwiftPM/Xcode base plus conditionally-detected sections for generator-managed Xcode projects, Package.resolved, Fastlane, signing material, and Antora/DocC documentation output — never overwriting an existing file without showing the user a diff and getting explicit approval first.

Purpose

iru-setup-swift-gitignore composes a Swift/Xcode-appropriate .gitignore: an unconditional base (.build/, DerivedData/, .xcresult, xcuserdata/, .xcuserstate, the narrowly-scoped .swiftpm/xcode/, .DS_Store) plus sections detected from the actual project — an XcodeGen/Tuist-generated .xcodeproj/ .xcworkspace (only when project.yml/Project.swift is present; otherwise the project file is hand-maintained and must stay tracked), a Package.resolved commit-vs-ignore decision (resolved via args or asked through AskUserQuestion, informed by flavor), Fastlane output paths, signing material, and Antora/DocC build output. It mirrors the diff-and-approve contract shared with the sibling Setup Java Gitignore / Setup TypeScript Gitignore / Setup Android Gitignore skills, adapted for the Swift/Xcode ecosystem, and fits into the catalog’s Swift/Apple bootstrap pipeline as the leaf step that runs once scaffolding and docs are in place.

Purpose group

Swift/Apple Bootstrap

Invocation

/iru-setup-swift-gitignore

Inputs

Argument Required Description Default

mode

No

new or existing — whether a root .gitignore is being created from scratch or gap-filled/merged into one that already exists.

Detected from whether a root .gitignore already exists.

flavor

No

library or app — informs the Package.resolved commit-vs-ignore recommendation. Passed straight through by an orchestrator (e.g. iru-setup-swift-library/iru-setup-apple-app) instead of re-detecting it.

Inferred from Package.swift’s declared products or the presence of an `.xcodeproj/.xcworkspace/app Info.plist; left unresolved (asked together with package-resolved) if no signal is present yet.

package-resolved

No

commit or ignore — the pre-resolved answer for whether Package.resolved is tracked or ignored, so a caller that already knows the answer skips the AskUserQuestion prompt.

Asked via AskUserQuestion (recommended default: commit for flavor: app, ignore for flavor: library); if flavor is unknown and the user has no preference, defaults to commit.

Outputs

  • A .gitignore file at the repository root — newly created, or updated after explicit user approval.

  • If .gitignore didn’t previously exist: it is written directly, no approval step needed.

  • If .gitignore already existed: a diff of the proposed content is shown first (via git diff --no-index), and the file is only overwritten if the user explicitly accepts.

  • A closing report naming which conditional sections (generator-managed Xcode project, Package.resolved, Fastlane, signing material, Antora build output, DocC output) were included versus skipped and why, the Package.resolved commit-vs-ignore decision and its reasoning, and warnings that detection is heuristic and that an already-tracked path this skill now proposes to ignore needs a manual git rm -r --cached.
