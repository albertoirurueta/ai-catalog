Setup TypeScript Library

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Generate the standard npm/TypeScript library toolchain at the repository root — package.json, tsconfig.json, vitest.config.ts, eslint.config.js, .prettierrc/.prettierignore, typedoc.json, and, when opted in, sonar-project.properties and .changeset/config.json — plus a minimal src/index.ts + test/index.test.ts skeleton, from explicit house templates embedded in the skill itself. It announces whether it is creating the toolchain from scratch or updating an existing one, and asks per pre-existing file.

Purpose

iru-setup-typescript-library bootstraps a new npm/TypeScript library’s build/test/lint/docs toolchain from a house template: ESM-only package.json and tsconfig.json (moduleResolution: bundler), Vitest with v8 coverage and an 80%-lines threshold, ESLint 10 flat config (@eslint/js + typescript-eslint recommended
eslint-config-prettier, plus a license-header rule once a license is chosen), Prettier, and Typedoc with treatWarningsAsErrors. Every devDependency version is looked up from the npm registry at run time (Step 4), with a recorded fallback only for when that lookup fails, and npm install is run at the end so the scaffold is immediately buildable. When any owned file already exists it announces "updating an existing setup", warns, and for each such file asks Update (merge, keeping customizations), Keep as is, or Replace (regenerate from the template, losing customizations), explaining each option’s consequences; Stop is offered in the first batch.

TypeScript/Node Bootstrap
