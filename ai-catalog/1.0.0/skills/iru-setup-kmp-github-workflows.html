Setup KMP GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold or update the GitHub Actions CI/CD and security workflows, plus a Dependabot config, for a Kotlin Multiplatform (Android + iOS) app repository produced by iru-setup-kmp-app.

Purpose

iru-setup-kmp-github-workflows combines the two sibling pipelines this catalog already has — iru-setup-android-github-workflows (Gradle, Android Lint SARIF, signed bundle to Google Play / Firebase, sync.yml) and iru-setup-swift-github-workflows (macOS runner choice, XcodeGen, xcodebuild, App Store Connect API key to TestFlight, Swift CodeQL) — around one cost rule: the JVM/Android half runs on cheap Linux runners on every change, while the iOS half needs macOS, whose minutes cost roughly 10x Linux on a private repository, so when it runs is an explicit choice (ios-ci: all, stable or none).

build.yml has a Linux android job (detekt, ktlint, Android Lint with SARIF upload, JVM/Android host tests, root Kover report and an 80% koverVerify, assembleDebug, optional ./gradlew sonar), a cost-gated macOS ios job (Kotlin/Native iosSimulatorArm64Test, xcodegen generate, SwiftLint, and xcodebuild build or, with ci-tests: full, xcodebuild test of the iosApp scheme on the newest iOS simulator) — each test job also uploads the UI tests' .ui-screenshots/ captures as a 7-day ui-screenshots-android / ui-screenshots-ios artifact (if: always(), no extra job or runner) — and an Antora + Dokka docs job deployed to GitHub Pages (pages: yes) or uploaded as a workflow artifact (pages: no). release.yml depends on distribution (internal: Firebase App Distribution + TestFlight; store: Google Play + TestFlight). sync.yml with .github/scripts/sync_versions.py (gitflow only) merges the release back into the integration branch and bumps VERSION_NAME to the next -SNAPSHOT. security.yml holds the shared security block (dependency-review, CodeQL java-kotlin with a manual JVM build, optional CodeQL swift on macOS, OSV-Scanner, gitleaks), and Dependabot covers gradle and github-actions.

The skill announces whether it is creating the pipeline from scratch or updating an existing one; for every pre-existing workflow, script or Dependabot file it names each concrete mismatch with this run’s choices and asks Update / Keep as is / Replace (Stop on the first question), unless on-existing decides. Standalone it resolves visibility, sonar, ios-ci, ci-tests and pages with cost facts for that visibility; there is no ci key, since invoking the skill means CI is wanted. Templates live in the skill’s reference/workflow-templates.md, and action versions are looked up at run time with a recorded fallback table.
