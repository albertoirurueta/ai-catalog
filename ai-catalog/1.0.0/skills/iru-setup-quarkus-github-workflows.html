Setup Quarkus GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or update the GitHub Actions pipeline for a Quarkus service — Java or Kotlin, Maven or Gradle (Kotlin DSL), single-module or hexagonal multi-module — as scaffolded by iru-setup-quarkus-service.

Purpose

iru-setup-quarkus-github-workflows generates the CI/CD and security files for a Quarkus service, fitting the catalog’s release flow (iru-release cuts a release branch and bumps the version with iru-java-bump-version; merging it runs the build on the stable branch; publishing the GitHub Release runs the image and sync workflows). It reads quarkus-stack.yml when present (otherwise detects the build) and writes:

  • build.yml — build and tests per ci-tests (unit = plain and @QuarkusComponentTest only with Dev Services off and every @QuarkusTest excluded; full = also @QuarkusTest with Dev Services containers and @QuarkusIntegrationTest against the packaged artifact), the JaCoCo 80% gate, Checkstyle/PMD/SpotBugs or detekt/ktlint reports, an optional SonarCloud/SonarQube scan (skipped on fork pull requests), a docs job (Antora plus Maven site/Javadoc or Dokka, deployed to Pages from the stable branch with pages: yes, otherwise uploaded as an artifact), and an optional native build-and-test job.

  • release.yml — only with distribution: registry: builds and pushes the container image (version tag and latest) via Jib or a Dockerfile, to GHCR by default.

  • sync.yml plus .github/scripts/sync_versions.py — after a release from the stable branch, opens a PR merging it back into the integration branch and bumping the next -SNAPSHOT (plus README.md and docs/antora.yml).

  • security.yml (dependency review, Gradle dependency submission, CodeQL with a real compile, OSV-Scanner, gitleaks) and .github/dependabot.yml (Maven or Gradle, GitHub Actions, Docker, npm for the docs toolchain).

It announces whether it is creating the pipeline from scratch or updating one, asks Update / Keep as is / Replace (or Stop) per existing unit, validates with actionlint, and ends with a required-secrets table.

Purpose group

Quarkus Service Bootstrap

Plugin

Shipped by the iru-quarkus plugin of the ai-catalog marketplace (install with /plugin install iru-quarkus@ai-catalog; see Plugins).

Outputs

  • .github/workflows/build.yml, security.yml, and (per choices) release.yml and sync.yml with .github/scripts/sync_versions.py.

  • .github/dependabot.yml, always written.

  • A report: scratch vs update and the action per unit, build tool/language/layout, visibility and its cost note, ci-tests, pages, sonar, distribution, native, security jobs included, open gaps (no Antora setup, missing JaCoCo or Sonar plugin, README wording the sync script won’t match), the required-secrets table, repository settings to check, and a warning to review every workflow before pushing.

The generated files' bytes come from template files under templates/ (and, where a template needs variant-specific notes, reference/) in .claude/skills/iru-setup-quarkus-github-workflows/; the skill reads only the files for the variant it resolved, not the whole set, which keeps its SKILL.md small.
