Setup TypeScript Gitignore

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Create or refresh the root .gitignore for a TypeScript/npm project, mirroring `iru-setup-java-gitignore’s contract for the npm ecosystem — never overwriting an existing file without showing the user exactly what would change and getting explicit approval first.

Purpose

iru-setup-typescript-gitignore composes a TypeScript-appropriate .gitignore: a universal base (node_modules/, build/output directories, test/coverage output, TypeScript incremental-build info, lint caches, env files, OS/editor noise) plus conditionally-detected sections for whichever package manager, frontend framework, and documentation tooling are actually present in the target repository — pnpm/Yarn debug logs, Angular, React/Vite (and Storybook), React Native/Expo, Ionic/Capacitor, Playwright, Turborepo, Istanbul/nyc, Antora docs build output, TypeDoc/Compodoc API docs, and a Spring Boot + Vaadin Hilla frontend embedded in a Maven project. It never invents entries for things that aren’t actually present. If .gitignore already exists, it is treated as sensitive: the skill reads it, merges rather than duplicates, and shows the user a diff before writing anything.

Purpose group

TypeScript/Node Bootstrap

Invocation

/iru-setup-typescript-gitignore

Inputs

Argument Required Description Default

(none)

No

This skill takes no arguments — it derives everything it needs by exploring the target repository directly (package.json’s `packageManager field and lockfile, angular.json, vite.config., .storybook/, app.json with an "expo" key, capacitor.config., playwright.config.*, turbo.json, .nycrc, docs/antora.yml / docs/antora-playbook.yml, typedoc.json, and a pom.xml depending on hilla-spring-boot-starter / com.vaadin:hilla or a src/main/frontend/ directory).

Not applicable.

Outputs

  • A .gitignore file at the repository root — newly created, or updated after explicit user approval.

  • If .gitignore didn’t previously exist: it is written directly, no approval step needed.

  • If .gitignore already existed: a diff of the proposed content is shown first (via git diff --no-index against a draft), and the file is only overwritten if the user explicitly accepts; existing hand-written, project-specific lines are preserved rather than dropped.

  • A closing report naming which conditional sections (package manager, Angular, React/Vite, React Native/Expo, Ionic/Capacitor, Playwright, Turborepo, nyc, Antora, TypeDoc/Compodoc, Hilla) were included versus skipped and why, plus warnings that detection is heuristic and that already-tracked files under a newly-ignored directory need a manual git rm -r --cached.
