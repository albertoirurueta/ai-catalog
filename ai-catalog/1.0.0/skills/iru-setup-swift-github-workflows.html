Setup Swift GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold (or update) the build.yml, release.yml, sync.yml (gitflow only), security.yml, and .github/dependabot.yml GitHub Actions workflows for a Swift repository produced by iru-setup-swift-library (a SwiftPM package) or iru-setup-apple-app (an XcodeGen/Tuist-generated Xcode app).

Purpose

iru-setup-swift-github-workflows wires up the house CI/CD pipeline for the Swift/Apple stack: SwiftLint
swift format lint --strict, a build/test step whose shape depends on flavor (library: swift test --enable-code-coverage --parallel with a .build cache keyed on Package.resolved, plus an xcrun llvm-cov-to-SonarQube-generic-XML coverage conversion and an optional ubuntu-latest Linux matrix leg; app: xcodegen generate/tuist generate plus one xcodebuild test -enableCodeCoverage YES run per selected platform destination, piped through xcbeautify, converted to Sonar’s generic XML via SonarSource’s xccov-to-sonarqube-generic.sh), an optional SonarQube/SonarCloud scan, a DocC + Antora documentation build published to GitHub Pages from the stable branch, a release workflow (library: verifies the release tag is valid semver and the manifest still parses, plus an optional release-please job; app: archives, signs via fastlane match or an App Store Connect API key, exports, uploads to TestFlight, and — for macOS — exports with Developer ID, notarizes and staples), a gitflow-only sync.yml that merges a released branch back into the integration branch and bumps the development version (reusing iru-swift-bump-version’s exact rewrite targets via a vendored `sync_versions.py), and a security.yml/dependabot.yml block (dependency-review, CodeQL, OSV-Scanner, gitleaks). Unlike its Java/TypeScript/Android siblings, no single real Swift repository exists to genericize these templates from — they are assembled instead from this catalog’s own already-verified iru-setup-swift-library/ iru-setup-apple-app/iru-swift-coverage/iru-swift-bump-version commands, plus this skill’s own verification pass. If any relevant workflow file already exists, it asks the user whether to stop or attempt an update using the templates as reference, preserving any step this skill doesn’t own.

Purpose group

Swift/Apple Bootstrap

Invocation

Inputs

Argument Required Description Default

args (key: value lines)

No

Pre-resolved values, one per line, for flavor (library/app), platforms, runner (macos-26/xcode-27), xcode-version, integration-branch, stable-branch, branching (gitflow/main-only), generator (xcodegen/tuist, app only), signing (fastlane-match/api-key/none, app only), release-please (library only), plus this catalog’s shared workflow-args vocabulary (open-source, publish, distribution, sonar + coordinates, mode, and the four security-* opt-outs). When an orchestrating skill (such as iru-setup-swift-repository) supplies these, the corresponding fact-finding step in Step 1’s survey is skipped for that value.

None — if args is absent or doesn’t match this key: value format, every parameter is instead resolved by surveying Package.swift/project.yml/Project.swift/fastlane/Fastfile/sonar-project.properties and the repository, asking the user directly (via AskUserQuestion for bounded choices) for anything that can’t be inferred — flavor defaults to auto-detected from the repository shape, runner defaults to macos-26, branching defaults to gitflow.

Outputs

  • .github/workflows/build.yml, release.yml, and (gitflow only) sync.yml — created fresh, or updated in place if any already existed and the user chose to continue.

  • .github/workflows/security.yml and .github/dependabot.yml — always written (or updated), independent of flavor/branching.

  • .github/scripts/sync_versions.py, always written together with sync.yml — never one without the other, and never for main-only.

  • .github/scripts/lcov_to_sonar_generic.py — only when flavor: library and sonar isn’t none (the app flavor instead fetches SonarSource’s own xccov-to-sonarqube-generic.sh at CI time).

  • A report of which files were created/updated/left untouched, open gaps (missing docs/antora.yml, a Packages/Core with no swift-docc-plugin dependency, a <team-id> the user still needs to supply, version wording that didn’t match sync_versions.py’s regexes), the required-secrets table below, and warnings about what this skill’s own verification pass could not exercise locally (no `brew — SwiftLint, xcbeautify, xcodegen/tuist, and therefore the whole app-flavor pipeline beyond its rendered YAML).
