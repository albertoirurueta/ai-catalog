Setup Android GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold or update the GitHub Actions CI/CD and security workflows, plus a Dependabot config, for an Android/Gradle repository produced by iru-setup-android-library or iru-setup-android-app.

Purpose

iru-setup-android-github-workflows wires up the house CI/CD pipeline for an Android/Gradle repository: build and unit test, an optional instrumented test on a reactivecircus/android-emulator-runner emulator, lint with SARIF upload, unit-test coverage via AGP’s own createDebugUnitTestCoverageReport task (with a vendored- jacococli.jar fallback), an optional SonarQube/SonarCloud scan, a Dokka + Antora documentation build published to GitHub Pages (library flavor), and — depending on flavor — either an optional Maven Central publish or a signed release build uploaded to Google Play or Firebase App Distribution. It also generates a security.yml (dependency-review, CodeQL, OSV-Scanner, gitleaks, plus two opt-in jobs) and .github/dependabot.yml, regardless of branching model. The skill supports two branching shapes — gitflow (develop.yml/main.yml/sync.yml) and main-only (main.yml/publish.yml, no sync.yml) — and two flavors (library/app), ships genericized example templates derived from a real Android library repository’s actual workflows, and resolves every placeholder from a survey of the target repository rather than guessing. If any relevant workflow file already exists, it asks the user whether to stop or attempt an update using the templates as reference, preserving any step/job this skill doesn’t own.

Pre-resolved values, one per line, e.g. flavor: library. Key values: flavor (library/app), branching (gitflow/main-only), integration-branch, stable-branch, java-version, run-instrumented-tests (yes/no), api-level, plus this catalog’s shared workflow-args vocabulary — open-source, publish (library only), distribution (none/internal/store, app only), sonar (cloud/self-hosted/none + sonar-organization/sonar-project-key/sonar-host-url), mode (new/existing), and four security-* opt-outs (security-dependency-review, security-codeql, security-osv, security-gitleaks) plus two security opt-ins (security-owasp-dependency-check, security-mobsfscan, app only) — so an orchestrating skill can supply them without re-prompting.

None — if args is absent or doesn’t match this format, every parameter is instead resolved by surveying the repository (module layout, existing sonar {}/mavenPublishing {} blocks, signing config, vendored JaCoCo CLI, branch names, README/Antora version wording) and asking the user for the rest — flavor is required and detected/asked if ambiguous; branching defaults to gitflow, java-version to 17, api-level to 35.
