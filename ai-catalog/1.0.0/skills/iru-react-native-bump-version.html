React Native Bump Version

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Set a React Native app’s version to an exact literal value across every file that needs to agree with it. A React Native app has two versions: the npm one in package.json (followed by iru-release, git tags, CHANGELOG.md, and README mentions) and the store-facing one the stores and devices see — app.json/app.config.* for an Expo app, the native android/ and ios/ projects for a bare React Native CLI app. This skill keeps both in step and never computes a version itself.

Purpose

iru-react-native-bump-version handles both toolchains this catalog supports. For expo, it updates package.json plus the lockfile, then app.json’s `expo.version or the version literal of a dynamic app.config.ts/.js; the ios.buildNumber/android.versionCode values are left to EAS when eas.json makes EAS own them and incremented in the app config otherwise, and android//ios/ are never edited. A computed dynamic config is reported, never guessed at. For metro, it updates package.json, versionName/versionCode in android/app/build.gradle(.kts), and MARKETING_VERSION/CURRENT_PROJECT_VERSION in every build configuration of project.pbxproj (plus Info.plist literals when the plist doesn’t route through build settings).

Store-facing values only ever receive a release: a x.y.z-dev.N pre-release changes package.json (and lockfile) alone, while a release x.y.z also sets the app/native version and increments each build number by exactly 1. Step 5 of the skill is the authoritative statement of this convention for callers such as iru-release.

Purpose group

The exact target version (e.g. 1.4.0, 1.4.1-dev.0). Checked against the X.Y.Z/X.Y.Z-dev.N convention; a valid semver string outside it is flagged and confirmed, and any value containing - or + is treated as a pre-release that never reaches store-facing files.

Outputs

  • package.json and its lockfile updated via the package manager’s version command with --no-git-tag-version (for every value, release or pre-release).

  • Expo, release only: app.json expo.version (or an app.config.* version literal) updated; ios.buildNumber/ android.versionCode incremented unless EAS owns them (appVersionSource: "remote", or autoIncrement on a local source).

  • Metro, release only: versionName/versionCode in android/app/build.gradle(.kts), MARKETING_VERSION/ CURRENT_PROJECT_VERSION in every build configuration of ios/<App>.xcodeproj/project.pbxproj, and Info.plist literals when present.

  • Optionally, README/Antora version mentions if sync-files was accepted.

  • Read-back checks: npx expo config (Expo); plutil/xcodebuild -showBuildSettings and a Gradle read-back (Metro), each reported as "not run" when its tooling is unavailable.

  • A report of the toolchain, old/new values, build numbers changed or left alone and why, and a warning to review the diff before committing. No commit or tag is created.

Dependencies

Invokes

None — iru-react-native-bump-version is a leaf skill; it runs the package manager’s version command and python3 file rewrites, plus optional read-back checks, without calling any other skill. It follows TypeScript Bump Version's Step 4 (package manager table) and Step 6 (sync) rules by reference only.

Invoked by

  • Release — Step 6, version bump for react-native-app projects (the react-native key is preferred over typescript).

  • TypeScript Bump Version — Step 0.5, which hands React Native apps (react-native or expo in dependencies) here, forwarding its arguments unchanged, and stops.

Related agents

None — this skill runs inline; it is not invoked from inside a custom agent.
