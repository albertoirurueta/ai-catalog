Setup Ionic App

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold a new Ionic (Angular or React) hybrid mobile app at the repository root using the real @ionic/cli start schematic, then layer on this catalog’s house test/lint/e2e/Sonar conventions on top of the stock starter.

Purpose

iru-setup-ionic-app bootstraps a new Ionic 9 + Capacitor 8 app — no Cordova, no Ionic Appflow — using the Ionic CLI’s own scaffold instead of a hand-rolled reimplementation of it, then wires in Vitest with v8 coverage (the Angular flavor’s @angular/build:unit-test runner, or Vite’s own runner for React), the starter’s existing ESLint flat config plus Prettier, a Playwright web-build smoke test, a Maestro on-device flow skeleton, and sonar-project.properties when opted in. Following the catalog’s UI contract (see Building user interfaces), the Playwright setup also gets a screen spec that captures HomePage across left-to-right/right-to-left × light/dark into .ui-screenshots/ with an @axe-core/playwright check at the level of a root .ui-quality.yml, and the stock starter is patched so it passes its own accessibility check. Every command and quirk documented in its SKILL.md was confirmed by actually running the exact sequence against both flavors (@ionic/cli 7.2.1, @ionic/angular/@ionic/react 9.0.4, Capacitor 8.5.2) rather than assumed from the tools' documentation alone.

TypeScript/Node Bootstrap

Outputs

  • A scaffolded Ionic app at the repository root (package.json, capacitor.config.ts, src/, framework config), moved up from a temporary sibling directory when the root wasn’t empty.

  • capacitor.config.ts re-initialized with the real app-id in place of the starter’s io.ionic.starter.

  • Vitest coverage wired into angular.json (Angular) or vite.config.ts (React), plus non-interactive test/coverage package.json scripts.

  • eslint.config.js extended with build/coverage ignores and eslint-config-prettier; .prettierrc.json and format/format:fix scripts added.

  • playwright.config.ts and e2e/smoke.spec.ts (optionally replacing the React starter’s Cypress setup), plus an e2e script.

  • UI contract files: .ui-quality.yml at the repository root (accessibility, directions, themes), e2e/support/ui-screenshots.ts (copied from the skill’s reference/ui-screenshots.ts, with @axe-core/playwright installed), and a HomePage matrix test in e2e/smoke.spec.ts that writes .ui-screenshots/screen/HomePage/default--<ltr|rtl>--<light|dark>.png. The starter’s index.html viewport, link underline, paragraph colour contrast and right-to-left inset-inline are fixed so it passes at enforce. .ui-screenshots/ must be gitignored (Setup TypeScript Gitignore adds it).

  • .maestro/smoke.yaml, an unverified on-device smoke-flow skeleton.

  • sonar-project.properties at the repository root, only when sonar is cloud or self-hosted.

  • android/ and/or ios/ native platform folders, for whichever of add-android/add-ios was Yes.

  • A report that opens by repeating the announced mode (from scratch or updating an existing setup), lists per owned artifact the action taken (created / updated / replaced / kept as is / removed) and each mismatch a kept artifact leaves with this run’s choices, the visibility used for Sonar and where it came from, every resolved value, what was included versus omitted and why, and explicit warnings to review generated files and provision Sonar/store credentials before relying on CI.
