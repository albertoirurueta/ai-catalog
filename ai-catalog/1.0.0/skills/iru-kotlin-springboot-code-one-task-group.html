Kotlin Spring Boot Code One Task Group

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Implement one bucket of Kotlin Spring Boot tasks from a plan’s task group end to end: capture one pre-change quality baseline, run iru-kotlin-springboot-code-one-task once per task (in parallel when the group allows it), then validate the whole bucket once, cheapest check first and containers last.

Purpose

iru-kotlin-springboot-code-one-task-group is the Kotlin counterpart to iru-java-springboot-code-one-task-group. It detects the build once (Maven or Gradle, hexagonal reactor or layered/feature service, Kotlin-only or mixed with Java, JaCoCo or Kover, how integration tests are wired, whether Docker is available), captures one detekt/ktlint baseline (plus Checkstyle/PMD/SpotBugs when touched modules hold Java sources), and implements each task through iru-kotlin-springboot-code-one-task. Parallel buckets run all tasks concurrently, except that port-before-adapter tasks and tasks sharing build-file changes are sequenced.

It then validates the entire bucket in one pass, every check delegated to an iru-gate-runner agent: license headers, KDoc plus a Dokka build (and Javadoc for Java files), structural checks for hexagonal reactors (enforcer banned dependencies, ArchUnit, Gradle project-dependency direction), scoped unit tests, an 80% unit-only coverage gate, the full unit suite, and static analysis diffed against the baseline. Last comes the Testcontainers-backed integration stage (Maven Failsafe verify or the detected Gradle integration task), serialized repository-wide behind an atomic mkdir-based .integration-test.lock (owner file, stale after 60 minutes, bounded wait of about 45 minutes, released on every exit path, single-threaded). Integration tests never satisfy the coverage gate; the aggregate figure is reported for information only. Docker being unavailable means the integration stage is reported unverified, never silently skipped.

Purpose group

Spring Boot Development Tooling

Plugin

Shipped by the iru-springboot plugin of the ai-catalog marketplace (install with /plugin install iru-springboot@ai-catalog; see Plugins).

Invocation

/iru-kotlin-springboot-code-one-task-group <bucket text>

Inputs

Argument Required Description Default

Bucket text

Yes

Every Kotlin Spring Boot task/sub-task in the bucket with its own text, the group’s Parallelizable verdict, and any relevant "Current code state" context.

None — always invoked with a specific bucket’s text, by iru-code-one-task-group.

Outputs

  • Source, test, build and migration files created or modified per task, via iru-kotlin-springboot-code-one-task.

  • License headers, KDoc (and Javadoc for Java files) validated once for the bucket.

  • Unit tests achieving at least 80% line coverage for changed classes, measured from unit tests alone (JaCoCo or Kover).

  • An integration-test result (passed, failed-and-fixed, or unverified with the reason) and, where available, an informational aggregate coverage figure.

  • implementation_plan.md with each task’s checkbox checked and its "group validation pending" note replaced by the final outcome (unit-only coverage reported separately from the aggregate).

  • A bucket summary for the caller: detected shape, per-task results, structural result, static-analysis findings, accepted coverage exceptions, integration result, lock behavior, build-configuration findings and blockers.

Execution flow

Dependencies

Invokes

  • Kotlin Spring Boot Code One Task — Step 2, once per task (concurrently or sequentially), via the iru-isolated-skill-executor agent; each implements its task and unit tests.

Each of the following runs via the iru-gate-runner agent:

  • Kotlin Code Quality — Step 1 baseline and Step 3.7 regression check (detekt and ktlint).

  • Java Code Quality — Steps 1 and 3.7, only when touched modules also hold Java sources.

  • Check License — Step 3.1, license headers for every touched file.

  • Kotlin KDoc — Step 3.2, KDoc plus Dokka build verification.

  • Java Javadoc — Step 3.2, Javadoc for touched Java files.

  • Java Test — Steps 3.4 and 3.6, scoped and full unit suites (Maven or Gradle).

  • Java Coverage — Step 3.5, the unit-only 80% coverage gate (JaCoCo or Kover).

Invoked by

  • Code One Task Group — Step 2, bucket for key kotlin-springboot.

Related agents

  • iru-isolated-skill-executor — spawned per task in Step 2.

  • iru-gate-runner — spawned for the baselines (Step 1) and every validation, integration and aggregate-coverage check (Step 3).
