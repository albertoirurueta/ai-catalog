Setup Android Gitignore

This documentation was generated with the assistance of AI. Please report any inaccuracies.

iru-setup-android-gitignore composes the root .gitignore and one per-module .gitignore for an Android (Gradle/Kotlin) library or app project, using irurueta-android-glutils's own .gitignore, lib/.gitignore and app/.gitignore as the concrete reference templates. It never overwrites an existing .gitignore without first showing the user exactly what would change and getting explicit approval.

Purpose

The skill produces a house-standard Android .gitignore: an unconditional root base (Gradle build output, local.properties, IDE files, keystores, google-services.json, profiling output, the Kotlin 2.x compiler’s root-level .kotlin/ cache, plus the catalog’s own Antora docs/build//docs/node_modules/ additions), a one-line anchored /build .gitignore for each Gradle module, and a conditionally-detected root section for Fastlane output. It deliberately never ignores a vendored jacoco-<ver>/ JaCoCo CLI directory if the repository vendors one (as the reference repository does, for `iru-setup-android-github-workflows’ opt-in coverage-conversion fallback), since CI would depend on that directory staying tracked to convert coverage without a network dependency. It mirrors `iru-setup-java-gitignore’s diff-and-approve contract, adapted to the Android/Gradle ecosystem.

Purpose group

Android Bootstrap

Invocation

/iru-setup-android-gitignore

Inputs

Argument Required Description Default

mode

No

new or existing. Selects whether the skill should expect to write fresh files or gap-fill/merge into files that already exist.

Detected from whether a root .gitignore already exists (present → existing, absent → new).

modules

No

Comma- or space-separated Gradle module directory names that should each get their own /build-only .gitignore (e.g. lib, app).

Derived from every include(":<name>") entry in settings.gradle.kts/settings.gradle; if neither file exists yet, falls back to whichever of lib/app exist as directories, or asks the user via AskUserQuestion.

Outputs

  • A root .gitignore — newly created, or updated after explicit user approval when one already existed.

  • A <module>/.gitignore for each resolved module (typically lib, app) — newly created, or updated after approval; skipped entirely when its content already matches.

  • A closing report stating which root file and each module file was created/updated/left untouched, which conditional Step 4 section (Fastlane) was included versus skipped and why, and confirmation that no ignore pattern would match a vendored jacoco-<ver>/ CLI directory if the repository has one.
