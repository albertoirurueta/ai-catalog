Setup macOS GitHub Workflows

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Scaffold or update the CI/CD pipeline for a macOS desktop app built by iru-setup-macos-app, around one cost rule: what can run on Linux runs on ubuntu-latest, and only what needs Xcode uses the macOS runner, because macOS minutes cost about 10x Linux minutes on a private repository.

Purpose

iru-setup-macos-github-workflows is the CI/CD step of the macOS chain run by iru-setup-macos-repository, and it also works standalone. It writes build.yml (a Linux lint job running SwiftLint and swift-format in a swift container; a cost-gated macOS job, macos-ci: all|stable, with needs: lint, running the Core tests with an 80% line-coverage bar, xcodegen generate, xcodebuild test with ad-hoc signing, optionally the XCUITest UI tests, and DocC — the app-test step passes TEST_RUNNER_UI_SCREENSHOTS_DIR, the next step rebuilds .ui-screenshots/ from the captures attached to the .xcresult (xcrun xcresulttool export attachments), and the same job uploads it as a 7-day ui-screenshots artifact, with no extra job or runner; an optional Linux SonarQube job; and an Antora docs job merged with the DocC archive), release.yml per distribution (internal: Developer ID archive and export, notarized and stapled app and DMG, Gatekeeper check, attached to the GitHub Release; store: archive and upload to App Store Connect), sync.yml plus sync_versions.py for gitflow (next MARKETING_VERSION and CURRENT_PROJECT_VERSION + 1), and the shared security block (security.yml with dependency-review, CodeQL swift, OSV-Scanner and gitleaks; Dependabot for swift and github-actions). Everything uses Xcode’s own tools; there is no Fastlane.

The templates assume iru-setup-macos-app’s scaffold contract; on a different layout the skill warns, asks whether to continue and adapts the commands. It announces whether it is creating or updating, asks Update / Keep as is / Replace / Stop per existing file naming each mismatch (unless `on-existing decides), looks up runner images and action versions at run time, and ends with the required-secrets table. Standalone it resolves visibility and asks macos-ci/ci-tests/pages/sonar with the cost facts for that visibility; there is no ci key.

Swift/Apple Bootstrap

Outputs

  • .github/workflows/build.yml (including the .ui-screenshots/ recovery step and artifact upload), with no accessibility report artifact or step when .ui-quality.yml says accessibility: none; release.yml (when distribution is not none), sync.yml and .github/scripts/sync_versions.py (gitflow), security.yml, .github/dependabot.yml, and .github/scripts/lcov_to_sonar_generic.py when Sonar is configured.

  • A verification pass: actionlint (or a YAML parse), py_compile of the scripts and, on macOS with the scaffold, a local run of the lint and macos job commands through iru-gate-runner. Signing, notarization, App Store upload and runner behavior are reported unverified.

  • A report with the action per file, the job and runner layout (restating the roughly 10x macOS cost), the options applied and the required-secrets table (SONAR_TOKEN, Apple team ID, App Store Connect API key, Developer ID certificate) plus repository-settings notes. It also tells iru-setup-readme the workflow names, the DMG asset name and the docs URL.

Execution flow

Dependencies

Invokes

None — iru-setup-macos-github-workflows invokes no other catalog skill; it writes workflow files from its own reference/workflow-templates.md and runs gh, git, actionlint, xcodegen, xcodebuild and python3 directly. The generated sync.yml follows the version convention of Swift Bump Version and the layout contract of Setup macOS App, but neither is called.

Invoked by

  • Setup macOS Repository — Step 7 (skipped when ci: no), via the iru-isolated-skill-executor agent, passing branching, branches, runner, macos-ci, ci-tests, pages, distribution, the Sonar keys, mode and on-existing so nothing is asked twice.

It can also be run directly by a person to add or refresh the pipeline later.

Related agents

  • iru-gate-runner — runs the local verification of the job commands (Step 5).
